# app-ui 变体迁移清单

基础 ID 由命令 `bun scripts/inventory-hbar-app-ui.ts` 生成；逐变体审计状态按当次已签收的
`review-ledger.json` 维护，重生成基础清单后须重新核对这些状态。列出全部 38 类、300 个稳定
变体 ID；画廊继续使用分类包装。

此清单显式记录已迁移的受控表面，不能把“已有内容契约”理解为所有业务状态与动作已经迁完，也不能把单个组件检查理解为最终产品验收。新的独立生产组件（会话导航、文件工作区、审批、问答和事件日志）另见集成文档，它们不占用或替换这 300 个 ID。

初始清单曾登记 22 个变体接入受控契约；本轮持续更新后的实现与交付状态以各行记录为准，
不再将这个历史计数当作当前总计。正式宿主模型/插件/设备管理、工具与专用面板和桌面业务
接入仍与参考预览的功能/布局结论分开验收。

2026-09-29 用户调整后，本表新增“功能与布局通过”：主要流程可用、自然流布局合理，
不同状态按风险抽查，共享行为允许从实现和已有案例推导，不逐按钮或逐布局组合校验。
这与“受控契约已接入”等迁移状态及下述 strict 审计状态分别记录；不因微小像素残差拖住进度，
也不将预览结果写成真实远端业务完成。参见 [当前交付标准](reactbits-pro-visual-audit.md)。

本表的“受控契约已接入”“已有内容契约，继续迁移”和“待数据化”只描述实现迁移状态。
可选严格视觉/交互审计状态以忽略目录
`artifacts/reactbits-pro-visual-audit/<run-id>/review-ledger.json` 为准；只有同时具备 8 个
静态 source/local 组合、按反馈机制选样的真实交互 before/after、结构硬门禁通过且无 page/console error，
才可把对应行更新为“视觉与交互审计通过”。
