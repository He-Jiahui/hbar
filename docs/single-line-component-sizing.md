# 文本用途、单行尺寸与阅读换行契约

先判断文字承担的用途，再选择换行策略；不能仅因文字位于按钮或工具栏的 DOM 内，就把它当成单行标签。相同表面也会同时包含不同类型的文字。

| 文字用途   | 典型位置                                                                         | 尺寸与换行                                                                                  |
| ---------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 操作与标识 | 按钮、标签、闭合选择器、工具栏状态、页签、单行列表名称                           | 完整文本加 padding 自然占宽，内部不换行、不省略；必要时所属容器横向滚动                     |
| 阅读内容   | 确认弹窗正文、弹窗的完整目标标题、风险说明、错误详情、帮助文字、带说明的选择卡片 | 按可用宽度自然换行，内容决定高度；长路径 / URL 允许安全断词，超出可用高度时正文区域纵向滚动 |
| 结构化原文 | Markdown、编辑器、代码、终端输出、diff                                           | 使用对应渲染器的阅读规则；保留代码缩进和原文复制来源                                        |

例如“自动批准”触发器、取消与确认按钮保持单行；“会话……将持续自动批准……”是需要完整阅读的确认段落，必须在弹窗内换行。带名称与说明的模型选项属于多行选择卡片，闭合后的模型触发器继续保持单行。弹窗的按钮组可换行排列整个按钮，每个按钮的文字仍保持单行。

`white-space` 会沿 DOM 继承，即使原生 popover 已进入顶层仍会受父元素影响。工具栏的单行结构由 flex 与不可压缩的控件负责，不能在整组父容器上设置 `white-space: nowrap`。共享浮层建立正常阅读边界，单行控件自己声明 `nowrap`；禁止使用全局 `span` / `p` / `button` 后代选择器抹平这些语义区别。

文本由共享 `LumenContentText` 组件承担，`context` 是必填的类型化内容位置。组件根据统一注册表选择 HTML 语义、字号层级和阅读规则，产品调用方不使用 `as="p"` / `as="span"` 猜测样式，也不根据字符长度临时切换布局。

```tsx
<LumenContentText context="control.label">{labels.approval}</LumenContentText>
<LumenContentText context="dialog.body">{labels.confirmBody(session.title)}</LumenContentText>
<LumenContentText context="choice.description">{model.description}</LumenContentText>
<LumenContentText context="feedback.detail" role="alert">{labels.error(code)}</LumenContentText>
```

上下文覆盖控件、状态、导航、工作区标题、工具标题 / 摘要、表单标签 / 说明、弹窗标题 / 正文、浮层标题 / 说明、选择卡片标题 / 描述、反馈、消息正文、元数据与代码。`LumenButton` 自动把直接的字符串 / 数字子节点接入 `control.label`，已组件化的说明卡片维持自己的内容上下文。`LumenStatus` 使用 `control.status`。`LumenText` 保留为兼容渲染原语；新增或重构产品文案必须声明内容上下文。图标、滚动视口和结构容器不属于文本正文。

按钮、标签、闭合选择器、状态、标签页和单行条目由完整文字、图标、gap、padding 与边框决定尺寸。禁止固定文字宽度、`text-overflow: ellipsis`、以隐藏溢出裁切文字，或因文本变长而在组件内部换行。工程与会话侧栏按用户新的明确要求采用下述导航裁剪例外，其他表面仍由滚动区域保留可读全文。

文字按钮允许最小点击目标；图标按钮、状态点和缩略图保留语义尺寸 token。最小点击区域不等于把文本框锁成固定宽高。

受限工作台里，容器拥有溢出。输入工具栏采用单行横向滚动，发送 / 停止保持在滚动区外。滚动区本身可聚焦，禁用按钮的文字仍可用方向键查看。标签页与单行数据行采用同样的局部滚动边界，页面本身不横向溢出。允许外层在明确断点重组整个组件，不能把一个标签拆成几行。

Markdown 正文、编辑器、说明段落和包含标题加说明的多行选项维持正常阅读流；它们不应继承单行控件规则。分页、虚拟化与 Host 内容容量是独立契约，不因移除视觉省略而取消。

输入栏实现由 Lumen 的 `LumenPromptComposer`、app-react 的项目上下文与闭合选择器共同承担。[浏览器回归](../e2e/single-line-controls.spec.ts)检查中英文、明暗主题、320 / 390 / 900 / 1024 宽度、加载 / 离线 / 错误、完整生成分支名、长标签和 200% 文字缩放；断言真实文本 Range 边界、单行行高、滚动可用性与主动作可见性。[真实 Host 回归](../e2e/composer-control-density.spec.ts)还保留审批中的原草稿与未发送边界。

Lumen 文字按钮默认不可压缩、单行，垂直 padding 随字号计算。工作台 / 文件标签页按完整标题自然占宽，由标签条滚动；侧栏树只由导航窗格纵向滚动，项目与会话标题按下述例外裁剪末尾，移动端当前会话标题由自己的单行容器滚动。闭合选择器、附件文件标签与搜索入口采用同一规则。带描述的多行选项明确保留正常文字流。[真实导航回归](../e2e/single-line-navigation.spec.ts)检查侧栏标题起点、末尾裁剪、单行高度、全文提示与菜单占位，并继续检查桌面标签页、移动端标题、功能按钮的完整内容及页面边界；受控组件回归还覆盖 0 / 1 / 7 / 32 / 33 条记录与原目标回调。

[旧省略清单](ui-text-overflow-audit-2026-10-06.md)记录此前的实现与辅助标题补全方式。本契约取代其中允许依赖 tooltip 或详情弥补单行文字裁切的规则；历史清单不代表现行验收标准。

折叠工具 / 思考行的标签与摘要按全文自然占宽，右侧结果状态不可压缩，行内阅读区域承担溢出。聚焦行后可用左右方向键滚动，Enter / Space 继续只负责展开。思考的选定首行 / 最新行、常规工具说明和错误首行不再因 160 / 72 字符的显示长度而添加省略号。工具参数抽取仍受 4,000 code point / 8,192 UTF-16 unit 的处理预算约束；超过提取预算时明确标注原文入口，复制来源保持原始输入 / 输出。提取预算不等同于用 CSS 隐藏可见标签。

活动面板中的任务、运行输入、工作流与 Agent 目标遵守[活动文本阅读策略](activity-text-layout.md)：紧凑字号、自然换行、超过三行默认折叠，独立按钮展开全文，面板统一纵向滚动；活动顶栏的会话标题也换行。文件树、排队消息和模型列表的单行字段继续保持完整文字，由列表承担横向滚动。引用路径由可聚焦的单行区域滚动，行号保留独立空间；编辑器内的文件提及保持完整原子标签，正常输入仍可多行编辑。搜索结果明确包含标题、工作区、时间和正文片段，正文允许自然换行，角色 / 时间 / 工作区标签保持单行。排队消息的 Host 预览预算仍有效，发生真实截取时显示“可编辑查看全文”的宿主文案，不附加视觉省略号。[数据与提及回归](../e2e/single-line-controls.spec.ts)覆盖 0 / 1 / 100 条任务、Agent 的 50 条边界、完整路径、模型选择和提及的撤销 / 恢复。

共用页面标题、工具面板标题、设置列表标题、表单 label、复选框和开关的名称也遵守单行契约；辅助说明继续允许多行。菜单中的普通动作、复制 / 展开 / 恢复按钮和设置导航不再通过局部 `white-space: normal` 覆盖共用按钮规则。目录管理中的名称使用局部阅读区域，优先级、移除和确认动作保持各自完整的点击区域。

`packages/app-react/src` 中的正常换行适用于阅读正文、确认与风险说明、错误详情、搜索正文、包含说明的模型 / 权限 / 位置选项、扩展说明、批注正文、设置恢复说明、工作区名称加路径的多行卡片及正文中的文件链接。布局适配层也必须遵守各自的文字用途，不能重新引入高优先级的省略、裁切或整组禁止换行规则。

侧栏项目 / 会话标题由 `SidebarCaption` 管理：根据用户提供的 Codex 侧栏参考，标题从左侧起点显示，外层按可用宽度单行裁剪末尾，只有实际溢出时才淡出末端，不添加省略号。标题不再独立聚焦或横向滚动，方向键继续归树节点的展开和导航所有。完整文字仍由宿主提供并保留在 DOM、可访问名称和悬浮提示中；状态和菜单保持独立占位。`ResizeObserver` 仅维护局部溢出外观，随组件卸载释放，短名称不应用淡出。字体与 padding 的语义尺寸保持不变，标题长度不引发行高变化。此例外不适用于工具标签、聊天输入按钮、标签页和弹窗正文。

[文字用途浏览器回归](../e2e/single-line-controls.spec.ts)同时检查中英文、明暗主题、1100 / 900 / 390 / 320 宽度的确认说明、长连续路径、模型辅助说明和弹窗目标标题。使用实际文本 Range 验证自然换行、文字没有横向裁切或省略；同时验证工具栏高度稳定、取消不执行授权、确认回调仍绑定原会话、关闭按钮可见及 Escape 回调。
