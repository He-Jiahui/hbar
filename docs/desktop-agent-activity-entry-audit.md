视觉上，参考将正文留作阅读主线：标题动作是短且可辨的入口；Activity 是按需侧栏，分组标题、状态标记和轻量行先提供扫描路径，再让详情和动作就近展开。`SessionChatSurface.tsx` 的桌面侧栏通过预留宽度与内容列并置，窄屏在 `ActiveSession.tsx` 另走覆盖呈现。迁移到 hbar 应保留这种信息层次和局部反馈，而不照搬其固定 `352px` 预留或窄桌面最小宽度：当前 hbar 的 320px 入口仍需正常流、可聚焦、可点击且无内容裁切。图标只使用 hbar 语义尺寸等级，文案与列表数据由 Host 契约提供。

## 下一步实施边界

1. **Agent 调用入口**：先决定 hbar 对 `/agent` 的真实语义。若采取显式 `agent.create`，须明确它与参考“父 Run 交给模型/Agent tool”不同；只呈现 Host 已支持的 `explore` profile，不展示静态 debugger 等假选项。捕获原 session、模型、prompt、幂等键，保存/核查未知接受结果；菜单补全不执行，确认提交后才创建，成功进入对应 Agent 详情。
2. **Activity 概览**：新建独立会话工具投影，而不是重命名 Monitoring。仅组合真实 Run、Agent、Goal/Plan/Workflow 事实；状态、计数、空态与错误要能追溯到源记录，行点击回到相应原会话工具或时间线。列表有界，晚响应、换会话、断线、归档、关闭来源时不串目标。
3. **视觉/交互验收**：参考原组件或公开画面与 hbar 生产树分开取证；至少中英 1440/900/320、长标题/目标、0/1/大量行、键盘与 Escape、打开/关闭/切会话/返回、状态变化和 reduced motion。宽屏可利用侧栏，窄屏改为正常流或明确覆盖层；不能只测 `scrollWidth`，还需检查关键动作在视口内。

本轮没有运行 cc-haha 完整 Electron 或商业模型调用；源码只能证明路由和组件结构，不证明新功能已经具有相同美感或成功率。hbar 的 Agent/Activity 改动应分别作为独立子功能实现、验证、提交。另需注意[会话旧矩阵](desktop-conversation-final-entry-audit.md)中“提案 Implement 不退出 durable Plan”是其审查时点事实，已由 `7bb8d46` 更新，当前行为见[Plan 契约](desktop-durable-plan-mode.md)。
