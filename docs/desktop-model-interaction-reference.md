# Composer model interaction: cc-haha → hbar

## Evidence and correction

The first migration (`54cd963`) made the model name actionable, but sent users to a full settings page. This differs from cc-haha's local model picker and adds navigation and a separate save step to a frequent composer action.

Reference evidence reviewed on 2026-09-24:

- `D:/Git/cc-haha/docs/images/app/zh-CN/model-picker.webp`: full application capture, model and separate reasoning entry at composer bottom-right, model menu above the trigger.
- `D:/Git/cc-haha/desktop/src/components/controls/ModelSelector.tsx`: current source, provider grouping, current selection, fixed search/header, scrolling list and responsive bottom sheet.
- `artifacts/reference-ux-v2/01-closed.png` through `09-model-narrow.png`: current original reference components rendered in an isolated fixture, not a recreation. The shell and model catalog are test fixtures; these captures do not prove real provider connectivity. `observations.json` records measured geometry.

The reference menu is a true overlay: desktop model width 360 CSS px, content-limited maximum height 420 CSS px, thinking overlay width 300 CSS px. At 390 CSS px the model menu is a bottom sheet. hbar expresses these widths as rem limits, measures only the overlay anchor, and keeps all menu content in flex flow. No screenshot coordinate layout is used for ordinary controls.

## Behavior contract

- Model and reasoning controls live beside Send, using the shared composer's `modelPicker` slot. Opening them preserves the conversation, draft, attachments and current navigation.
- Models come from Host `model.list`; provider names, IDs, capabilities and current configuration are actual contract data. There are no product demo models. The list renders 60 rows per explicit page, while search covers the contract-bounded 4,096-record catalog. Header and search do not scroll.
- The current model is kept as the first visible row when it matches the search, even if its catalog position is beyond that first 60-row page. It counts toward the same bound, stays unique as the page expands, and an unavailable/stale model is not fabricated into the list. Reopening resets the list scroll to the selected row.
- Selecting a model writes the explicit originating session's configuration with baseline revisions and an idempotency key. Confirmed selection immediately updates the composer and closes the menu; no settings-page save is required.
- Reasoning is a separate discrete slider using only the selected model's supported levels. Movement and keyboard arrows/Home/End preview the level locally in the large value and slider accessibility text, without changing the confirmed trigger or writing to Host. Pointer release applies once; Enter or leaving the slider applies a keyboard preview once. Escape and pointer cancellation discard the uncommitted preview. A pending or unknown request cannot start another write. It can be used without first opening the model menu.
- A preview captures the source session, model, supported levels and confirmed configuration revisions. If those facts change before application, the preview is discarded rather than applying its index to a different model. Only the confirmed Host result changes the composer trigger; rejection returns to that confirmed value, while an unknown result keeps the existing same-key reconciliation path.
- During a pending or unknown model write, sending is blocked. Unknown results expose a local same-key reconciliation action; repeated clicks do not start a second write. Old session/read responses cannot replace another session's state.
- Search with no matches, no configured models, read failures, unavailable configuration, rejected writes and unknown results are distinct states. Provider configuration is an explicit empty-state recovery route, not the default model-selection action.
- In the model menu, Escape/outside click close without selecting. The reasoning slider separately treats an uncommitted Escape/pointer cancellation as a local discard; leaving the slider with a changed keyboard preview applies it once. Model selection restores keyboard focus to the trigger. Opening search focuses the search field; Arrow Down/Up moves through model options.
- Host-provided Chinese and English labels include accessible names, capability text, errors and remaining-item counts. Long names truncate in the compact trigger but wrap in model rows and retain the full title.

## Verification artifacts

`e2e/composer-model-entry.spec.ts` exercises the real temporary Host and Web application with mock providers (no paid model traffic), covering immediate model/thinking persistence, search, 60-row page bound, draft retention, focus, cancellation and 1440/900/390/320 viewports in both locales. It writes `artifacts/reference-ux-v2/hbar-model-*.png` and `hbar-effort-*.png` for manual comparison. The scoped flow-layout guard only exempts the demonstrated popover container, not its descendants.

The long-catalog regression selects a model beyond the first page through search, closes and reopens the picker, then checks that it is the selected first row at desktop and 320px without losing the draft or exceeding 60 initial rows. The narrow screenshots are `artifacts/reference-ux-v2/hbar-model-selected-late-{en-US,zh-CN}-320.png`.

The reasoning interaction regression checks the pre-release local value and `aria-valuetext`, verifies no Host revision changes during keyboard navigation or pointer dragging, confirms exactly one revision after Enter/pointer release, and proves Escape retains the prior confirmed value. Its 320px mid-drag screenshots are `artifacts/reference-ux-v2/hbar-effort-drag-preview-{en-US,zh-CN}-320.png`. The cc-haha isolated original component was also exercised with ArrowRight, an unreleased drag and Escape; those interactions use fake runtime state and do not prove live provider traffic.

The follow-up visual unit preserves that preview/confirmation transaction while adding a locally styled filled track and one decorative stop per Host-provided `thinkingLevels` item. The native `LumenRange` remains the single pointer/keyboard/assistive-technology target; its fill and the stop colors follow the local preview before a single confirmation. The stops sit immediately below the range in flex flow, rather than embedded in cc-haha's custom overlaid slider; this is a deliberate semantic/layout difference, not an exact visual replica. Forced-colors uses system colors for the rail, stops and thumb. Its original 1440px capture still showed dark lines around the composer from concurrently evolving shared UI styles; the later [Composer boundary unit](desktop-composer-boundary.md) removed those lines from the hbar session input.

The actual Host/Web visual runs cover both locales at 320/390/1440 CSS px (`artifacts/reference-ux-v2/hbar-effort-scale-{en-US,zh-CN}-{320,390,1440}.png`), a 390px long-label layout stress fixture and a forced-colors capture. The long label is deliberately injected into the visual test DOM and is **not** a product locale string or Host option. DOM assertions verify the five fixture-provided stops, selected/progress state under keyboard and pointer previews, focus, no horizontal overflow, and the previously established cancellation/unknown paths. These artifacts are ignored local QA files, not production content.

The current cc-haha `desktop/src/components/ui/SearchField.tsx` supplies a border, search icon, visible keyboard focus and a separate clear button when entered text exists; `desktop/src/components/controls/ModelSelector.tsx` uses it in the model overlay. Its published `model-picker.webp` shows the overlay shape and provider/model hierarchy, but predates that search detail. Hbar now keeps its Host-bounded searchable catalog while using the same semantic search affordances: an inline icon, light framed field, and localized clear button that returns focus to the query. The former shared field's two decorative boundary strokes no longer appear in this overlay. The refreshed real-Host E2E checks en/zh query/clear/focus, 60-row restoration, 1440/900/390/320 placement and no horizontal overflow; `hbar-model-open-{locale}.png`, `hbar-model-search-active-{locale}.png` and `hbar-model-{locale}-320.png` are the ignored visual captures. This is a focused visual and control correction, not a new catalog or model-write contract.

This document records the model subfeature only. Goal/Plan, navigation, message actions, project management and remaining reference differences are tracked separately in the broader [migration record](desktop-experience-migration.md); model-picker verification alone is not evidence of full application parity.
