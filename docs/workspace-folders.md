# 多根目录工作区

一个工作区可以注册 1–32 个服务端根目录，保存后的目录清单属于 Host，而不是某台浏览器的本地偏好。

## 入口与操作

- 侧栏的 **打开工作区**：服务端目录输入框右侧的 **浏览服务端目录** 按钮打开 Host 文件夹浏览器。
- 空会话的 **工作位置 → 目录**：同样提供右侧浏览按钮，默认从当前项目路径开始浏览。
- 项目操作菜单，以及打开工作区列表中的编辑图标：进入 **管理工作区目录**。

浏览器只列出文件夹，可以进入子目录、返回上一级、使用快速位置或输入绝对路径。勾选支持跨目录保留；“加入所选目录”返回目录管理页面，再点击“保存工作区”确认。浏览、勾选和未保存的编辑不会改动文件系统。

原有直接输入路径并“添加项目”的单目录流程仍保留；已有单目录项目可以从“管理工作区目录”加入其他根目录。

目录管理页面允许修改短名称和物理路径、移除引用，并用上/下操作调整优先级。第一项为默认工作目录。取消会丢弃未保存的草稿；“丢弃修改并重新加载”明确以服务端版本替换草稿。运行或排队中的任务会阻止根目录配置变更。

## 虚拟目录与实际位置

例如注册 `frontend` 和 `backend` 后，文件工具使用 `frontend/src/App.tsx` 或 `backend/server.ts`，不必携带完整的物理路径。未带根目录名的相对文件路径指向第一项。查找和搜索默认按优先级遍历所有根目录。

执行命令的工作目录与 Git 的默认目录均为第一项；指定其他根目录的 Git `cwd` 可以使用别名。命令环境提供 `HBAR_WORKSPACE_ROOT`，其下的别名链接指向选中的实际目录。命令跨根访问时可以使用该环境变量，不能假定其他根目录位于第一项目录内部。

Host 创建版本化的别名链接容器，不移动或复制原目录。Windows 使用目录 junction；每次映射访问检查链接是否仍指向注册的目标。移除引用不会删除原文件或文件夹。虚拟目录映射不是操作系统级安全沙盒，现有路径授权、受保护 Host 数据限制、符号链接边界检查和系统级隔离策略仍分别生效。

工作区的原始 `path` 保留为身份锚点；调整优先级改变默认执行目录，不改变项目 ID，也不会自动重命名项目。旧工作区未保存多根配置时保留原来的单目录文件布局。隔离 worktree 只替换与原始项目锚点匹配的根目录；其他根目录仍使用其注册路径。

## 并发与结果确认

保存使用配置版本检查和用户作用域的幂等请求键。其他窗口先保存时，本窗口显示冲突并保留草稿，必须重新加载后再编辑。断线或响应丢失时，原请求及请求键在当前运行时保留；关闭再打开管理窗口不会用新请求覆盖未确认的操作。先“核对保存结果”，必要时“重试原保存请求”，两者都使用原始请求。

目录页面按 200 项分页；服务端单次目录扫描有 5000 项上限，达到上限会提示输入更具体的路径。不存在、重复实际目录、不可访问或受保护的目录均不能保存。
