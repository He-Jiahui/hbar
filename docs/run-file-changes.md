# 每轮文件修改汇总

每个 Run 结束（完成、失败、取消或中断）后，文件汇总记录本轮已提交的实际文本写入。没有净修改时不展示卡片。这里的“会话结束”指一轮助手执行结束，持续目标和下一轮对话各自有独立汇总。

`ToolResult.fileChanges` 是插件 SDK 的测量契约：路径必须是工作区相对路径，`before`/`after` 是实际写入前后的文本，`null` 表示文件不存在，空字符串表示存在的空文件。执行网关捕获 Host 的执行根，工具参数不能选择汇总根。内置 `write_file`、`edit_file`（包括工作流中的嵌套调用）提供该记录；其他写入插件需要实现同一契约。任意 shell 命令及外部编辑器的修改不会被猜测为本轮写入。

Storage 从提交的工具结果构建可重放投影。同一路径取首次修改前、最后修改后的版本，恢复到原样的文件不计入修改数。摘要只包含文件数、净增删行数及前三个文件；详细列表以每页 50 个文件读取，差异以每页 200 行读取并折叠长段未变内容。每轮最多记录 256 个文件、32 MiB 版本文本，单个版本最多 2 MiB。达到记录容量后明确标记不完整并关闭撤销。差异计算有时间和编辑长度上限，无法准确计算时计数返回 `null`，不伪装成零。

撤销通过 Host 命令执行，绑定原始 Session 和 Run。Kernel 在与分支切换、排队执行共用的检出目录锁中检查任务已结束、工作区没有活动任务、执行根未切换。执行提供者逐文件核对当前版本与原始写入后的版本，全部检查通过后才恢复；新建文件恢复为不存在，原有空文件恢复为空文件。与内置写入共享文件锁；写入失败会尝试回滚，后续修改冲突时不会覆盖冲突文件。撤销完成记录是持久事件，重试幂等，历史差异继续可查看。

外部进程不受 Host 文件锁约束；恢复操作逐次复核版本并在回滚时也检查版本，无法保证任意外部写入与多文件恢复之间具备文件系统级事务隔离。恢复后会保留历史汇总并明确显示已撤销。

数据验证：`tests/run-file-changes.test.ts` 覆盖实际工具和 Host 命令、版本冲突、重复编辑、空文件、新建文件、失败/取消后部分写入、分页/容量、重放恢复以及批量恢复失败回滚。
