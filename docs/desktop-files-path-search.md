# Files: All files path search

Reference evidence: cc-haha's published `D:/Git/cc-haha/docs/images/app/en/workspace-changes.webp` shows the search control inside Files above its list, but that particular frame is in Changed mode. The All-mode behavior is established by `desktop/src/components/workspace/WorkspacePanel.tsx` and the deep-directory cases in `WorkspacePanel.test.tsx`: path results can be opened without expanding ancestors, and returning from preview retains the query. The reference repository was read-only.

hbar previously filtered only already-loaded tree nodes. The existing Host `file.find` command now backs the same All-files search field with a 250 ms debounce and a 100-result limit. It searches case-insensitive workspace-relative **file paths**, not contents or directory names. A result shows its file name and parent path and opens through the existing file-preview command; returning preserves the query and any unsaved document draft. Clearing restores the lazy tree. Search has distinct loading, no-match, error/retry and truncated states, with no silent fallback to loaded nodes. In-flight work is aborted on query change, panel close, target change and mode switch; late results are ignored by panel/workspace/query identity. Keyboard Arrow Up/Down, Home/End, Enter and Escape work in the search field without intercepting IME composition.

The copy is supplied by the web Host in Chinese and English. Search/clear/refresh use the shared semantic `sm` icon tier and stay in a single flexible toolbar at 320 px; the result list flows with long file names and parent paths. The screenshot layout is not reproduced with absolute coordinates or fixed content heights.

Historical verification for the initial path-search feature (`25dda457`): `tests/file-workspace-search.test.ts` exercises unopened paths, preview/back/draft, no match, error/retry, truncation, superseded response and close/rebind isolation. `e2e/file-workspace-tree.spec.ts` ran against a real temporary Host in en-US and zh-CN (2/2), including 1440/1024/390/320 widths, two same-named files in different parents, keyboard End/Enter, Escape, preview/back, original tree navigation and unsaved draft. Those assertions did not prove the first ArrowDown or actual result focus. Production screenshots were inspected at `artifacts/file-search/search-en-US-1440.png` and `artifacts/file-search/search-zh-CN-320.png`. This is not content search and does not add a Search chats contract.

## Native keyboard focus repair

Reference source: read-only cc-haha `e28d0a653481ef41b7a329411eeb2f0fd5656731`, `desktop/src/components/workspace/WorkspacePanel.tsx`. `WorkspaceFilterInput` passes ArrowDown to the first result; `WorkspaceSearchResultRow` moves actual button focus for ArrowDown/ArrowUp/Home/End and clears/refocuses the input on Escape. The original `WorkspacePanel` was rendered unchanged with a synthetic session and in-memory workspace API responses, not a native CC process or live backend. The continuous keyboard capture and DOM active-element observations are in `artifacts/file-search-keyboard-v16/reference/keyboard-flow-report.json` and its adjacent screenshots. This establishes UI behavior, not backend search correctness or full-window visual parity.

On hbar `6c3a1078`, the regression reproduced with a production Web build and real temporary demo Host: after the first ArrowDown, DOM focus remained on the search input and `aria-current` moved to the second result. The original path-search change `25dda457` introduced `activePath = null`, then clamped the missing index to zero before adding one, and changed only the highlight instead of native focus. The red snapshot is `artifacts/file-search-keyboard-v16/hbar-first-result-red.json`.

The repair removes that parallel selection state. Input ArrowDown focuses the first actual enabled result; result ArrowUp/Down/Home/End move native focus within the current rendered list, and native Enter/Space activate the focused file button. Input Home/End, ArrowUp and first-result Enter shortcuts remain available. IME composition is not intercepted. Keyboard focus uses the shared visible focus ring, while `aria-current="page"` identifies the opened file instead of a hover or artificial keyboard index. Hover cannot change which file Enter opens. Escape and the clear action clear the query and focus the input.

Result DOM identity includes the panel, workspace, source Session, Session file target and query. A removed or disabled focused row recovers into the visible search input only while the old list still owns focus; another pane's focus is not reclaimed. The existing Host-owned labels, `sm` icons, 100-result bound and pane-owned flex scroll layout are unchanged. No overlay coordinates, fixed content height, additional copy or backend contracts were introduced.
