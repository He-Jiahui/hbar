# Pre-session branch creation

The Location picker exposes branch creation before a Session exists: open Location, choose Branch, then choose New branch. The form is part of the picker; it does not add a separate composer action. Cancel returns to the branch list. On confirmed creation, the picker closes, the new branch becomes the draft's selected branch, and the prompt text remains unchanged.

The selected base is captured from the registered workspace, as an exact local branch ref and commit OID. The Host creates `refs/heads/<name>` only if the requested base still matches that OID. It does not check out the new branch or change the registered worktree's HEAD. The user can search and choose a different available local branch in the picker; that selection is also draft-only and does not switch branches when clicked.

Existing branch selection returns to Location's root view, clears the search, and focuses its Branch row so the user can continue choosing the working-tree mode. This follows CC `RepositoryLaunchControls.tsx:361-365`. Mode selection and successful new-branch creation close the picker; ordinary existing-row selection does not close it early. Desktop/narrow shared and isolated main-flow browser tests cover that distinction.

The return transition keeps the already-read repository page. A fresh unfiltered branch read starts when the Branch view is reopened; it does not transiently remove the root Branch control and lose keyboard focus. The combined branch-creation/Location browser suite passed 4/4 in English desktop and Chinese narrow layouts after this correction.

In shared mode, selecting or creating a branch stores `{ mode: 'shared-branch', branch: { ref, tipOid } }`. Host launch preparation applies that branch on first Send, not while the Location menu is open. In isolated mode, selection stores a derived base ref; first Send prepares a per-Session worktree branch from it rather than checking out the selected base in the registered worktree. Creating a branch and choosing an isolated base require a committed local branch in a registered repository-root workspace. Remote refs are not offered. Existing shared-branch selection follows the Host's reported availability and is not widened into branch creation for repository subdirectories.

Create requests use one attempt key for request correlation, not a durable receipt or replay guarantee. If the response is uncertain, the UI blocks another write and performs only a bounded, read-only exact-ref/OID check. A matching ref can be adopted only after the user confirms; a missing, different, or incomplete result is not automatically retried. The branch ref is not removed on cancel or application teardown.

The first browser run exposed an inner form whose submit could reach the composer Send. The picker now uses an ordinary flow container with an explicit Create button; name-input Enter uses the same enabled condition and prevents the outer submit, while search-input Enter cannot send a message. Unknown operations retain their original name, perform read-only checking and require explicit adoption. This change uses host-provided localized copy and shared icon tiers; no coordinate-based content layout was introduced.

This slice integrates the no-Session pre-session landing/client draft. It does not yet add this editable Location picker to an already-created empty Host Session reached through the sidebar's New Session action; that entrance needs its own integration and verification rather than being inferred from these two tests.
