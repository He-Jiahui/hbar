# 会话用户消息锚点

会话内容区左侧的短线对应真实用户消息。悬停或键盘聚焦显示用户原文和该轮最后一条文字回复的预览，点击或按 Enter 跳到消息起点；当前阅读的对话使用更长、更亮的短线。附件消息使用宿主提供的附件文案。空消息、工具输出、隐藏推理和已识别的自动 Goal 输入不生成锚点，运行中的用户引导仍可定位。

锚点复用 Session timeline 的消息、分页和虚拟列表定位，不请求模型生成摘要。每组最多显示 24 条，上一组、下一组与上下方向键可浏览已加载的对话，Home / End 跳到首末锚点。“加载更早的对话锚点”复用现有历史分页，并展示读取、重试和容量边界。原有 1,000 条消息上限保持有效。

跳转通过会话阅读状态发起；先关闭会话搜索并结束上一条定位请求，然后按消息 ID 定位。工作区、会话、页签实例和运行时身份校验可拦截过期回调。草稿保留，其他会话不继承锚点预览或分组。设置和文件页返回继续使用已有阅读位置恢复；刷新后根据加载的消息重新构造锚点。

预览使用共享 LumenFloatingSurface 的右侧定位、顶层协调、模糊背景和窗口边界约束。所有标签来自 Host 的类型化中英文文案。正文是有界纯文本，按完整字素截断，用户标题显示一行、回复最多三行。轨道在普通 flex 流中垂直居中；预览是唯一的覆盖层，窄屏继续可用。

## 参考与验证

- 视觉参考：用户提供的 Codex 会话锚点截图，短线轨道和右侧内容预览。
- 结构参考：[ReactBits AI Chat 1](https://pro.reactbits.dev/docs/app-ui/ai-chat/ai-chat-1)，维持消息、工具与输入框的顺序。
- 浮层交互参考：[ReactBits App Dialog](https://pro.reactbits.dev/docs/app-ui/app-dialog)，通过现有 Lumen 契约实现。
- `tests/conversation-anchors.test.tsx` 覆盖真实消息筛选、中英文、附件、空列表、单条、24 / 25 / 1,000 条、中文与 emoji、4,000 字符消息、分组和历史状态。
- `e2e/conversation-anchors.spec.ts` 使用真实临时 Host 验证预览、分页、虚拟消息跳转、键盘、搜索、设置返回、会话切换、刷新和草稿保留；检查 1440 / 390 / 320 宽度、页面错误和溢出。
- `e2e/session-reading-return.spec.ts` 验证原有设置、文件工作台及跨会话阅读位置恢复。

本次验证中，锚点、会话阅读与搜索相关的 114 项 Bun 测试通过，3 条锚点 E2E 通过；相关源码的严格类型检查、lint、Web 构建及文案／图标／布局契约检查通过。全仓类型检查仍有旧 Web 模块引用和其他测试的既有错误。原有阅读恢复 E2E 出现位置偏移；在未接入锚点的 `c115323c` 基线版本中也复现了同一首条可见消息偏移，不能将这一门禁标记为全部通过。
