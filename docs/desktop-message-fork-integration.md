# 消息旁 Fork 的桌面交互

cc-haha 的 `desktop/src/components/chat/MessageActionBar.tsx`、`MessageList.tsx` 和 `turnCompletion.ts` 把 Fork 放在已完成用户消息及最终助手回复的复制操作旁，而不是会话标题或全局命令中。隔离组件截图只能证明动作位置；本实现的结果以真实 Host 验证为准。

hbar 先由 Host 的 `session.forkableMessages` 按消息 ID 批量给出资格，再在消息旁显示具名 Fork 图标。资格查询读取持久 Run 和完整工具前缀，不凭前端快照的 40 条 Run 上限猜测；复制到子会话、但没有子 Run 记录的历史消息不会再次误显为可 Fork。点击携带原会话、消息和页签实例，预留 32 页签中的一个位置，再用持久幂等键创建精确消息前缀。子会话作为新页签打开；来源已切换时只保留已创建事实，不抢当前导航。用户消息的复制标签是“复制消息”，助手仍是“复制回复”。

写入失去回执时，动作保持“结果未知”，只允许 `session.forkFromMessageReceipt` 用原操作者、原目标与原键只读核对，不重新发创建。查不到回执不等于原请求确定失败；入口继续保持未知。成功但跳转失败时，子会话仍在页签里，来源行标示已建立。来源会话和子会话中的草稿各有归属，Fork 不消费当前输入框内容。

已验证的范围：底层目标/工具完整性、超过 40 条 Run 的历史资格、身份/哈希冲突、回执丢失后的重启核对、32 页签预检和迟到导航由聚焦 Bun 测试覆盖；真实临时 Host 的 en-US/zh-CN 浏览器用例点击用户与最终助手两处入口，检查两个子会话分别只有 1/2 条消息、没有伪造的 Run、来源消息仍在，并在 320px 下确认可点击且无水平溢出。截图位于 `artifacts/reference-fork/actions-{en-US,zh-CN}-{1440,320}.png`，是 hbar 运行结果，不是参考产品截图。此范围不声称任意中途助手消息、未完成 Run 或不可见的无限历史都可 Fork；客户端历史仍有 1,000 条已加载消息上限。Browser、Terminal、Team 与斜杠入口另行验收。
