# 会话顶部自动加载历史

会话消息区向上滚动到顶部时自动读取更早的一页消息。原来的“加载更早消息”按钮改为宿主提供的中英文文字提示；加载时显示进度，失败时保留就近重试按钮，断线时不发起新请求。消息仍由现有 Session timeline 按 60 条分页，并遵守 1,000 条容量限制。

滚轮、向下拖动手指以查看前文、消息区内的 Home / PageUp / 向上键，以及原生滚动条均可形成阅读意图。打开会话、程序定位、搜索定位和虚拟列表的测量修正不会自行加载历史。输入框、嵌套代码区和左侧锚点条的滚动不属于消息区。

每次顶部意图最多读取一页，读取中拒绝重复触发；同一个游标没有新增内容时不会循环请求。顶部虚拟行尚未进入可见区域时，最多等待 16 个动画帧后再读取，避免把尚未重绘的尾部行当成顶部阅读位置。

分页捕获原消息 ID 与偏移，成功后通过现有受控阅读定位恢复。用户向下滚动、发起新的定位、切换搜索结果、切换会话／页签／Host 时不恢复旧位置。异步页面继续由 timeline 的 selection generation 校验，旧目标的迟到响应不能污染当前会话。没有新增传输、数据库或模型请求。

## 手动复核

实现版本为 `a0f5883e`。打开具有超过一页历史的会话，确认消息区没有普通加载按钮；向上滚动到顶部，观察加载文字与更早消息插入，原消息仍处于原阅读范围。重复顶部滚动可以继续查看上一页，达到历史尽头后提示消失。

读取中再次向上滚动不会并发请求同一页。断线时保留草稿，重连后再向上滚动可继续；失败时使用消息区的重试入口。切换到空会话后，原会话的迟到页面不能出现在空会话中。输入框里的 Home 和消息锚点跳转不应自动触发历史分页。
