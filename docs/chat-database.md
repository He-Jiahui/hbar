# 聊天数据库设置、监控与清理

打开 **设置 → 聊天数据库**，在“存储位置”之后查看当前 Host 的占用、保留规则、自动任务、手动清理和执行记录。页面支持全局、项目和会话三个范围，复用已有设置表单的保存、冲突核对和恢复继承操作。

## 占用统计

全局概览显示聊天和消息数量、消息内容字节、数据库历史负载、SQLite 主文件与 WAL/SHM、数据库空闲页、聊天日志、原始附件和磁盘缓存。消息内容和数据库文件采用不同口径，不能相加作为实际磁盘占用。

全局总占用使用数据库、日志、附件和缓存的实际文件字节。项目及会话显示可归属的历史负载、日志及去重附件引用，SQLite 文件和缓存另列为全局共享信息。同一附件可被多个项目引用，因此各项目数字不能直接相加。

统计显示采样时间及完整性。旧数据按批次回填，目录扫描分批进行；统计不完整时不启动容量清理。页面可见且连接正常时每 30 秒刷新，也可手动刷新。

## 保留规则与自动任务

| 配置             | 默认值及含义                                                              |
| ---------------- | ------------------------------------------------------------------------- |
| 保留天数         | 90 天，范围 1–36,500 天；按最后一次消息或运行活动，重命名和归档不延长期限 |
| 仅清理已归档聊天 | 开启；关闭后按同样规则检查未归档聊天                                      |
| 自动清理         | 关闭，需要保存后才生效                                                    |
| 定时清理         | 每天 03:00，Asia/Shanghai；支持每周、星期、时间及 IANA 时区               |
| 容量触发         | 关闭；默认上限 1,024 MiB，目标降至上限的 90%                              |
| 容量优先         | 关闭；开启后容量任务可突破保留天数，仍遵守归档与活动保护                  |
| 缓存保留         | 7 天，仅全局配置，可设为 0 天                                             |
| 无引用附件保留   | 7 天，仅全局配置，至少 1 天，仍需通过引用和上传检查                       |

子层可覆盖规则或恢复继承。任务使用已保存值，编辑中的草稿不改变正在运行的任务。全局及有显式清理覆盖的项目、会话维护各自的任务游标，纯继承不重复建立计划。父范围自动任务逐聊天解析子层规则，跳过显式关闭自动清理的目标。

Host 每分钟检查触发条件。Host 关闭期间不会执行，重启后最多补一次错过的周期。容量任务最旧优先，全局先回收可清理缓存和无引用附件；无法达到目标时记录剩余占用和跳过原因，不因 SQLite 文件暂未缩小而继续扩大删除集合。

## 手动清理

| 操作               | 可用范围                                                   |
| ------------------ | ---------------------------------------------------------- |
| 按规则清理聊天     | 全局、项目、会话，按整条聊天删除                           |
| 清理缓存           | 全局，仅已知且可重建的类别                                 |
| 回收无引用附件     | 全局；项目和会话仅能回收因自身聊天清理而失去最后引用的附件 |
| 回收数据库空闲空间 | 全局，在 Host 空闲时运行独立受管 Worker                    |

先生成预览，再检查候选、预计回收量和跳过原因。预览固定集合，有效期 5 分钟；清理不增加集合外目标。确认后核对规则 revision，每项删除前再次核对活动、聊天版本或文件身份。预览与记录采用游标分页，每页 50 项。

最多一个清理作业运行。关闭设置页不会停止 Host 作业，取消在安全边界生效，已删除部分如实记录。VACUUM 的不可立即中止阶段显示“取消已请求”，直到 Worker 退出并核实终态。断线或丢失响应时按原请求、幂等键和 operationId 核对，不换新标识重复清理。

删除聊天通常先增加 SQLite 可复用空闲页，数据库主文件未必立即缩小。“回收数据库空闲空间”执行 checkpoint、VACUUM 和完整性核对，区分实际回收字节与可复用空间。

## 保护与恢复

运行中、排队、待审批、待输入、待续跑、执行目标准备中的聊天及启用中的定时任务目标会跳过。有保留子聊天或 Agent 的父聊天也会跳过，符合条件的树按叶子优先处理。

消息、工具结果、Run、事件日志、设置背景、定时任务及持久草稿都参与附件引用检查。上传前建立哈希保留声明，上传 lease 与删除互斥。回填不完整、旧设备草稿清单未确认或仍有引用时保守保留。

Web 会话、新聊天和外观草稿使用独立窗口命名空间声明引用。关闭窗口及设备离线不释放引用，显式移除、丢弃或发送成功后释放或转移。上传响应丢失后保留原哈希和请求身份；既有老设备的未知清单不能自动视为空清单。

缓存不跟随符号链接或 Windows junction，跳过使用中资源、锁、挂载、Git 工作树、注册插件根目录和未知类别。预览后新增引用、文件变化或路径重定向会阻止删除。

聊天删除标记、资源回收日志和维护回执保存在 SQLite 之外。重启及日志重建先核对这些记录，已清理聊天不会从旧日志复活。删除同步侧栏、搜索和打开的聊天，重连后核对已打开目标。保留的已删除页签显示空态，草稿仍可编辑、附件仍可显式移除，无法向该聊天继续发送。

## 接口与验证

公开 Client SDK 的 `createChatDatabaseCommandClient` 提供统计、任务、预览、清理、作业、取消、回执核对、记录及草稿引用命令。副作用命令要求幂等键，长操作立即返回受理标识。Zod 校验契约，kernel 负责策略和调度，Storage Worker 负责投影、事务与恢复，Runtime 管理页面和作业状态。

数据库从 schema 22 前向迁移至 23。Host、桌面资源和 standalone CLI 都包含 maintenance Worker。存储与恢复实现见[架构说明](architecture.md)，检查方法见[验证说明](testing.md)。

页面注册来自 `apps/web/src/settings-presentation.json`。分组、字段流和保存区域依据 [Settings Form 1](https://pro.reactbits.dev/docs/app-ui/settings-form/settings-form-1)，清理操作及确认流程依据 [Settings Form 6](https://pro.reactbits.dev/docs/app-ui/settings-form/settings-form-6) 的公开预览结构，使用现有 Lumen 语义主题、图标尺寸及共享浮层落地。

完整浏览器路径使用真实临时 Host：

```text
bun run build
bun run test:e2e -- e2e/chat-database-settings.spec.ts e2e/chat-database-drafts.spec.ts e2e/chat-database-deletion.spec.ts
```

这些场景覆盖英文桌面、中文窄屏、保存与继承、真实占用变化、固定预览、分页、丢失响应、两个窗口的草稿引用、在线与离线删除、焦点及溢出。定向测试通过不代表全仓门禁通过，仓库级 lint、typecheck、基础测试及构建结果须另行报告。
