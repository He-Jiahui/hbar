# 有界文本搜索与续页

`search_text` 按工作区内相对文件路径、行号的稳定顺序返回命中行。同一行的多个匹配算一条，
上下文行不额外占用条目数量。多根工作区先按已保存的文件夹优先级，再按各根内的路径、行号排列，
返回 `frontend/src/a.ts` 这样的虚拟路径，不展开实际服务端绝对路径。

## 参数

| 参数         | 默认    | 语义                                                                               |
| ------------ | ------- | ---------------------------------------------------------------------------------- |
| `limit`      | `200`   | 当前页最多返回的命中行数，范围 `1–1000`；文本字节上限可能使实际页更短。            |
| `from_index` | `0`     | 从 0 开始的命中行索引。续页使用上次返回的 `pagination.nextIndex`。                 |
| `fully_scan` | `false` | 为 `true` 时继续扫描全部符合现有规则的文件，统计完整命中数量，并尝试缓存完整索引。 |

续页时保持其他搜索参数及工作区根目录顺序不变。`from_index` 不是文件字节偏移，也不是页码；
不要自行加 `limit`，因为超长文本可能导致当前页少于 `limit` 条。文件或搜索范围变化时，索引对应
当前重新验证后的文件状态，不是持久快照；需要严格遍历同一批结果时，应避免过程中修改文件。

```json
{ "pattern": "WorkspaceQuery", "literal": true, "limit": 20, "fully_scan": true }
```

收到 `nextIndex: 20` 后：

```json
{ "pattern": "WorkspaceQuery", "literal": true, "limit": 20, "from_index": 20 }
```

## 停止、统计与折叠提示

普通模式首次没有完整缓存时，达到请求的命中行预算就停止内容匹配，不再为隐藏内容计数。
因为有稳定排序和新增／删除验证要求，目录发现仍会执行；这不等同于停止遍历目录。
命中数恰好达到上限但未验证结尾时也可能提示未知，下一页可以为空，不虚构一个“至少还有一条”。

工具正文的 UTF-8 上限是 **64 KiB**，其中为末尾提示保留空间。原生单页正文预算是 60 KiB；
工具格式化层再次按完整命中组限量，续页索引只跨过实际显示的条目。如果第一条原文或上下文过长，
优先保留命中行的路径、行号和部分文本，标记 `textTruncated` 并提示用 `read_file` 按行读取原文。
续页不用于补全同一条被截短的长行。

有未显示内容时，输出末尾使用“折叠了剩余内容”提示：

- 未完整扫描：只给本页数量、未知剩余数量，以及 `from_index` 和 `fully_scan=true` 的继续方式。
- 完整扫描或有效完整缓存：给准确的总命中数、剩余命中数、缓存状态与续页索引。
- 剩余目录摘要最多六组；目录过多时归并到上级目录，并把更多分组计入“其他目录”。长目录名缩短显示。
- 仅原文被截短而没有剩余条目时明确区分这两种情况，不提示不存在的下一页。

结构化 `details.matchCount` 是实际显示条数；`details.pagination` 提供 `fromIndex`、可选的
`nextIndex`、`scanComplete`、完整扫描时的 `totalMatches/remainingMatches`、`cacheHit/cacheStored/cacheLimited`、
以及压缩后的 `folders/otherMatches/foldersCompressed`。没有完成扫描时不提供猜测总数。

## 缓存与边界

完整缓存保存文件身份、版本和完整命中行索引，不保存无界的结果正文。查询键隔离工作区、范围、
pattern、匹配模式、大小写、include/exclude、隐藏文件选项及受保护目录；页大小和上下文数量不妨碍复用。

每次复用前仍重新发现符合规则的文件，并检查版本：修改、替换、添加、删除、改名、忽略规则变化都会
使不再匹配的缓存失效。Host 写操作显式使完整查询计划失效。缓存最多 32 个完整计划，5 分钟 TTL，
单个计划最多 4 MiB 且最多使用配置总缓存容量的一半，纳入现有总字节预算和 LRU 回收。
超出容量或无法可靠验证身份时仍返回已完成扫描的准确统计，但明确标记未保存完整缓存，不冒充缓存成功。

`fully_scan` 仍限制在获准的工作区和现有搜索规则内：忽略文件规则、默认隐藏文件排除、二进制／无效
UTF-8 跳过、单文件 2 MiB、每根最多 100,000 个符合条件的文件。查询沿用 Host 的有界队列、
并发数、30 秒超时和取消生命周期；超时／取消不会发布半份完整查询计划。它不是扫描整台电脑，
也不是脱离工具生命周期的后台任务。

## 验证

定向覆盖参数默认值与边界、普通模式停止且不缓存部分匹配、超过 1,000 条的完整索引缓存、
续页及上下文复用、变化与忽略规则失效、容量不足、UTF-8 长行、多根跨界和字节限量续页、
压缩目录摘要，以及真实 Kernel 工具门禁与模型 Run 中的分页结果。

```text
bun test ./tests/local-tools-native.test.ts ./tests/search-text-pagination-native.test.ts ./tests/workspace-query-runtime.test.ts ./tests/local-tools.test.ts ./tests/search-text-pagination-output.test.ts ./tests/search-text-pagination-mounts.test.ts
```

原生模块使用 `bun run native:build` 构建。这里的验收是现有查询 N-API 模块和真实 Host 工具路径，
不是桌面安装包或真实商业模型的原生窗口验收；本轮没有生成或安装新的 EXE。
