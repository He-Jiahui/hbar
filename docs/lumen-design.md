# Lumen 视觉设计评审

目标：轻盈简洁的 AI 开发工作台。低噪声表面、稳定的紧凑动作行、清楚的语义着色、自然的交互过渡。留白主要给阅读与区域分组，工具动作和操作标签保持紧凑单行。

## 2026-10-10 的公共组件与全界面升级

Lumen 已有独立的 [包级 DESIGN.md](../hbar-ui/packages/lumen-app-ui/DESIGN.md)，生产组件与交互验收消费同一公共实现。`@lumen/app-ui` 提供外观和通用组合，`@hbar/app-react` 接入业务 ViewModel，Web 宿主提供类型化文案、数据和回调。

- 表面角色 `canvas / navigation / reading / raised / overlay` 与 `glass / frost / solid` 材质分开；阅读区连续，输入区保留一个表单表面。
- 文本位置由 `LumenContentText` 声明。按钮、状态、工具标签完整单行，侧栏记录左对齐并末尾裁剪，弹窗和说明自然换行，技术原文由所属区域承接局部滚动。
- 页面标题、紧凑记录、指标、自适应操作栏和抽屉使用公共组合。输入辅助操作进入“更多”，发送／停止常驻；工具呈现切换沿用同一实例和阅读位置。
- 新布局默认关闭右侧工具，并为对话保留 `32rem` 阅读预算。会话状态分为概览、请求和原始消息；详情按需挂载，再次访问保留展开状态。
- 动作类别与结果颜色独立；成功绿、警告黄、失败红、进行中蓝。发光沿组件轮廓，呼吸与过渡不改变控件几何尺寸。浅色默认的辅助文字和成功色依据实际背景采样调整，宿主自定义色值继续保留。

全界面清单、六个维度的评估、前后截图和实际检查结果见 [升级验收记录](ui-visual-upgrade.md)。下文保留 2026-10-06 的评审和验证历史；其中当时的工程检查限制不代表本轮最新结果。

| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |

## 本轮检查与改进

2026-10-06 在 Tauri 开发窗口与浏览器检查到：

1. 工程侧栏把通用侧栏再嵌入两个参考变体表面，产生多层边界和圆角。侧栏应是一个连续导航区域，内部用组间距组织。
2. 默认 `HbarPromptComposer` 把真实受控表单再放入完整 Prompt Input 示例外壳。外层玻璃、表单边界、内部阴影和编辑器边界同时出现，削弱了输入内容的层级。
3. 侧栏品牌标题与新建会话标题比导航和正文更强，重复占据视觉焦点。品牌、区域标题与主内容标题需要少量可随设置缩放的层级。
4. 侧栏底部的功能入口连续横排，长文案和窄侧栏容易拥挤。保持文字单行，按内容宽度自然分行组织按钮，保留通知入口。

实施范围是 hbar 的宿主组合与样式。使用现有 Lumen primitives 和受控数据，不修改各参考变体的独立预览、不改变 Markdown 或工具输出原文，不替换主题色板。

已经落实：

- [工作台组合](../packages/app-react/src/lumen-workspace-shell.tsx)直接使用通用侧栏和工具栏，去掉重复的 Sidebar / Navbar 示例表面。导航、焦点和宿主插槽保持原有接口。
- [输入区组合](../packages/app-react/src/prompt-composer.tsx)默认直接返回受控 `LumenPromptComposer`，明确指定的 1 / 4 / 7 变体仍可用。
- [宿主样式](../apps/web/src/workbench-design.css)降低品牌与空态标题的强调程度，整理导航组间距和底部入口，移除重复阴影，给新建会话输入区更多留白；字体层级与圆角跟随 Lumen 外观设置。
- 输入焦点由父表单清楚表达，失败保持危险色，系统高对比度保留可见边界。会话编辑器使用自己维护的字体、行距、内边距和测量，宿主不覆盖这些排版参数。

本轮验证：17 项现有组件测试、24 个浏览器布局/交互组合、8 次真实 Host 会话检查通过。浏览器覆盖中英文、明暗、桌面/平板/窄屏/短视口、125% 文字放大、菜单与焦点返回、reduced motion、motion off 和 forced colors。真实会话覆盖 1440 / 320 两种宽度、两种语言，每个场景运行两次，核对折叠、完整 Copy、草稿和重载。

验收脚本通过实际键盘阅读意图与控件可点击条件等待测量稳定，保留完整的可见性、位置稳定和无额外工具执行断言。此次不修改组件库的业务滚动逻辑。

改动范围的严格 lint、类型检查、布局/文案/图标守卫与 Web 构建通过。完整仓库 typecheck 仍有 CLI、存储和旧测试入口的错误；全库文档检查仍有 142 个既有失效链接。本次设计文档的本地链接和七份参考校验均通过。

## 后续优化：会话阅读层级

2026-10-06 继续优化时，实测 Lumen 文字设置从中改为大，正文仍固定为 14.5px、思考详情 12.5px、代码 13px。Markdown 一级标题由浏览器默认样式放大到 29px；表格没有稳定的单元格留白与分隔。

已经调整：

- 会话统一使用从 `--lumen-font-size` 派生的正文、详情、辅助信息字号，覆盖正文、思考、摘要、工具标签、状态文本、代码与命令输出。中档正文为 14.7px，大档为 16.8px；页面缩放继续等比例生效。
- Markdown 标题改为较克制的相对层级，一级标题为所属正文的 1.5 倍；段落、列表、引用和分隔使用一致的阅读节奏。
- 思考详情去掉外层卡片，使用轻量左侧分隔；代码与工具原始输出保留独立的阅读边界。
- 表格左对齐、增加单元格留白和细分隔；超长连续值由表格自身横向滚动，不撑宽会话。

参考：[AI Chat 1](https://pro.reactbits.dev/docs/app-ui/ai-chat/ai-chat-1) — 保持思考 disclosure、工具调用、答案与代码的阅读顺序；[Tool Calls 5](https://pro.reactbits.dev/docs/app-ui/tool-calls/tool-calls-5) — 保持命令输入与结果的单层组织。采用 Apple / Runway 的克制阅读层级与 Cursor 的技术内容角色，不导入参考品牌色板。

验证：41 个已有消息、代码、复制和高亮测试通过；新增 8 个浏览器场景覆盖中英文、明暗、1440 / 320 宽度、小中大文字设置和 125% 页面缩放，核对折叠状态、焦点、代码与工具结果的完整 Copy、原始参数和表格滚动。组件浏览器回归另外覆盖语义颜色、工具标签、结果状态、蓝色呼吸与原始输出。

全库 TypeScript 检查仍报告 CLI 插件类型、旧 Web 入口、存储接口与既有 E2E 的错误。全库 lint 在现有 8GB 堆限制下耗尽内存；当前改动使用严格配置执行范围检查，不把全库门禁写成通过。

## 后续优化：统一导航运行反馈

侧栏运行图标此前使用成功绿和私有的 1 秒旋转动画，与会话中的信息蓝呼吸不一致，也没有处理 Lumen 的关闭动效设置。现在工程视图与时间视图共用 [运行指示器](../packages/app-react/src/session-activity-indicator.tsx)，运行状态直接复用公开 `LumenIndicator` 的信息蓝呼吸；等待审批保持警告图标，排队和取消请求使用静态辅助图标。状态占位由 `sm` 图标语义尺寸决定，状态切换不改变占位大小。

动效与发光使用 Lumen 的现有时长、光强和主题变量。关闭动效、减少动态效果、零发光和系统高对比度保留可见的状态与可访问名称。悬浮过渡与呼吸只改变绘制强度，浏览器验收核对中间帧和前后尺寸。

参考：[App Shell 9](https://pro.reactbits.dev/docs/app-ui/app-shell/app-shell-9) — 保持工程 / 会话导航与主阅读区的关系；[Agent Activity 3](https://pro.reactbits.dev/docs/app-ui/agent-activity/agent-activity-3) — 用紧凑状态表达真实运行与审批，颜色采用项目的信息 / 警告角色。

最终验证：50 个相关单元测试通过；阅读和运行指示器共 12 个受控浏览器场景通过。真实本地 Host 的后台任务在工程 / 时间视图中经历运行、等待审批和取消，保留草稿、正确更新状态；4 个持久化 read_file 会话核对完整 Copy、原始参数、折叠、草稿和重载。工具会话验收副本只把准备阶段的展开入口同步为当前 `LumenTreeItem`，原有工具与持久化断言不变，版本和资产校验保存在验收记录中。

Tauri 开发窗口通过只读检查确认已经热加载新的阅读字号与运行指示器样式，旧旋转样式未加载，没有 Vite 编译错误覆盖层；没有改动用户当前窗口的导航或表单草稿。

检查限制：3 个已有外壳测试仍断言旧导航的 `aria-current="page"`。在只替换回优化前运行指示器、保留其他当前代码的隔离加载实验中，仍出现完全相同的 3 项失败；当前另有进行中的树形导航改动。此处记录基线差异，不将它们计入通过的测试，也不改写其他任务的导航实现。全库 typecheck 与 lint 限制仍如前述；当前改动范围的严格 lint、类型、守卫与 Web 构建通过。

## 统一的视觉规则

| 区域或状态                    | 规则                                                                                            |
| ----------------------------- | ----------------------------------------------------------------------------------------------- |
| 画布                          | 一个连续工作区背景；正文通过阅读轴、行距与段落组织                                              |
| 导航                          | 一个连续侧栏表面；分组用间距，保留细分隔与明确的选中/焦点反馈                                   |
| 输入区                        | 一个表单表面；编辑器属于此表面，输入内容和操作栏以间距分开；焦点在父表单可见                    |
| 菜单 / 对话框                 | 需要独立表面与边界，继续使用共享浮层定位、背景模糊与外部点击关闭契约                            |
| contained / outlined / text   | 对应主操作、次操作、轻量导航；视觉由公开 variant 和 tone 决定，不通过宿主选择器伪装按钮样式     |
| 工具 / 思考                   | 单行标签、摘要与状态完整显示；宽度由文字和 padding 决定，外层承接滚动，详情与原文 Copy 保持独立 |
| 进行中                        | 信息蓝＋光强呼吸；状态文字始终可读，动画不改变布局                                              |
| 成功 / 无结果 / 失败          | 成功绿 / 警告黄 / 危险红，文字标签仍明确表达结果                                                |
| 普通 hover / focus / selected | 从当前状态渐变到目标状态；已有状态时长与 easing 统一控制                                        |
