# Lumen 视觉设计评审

目标：轻盈简洁的 AI 开发工作台。低噪声表面、稳定的紧凑动作行、清楚的语义着色、自然的交互过渡。留白主要给阅读与区域分组，工具动作和操作标签保持紧凑单行。

## 参考的具体取舍

下表来自 getdesign.md 的独立设计分析与公开预览，不是品牌官方组件规范。原始文档与来源校验保存在 [项目技能](../.agents/skills/hbar-design-md/SKILL.md)中；示例里的营销内容、专有字体和品牌原色不进入 hbar 业务组件。

| 参考                                              | 观察到的特点                                     | 适用于 Lumen 的部分                                | 本轮不采用的部分                                        |
| ------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------- | ------------------------------------------------------- |
| [Raycast](https://getdesign.md/raycast/design-md) | 有序的暗色表面、细边界、文字层级、命令行与快捷键 | 侧栏分组、轻量搜索入口、明确选中状态和键盘焦点     | 营销页红色斜纹、固定暗色模式、全局发光                  |
| [MiniMax](https://getdesign.md/minimax/design-md) | 中性画布与产品色分工、文档阅读层级、紧凑元信息   | 模型信息与状态的可扫描性，有限范围内使用强调色     | 高饱和大面积产品渐变、80px 宣传标题、为每个模块再加卡片 |
| [Apple](https://getdesign.md/apple/design-md)     | 简洁画布、留白、少量分隔、交互蓝色、内容优先     | 主工作区连续背景、输入区单一表面、清楚焦点         | 商品摄影、广告版面尺寸、缩放按压导致的几何变化          |
| [Cursor](https://getdesign.md/cursor/design-md)   | 编辑式阅读、代码等宽、标签＋动作时间线           | 工具标签和描述的稳定对齐，思考与代码输出的阅读角色 | 橙色替换已有蓝色操作角色、将五种动作色误作五种结果色    |
| [Runway](https://getdesign.md/runwayml/design-md) | 阅读内容留白、细分隔、层级克制、主次动作清楚     | 正文与技术输出的留白、降低重边框与重复阴影         | 视频主视觉、强制黑白状态文本、仅一种按钮尺寸            |

## Lumen 当前设计与实现

仓库中没有独立的 Lumen `DESIGN.md`。现有设计描述分散在 [组件包 README](../hbar-ui/packages/lumen-app-ui/README.md)、[早期 Workbench README](../hbar-ui/docs/src/modules/lumen-workbench/README.md) 和公开样式实现中。本评审整理这些信息，并区分现状、宿主改进和后续组件库工作。

| 维度     | 当前证据                                                                                                                                                                                     | 判断                                                               |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 控件     | `LumenButton` 提供 contained / outlined / text，保留 solid 别名；`LumenNavigationButton` 提供选中语义                                                                                        | 已符合实色、描边、仅文本的要求，应保留 MUI 交互与可访问名称        |
| 表面     | [materials.module.css](../hbar-ui/packages/lumen-app-ui/src/materials.module.css) 提供 glass / frost / solid；[styles.css](../hbar-ui/packages/lumen-app-ui/src/styles.css) 提供明暗语义变量 | 材质和区域职责需要分开。普通阅读区无需为了玻璃效果再嵌套表面       |
| 动效     | [effects.css](../hbar-ui/packages/lumen-app-ui/src/effects.css) 已提供可逆状态过渡、按压过渡和运行呼吸；有 motion off / reduced motion / forced colors 处理                                  | 应消费现有变量，不另造动画时长、不让内容位移或闪烁                 |
| 内容     | 正文、思考、Markdown、工具输出和折叠摘要已使用 [会话阅读角色](../packages/app-react/src/session-message.css)                                                                                 | 本轮保留着色与复制原文，只改善区域层级；颜色不应用作装饰性随机高亮 |
| 外观偏好 | `LumenProvider` 投影宿主的主题、控件尺寸、文字尺寸、圆角、形状、光强和动效                                                                                                                   | 新增宿主字体层级从 `--lumen-font-size` 派生，继续跟随用户设置      |

早期 Workbench README 仍提到单边 light strips；组件包 README 和当前 effects 实现已经采用围绕原本轮廓的发光。判断现状以公开组件包和实际运行结果为准，不把旧文案当作现行视觉约束。

## 本轮需要解决的组合问题

2026-10-06 在 Tauri 开发窗口与浏览器检查到：

1. 工程侧栏把通用侧栏再嵌入两个参考变体表面，产生多层边界和圆角。侧栏应是一个连续导航区域，内部用组间距组织。
2. 默认 `HbarPromptComposer` 把真实受控表单再放入完整 Prompt Input 示例外壳。外层玻璃、表单边界、内部阴影和编辑器边界同时出现，削弱了输入内容的层级。
3. 侧栏品牌标题与新建会话标题比导航和正文更强，重复占据视觉焦点。品牌、区域标题与主内容标题需要少量可随设置缩放的层级。
4. 侧栏底部的功能入口连续横排，长文案和窄侧栏容易拥挤。保持文字单行，按内容宽度自然分行组织按钮，保留通知入口。

实施范围是 hbar 的宿主组合与样式。使用现有 Lumen primitives 和受控数据，不修改各参考变体的独立预览、不改变 Markdown 或工具输出原文，不替换主题色板。

## 统一的视觉规则

| 区域或状态                    | 规则                                                                                        |
| ----------------------------- | ------------------------------------------------------------------------------------------- |
| 画布                          | 一个连续工作区背景；正文通过阅读轴、行距与段落组织                                          |
| 导航                          | 一个连续侧栏表面；分组用间距，保留细分隔与明确的选中/焦点反馈                               |
| 输入区                        | 一个表单表面；编辑器属于此表面，输入内容和操作栏以间距分开；焦点在父表单可见                |
| 菜单 / 对话框                 | 需要独立表面与边界，继续使用共享浮层定位、背景模糊与外部点击关闭契约                        |
| contained / outlined / text   | 对应主操作、次操作、轻量导航；视觉由公开 variant 和 tone 决定，不通过宿主选择器伪装按钮样式 |
| 工具 / 思考                   | 标签单行，行为描述弹性省略；展开后才呈现详情，保持稳定 disclosure 和原文 Copy               |
| 进行中                        | 信息蓝＋光强呼吸；状态文字始终可读，动画不改变布局                                          |
| 成功 / 无结果 / 失败          | 成功绿 / 警告黄 / 危险红，文字标签仍明确表达结果                                            |
| 普通 hover / focus / selected | 从当前状态渐变到目标状态；已有状态时长与 easing 统一控制                                    |

## 后续组件库优化

这些项目是建议，未在本轮宣称已完成：

- 增加公开的区域角色：canvas、navigation、reading、raised、overlay。它们选择中性表面层级；glass / frost / solid 仅选择材质，避免材质枚举同时承担所有层级职责。
- 把目录变体中的局部硬编码色板与字体审计为“参考预览专用”或“生产角色”，让生产组件统一消费外观偏好与语义变量；不能直接批量替换所有 300 个变体。
- 将早期 Workbench 的 light strips 描述更新为当前轮廓发光，集中维护一份组件库级设计规范，并让 README 仅保留入口和接口契约。
- 为区域组合建立固定的明暗、短视口、长文案、文字放大、零发光和 reduced motion 检查矩阵，避免只检查单个控件的静态图片。
