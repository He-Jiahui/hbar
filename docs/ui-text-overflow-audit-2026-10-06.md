### Short copy versus genuinely long content

This split is useful for triage: an ellipsis is expected for a path/objective/snippet, but a short localized action or status should normally remain fully legible.

- **Short copy with early-clipping risk:** search timestamp and role, file saved/dirty status, model/provider trigger labels, pre-session choice/location labels, the prepared-goal action chip, sidebar search, feature-navigation actions, and the session project error. These have small semantic payloads and should be checked first in zh-CN at 320/390px. The feature-navigation, pre-session location, prepared-goal, and project-error fixes now provide title/accessible recovery; geometry still needs runtime evidence.
- **Genuinely long content where bounded display is intentional:** objectives and workflow titles, workspace/session paths, branch/model IDs, search snippets, attachment/image/file names, goal objectives, thinking/tool/command output, and queued-run previews. These should retain an explicit title, aria label, disclosure, or pagination status; the table records the specific mechanism and the cases where it is absent.
- **Known information-loss projections:** diagnostics database keys (first 12 entries) remain bounded to the first 12 and need a product decision about a show-all/details affordance. Git head still renders a 12-character compact value, while the existing full hash is retained in the metric's existing `detail` DOM text for complete read-back.

### Parser, normalization, and non-loss slices

The other app-react slices (including `composer-attachment-input.ts:116` error-code sanitization to 200 characters, message/file reference parsing, markdown/code ranges, `file-preview-reveal`, immutable tab removal, branch `refs/heads/` normalization, slash-editor insertion ranges, roster/session command batching, and syntax-token lookahead) operate on offsets, bounded error metadata, or transport batches. ## Risk priorities and required geometry verification

Static source inspection cannot determine computed widths, font metrics, container-query branches, lazy data, or the final accessible name after the Lumen host renders a slot. The following matrix is the minimum runtime boundary for the next UI/E2E pass:

- Viewports: 320px, 360px, 390px, 768px, 1024px, and 1440px; include both `zh-CN` and English.
- Content cardinality: empty, one item, and seven items for every list/picker in the tables; include >page-size and >preview-limit cases where called out.
- Content shape: long CJK without spaces, long Latin/path/model IDs, emoji/grapheme sequences, a long localized status/error, and a long action label.
- States: disabled, pending/running, failed/error, selected/unselected, no current workspace/session, and narrow sidebar/composer with all neighboring controls present.
- Assertions: no horizontal scroll (`scrollWidth <= clientWidth` for the relevant surface), clipped nodes have an intentional `title` or `aria-label`/disclosure, buttons retain their hit box, and `aria-expanded`/pagination status changes when the full value is requested.

The bounded follow-up implementation mirrors the existing labels into titles for `FeatureNavigation`, the pre-session location trigger, and session project errors. Remaining boundaries are the dirty mention-browser heading, generic host-supplied toolbar slots, diagnostics keys beyond the first 12, and Host-bounded queued-run previews. These are not all defects: collection limits need a product decision, and the client cannot reconstruct content the Host did not send.
