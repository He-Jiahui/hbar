# Sidebar activity runtime

`workspaceActivity` owns the selected sidebar organization, its versioned device preference, and the bounded activity projections consumed by the Shell. Version 2 of `workspaceSidebarOrganization` stores mode, previous grouped mode, sort condition and manual project order in one compare-and-set write. Version 1 and the legacy `workspaceActivitySortBy` value are read without a migration write; after an explicit change, version 2 is authoritative. Switching modes preserves the selected grouped sort condition.

Manual ordering is limited to the loaded sidebar prefix (at most 200 projects plus 20 pin reserves). `workspaceActivity.moveProject` validates the captured visible order and sort, requires the recent-project view, and keeps pinned and ordinary projects in separate sections. Newly loaded, unranked projects keep their Host order after the manually ranked prefix. Selecting either sort condition, including the current condition, or choosing Project/Time clears manual order. Moving a project changes neither navigation nor drafts. Preference write failures retain confirmed state and use the existing local sidebar error/retry entrance.

- `project` queries Host-ordered display aliases using the active locale; `recentProject` uses the selected latest-Session timestamp. Both use the existing Directory Workspace retention seam and leave Session navigation and drafts alone.
- `time` queries the Host's global Session activity feed, including direct Run execution hints. It is always active-first and then `updatedAt` descending, independent of grouped sort and pins. The previous grouped organization is persisted with the mode so toggling Time off restores the last grouped view after restart.
- The same owner accounts for the retained Session pages (up to 900) and Workspace contexts (up to 220, with up to 20 slots kept available for pins). Time rows project canonical Workspace and Session records through Directory's existing activity retention seam; the Workspace activity summary timestamps are null because a global Session page is not a complete per-Workspace activity summary.
- Refreshing Time aims to retain the previous loaded row count, refetching revision-bound cursor pages up to the Session budget. Each validated page becomes the accepted visible prefix as it arrives; if a later read fails, that prefix remains visible and is marked stale/error rather than being treated as current. If the next page would exceed the Workspace context budget, the last accepted prefix remains visible and `timeline.limitReached` stops further paging.
- Host session/workspace/alias/organization/activity hints and visibility changes are coalesced with a 300 ms minimum interval. Only the visible mode is refreshed; a hint received during an active read schedules one follow-up. Time marks accepted rows stale while reconciling and keeps them on read errors.

The Runtime command surface is `workspaceActivity.setOrganization({ organization })`, `workspaceActivity.toggleTime({})`, `workspaceActivity.setLocale({ locale })`, `workspaceActivity.refresh({})`, and `workspaceActivity.loadMore({ scope: 'timeline' })`. Grouped Workspace sorting remains available in Time mode as a persisted preference for the next grouped view, but does not reload or reorder the Time feed.
