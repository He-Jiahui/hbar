# 后台托盘与会话自动化

## 原生后台入口

桌面支持 `--background`：启动 Host 与托盘，不创建工作台 WebView。托盘的“打开客户端”按需创建工作台；后台模式下关闭工作台会销毁窗口和 WebView，托盘与 Host 继续运行。“打开网页”使用系统浏览器打开 Host 地址，不在 URL 中传递凭据。

“设置 → 通用 → 桌面启动方式”保存到全局分层字段 `desktop.startupMode`，取值为 `client` 或 `background`，默认 `client`，在下次桌面启动生效。显式 `--background` 或 `--client` 覆盖本次启动，不改写已保存值；两个冲突参数被拒绝。工作区和会话不能覆盖该全局设置。

已保存后台偏好时，`--client` 可以临时打开窗口；关闭窗口仍会释放 WebView 并回到后台。

原生壳通过受鉴权的只读 `/api/desktop/startup` 取得当前 Settings 投影与类型化托盘文案，没有独立的本地启动偏好存储。Controller 尚在恢复时只对这项读取进行有界重试；无法认证或配置损坏不会被当作默认配置。旧 Host 返回 404 时保留客户端启动兼容行为。

同一数据根已有健康 Host 时复用实例。普通“退出客户端”保留 Host；“停止后台并退出”重新读取连接并核对健康实例，再终止其 Supervisor 进程树，不能把陈旧 Host PID 当作当前所有者。停止失败时保留托盘。后台窗口关闭不会弹出原有的退出服务确认框。

## 网页监听设置

“设置 → 通用”提供全局字段 `backend.webAccess`（`local`／`lan`，默认 `local`）与 `backend.webPort`（1–65535，默认 4317），均在重启后台后生效。局域网模式绑定 `0.0.0.0`，继续使用现有设备配对、角色与工作区权限。保存草稿不会改变当前连接；页面分别显示当前 Host 实际提供的地址和待重启应用的设置。

Host 在绑定端口前，通过存储包的有界只读 Worker 读取已提交的全局设置，再通过 kernel 的公开设置投影解析监听策略。读取不打开写者、不迁移 schema、不执行 checkpoint，也不依赖执行模块就绪。空数据根和旧 schema 沿用默认值；损坏、过大或不兼容的设置明确失败，避免静默使用另一组监听参数。读取支持取消、超时并等待 Worker 退出。

显式 Host `--host`／`--port` 覆盖本次启动。原生桌面采用已保存的监听设置；测试或显式环境配置可以使用 `HBAR_PORT` 覆盖，`0` 表示操作系统分配临时端口。冲突记录 `EADDRINUSE`，不会悄悄改用随机端口。原生启动超时只释放本次启动且尚未就绪的 Supervisor，保留已复用的 Host 和占用端口的其他服务。

- `tests/startup-settings.test.ts` 验证首次读取、WAL 中的提交、数据库与 WAL 字节不变、旧版本无迁移、损坏与过大配置、取消及超时。
- `tests/backend-web-listener.test.ts` 验证持久端口、范围校验、真实局域网鉴权与配对、端口冲突和原服务存活。设置 `HBAR_TEST_HOST_EXECUTABLE` 可针对已编译的独立 CLI 重跑同一流程。
- `bun scripts/verify-background-port-conflict.ts` 使用原生桌面、隔离数据根和受控占用端口，验证启动诊断、未就绪 Supervisor 释放和原监听服务保留。
- 扩展的中英文设置 E2E 同时保存后台启动方式、网页访问范围和端口，验证刷新恢复以及实际地址不会被待重启的设置替换。

## 独立服务入口

`hbar serve` 在同一数据根没有可连接 Host 时启动受管 Supervisor，终端保持运行并显示实际地址与有效五分钟的配对码。它沿用网页监听设置，支持显式 `--home`、数据／缓存路径、绑定地址、端口、TLS、profile 和本地执行限制。服务入口保存供原生客户端和 CLI 复用的本地连接记录，但不增加桌面开发服务器的 Origin 例外。

已有 Host 时，入口通过健康检查及 WebSocket 握手核对实例身份和认证，再显示该实例的实际地址并生成一次配对码；不会创建 workspace 或 session，也不停止原服务。传入的启动覆盖项只在下次真正启动服务时生效。身份不匹配、鉴权失败及畸形响应明确失败，不据此启动第二个 Host。Supervisor 或直接 Host 仍持有存活租约时，有界等待其恢复；真正的进程租约继续处理并发启动竞争。

新建服务由当前终端持有；终端的退出信号只停止本次创建的 Supervisor，Windows 使用整棵受管进程树停止。连接已有服务的入口展示信息后正常退出，原有所有者继续运行。配对生成是一次明确操作，未知写入结果不会自动重试。

`tests/cli-backend-service.test.ts` 通过真实 CLI 服务验证新建、复用、地址与身份不变、设备配对、session 不变、非法启动参数和错误实例拒绝。设置 `HBAR_TEST_CLI_EXECUTABLE` 可对编译后的独立程序运行同一用例。`--unattended` 将在自动推进服务接入时提供，目前不接受该参数。

## 托盘地址与配对

托盘增加“复制网页地址”、“配对可操作设备”和“配对只读设备”。复制操作写入当前连接的无令牌地址。配对操作通过受鉴权的 `/api/desktop/pairing` 调用原有 `pairing.create` 用例，只接受显式角色，不能传入 actor 或额外权限；原生弹窗显示该角色、实际网页地址、配对码和到期时间。配对码有效五分钟，成功使用或生成新码后失效。

菜单及弹窗文案由 Host 的类型化中英文契约提供。新动作通过独立 `/api/desktop/tray` 协商，保留既有启动 DTO；旧 Host 返回 404 时省略新增菜单项。地址列表最多展示 16 个不同地址，空列表有明确提示。两个端点沿用每请求设备鉴权、全局操作员权限与 Origin 校验，并返回 `no-store`。

原生壳使用 Tauri 剪贴板和系统弹窗适配，不为这些操作创建 WebView，也不向网页授予新的插件权限。网络配对在有界后台任务中处理，超时五秒、响应最多 32 KiB、拒绝重定向。一次点击只提交一次；超时等未知结果提示用户核对连接并显式重新配对。请求及弹窗共用一个在途额度，退出后忽略迟到显示，不终止 Host 中其他任务。

本项通过 11 项相关 Bun 集成测试、24 项原生单元测试、全仓类型检查、变更范围严格 lint、Host／原生构建及真实无 WebView 托盘 smoke。覆盖角色、配对消费、设备撤销、越权、Origin、内容容量、旧 Host、重定向和大响应；原生 smoke 继续验证 Host 复用与关闭窗口后 Run 完成。托盘菜单的实际点击、剪贴板读回和弹窗视觉仍需桌面交互检查；当前自动化结果不包含这些断言。

## Command 公共路由基础

`@hbar/commands` 提供 `CommandRoutingPort` 与 `createCommandRouter`，统一目录、描述和执行入口。稳定 Host 通过 `host.commands` 暴露受信任的进程内端口，网络 RPC 使用同一对象；受管 Controller 也使用相同路由实现。鉴权边界提供 actor，调用载荷不能夹带 actor；执行仍由原命令所有者进行参数、版本、并发、超时与回执处理。

目录按一致的字符顺序排序和推进游标，修复此前本地化排序与字符比较混用导致的大小写边界漏项。候选命令按 ID 去重，描述来自当前路由所有者，隐藏指令不出现在公开目录。单页最多 200 项与 512 KiB，来源最多 128 个、原始目录项最多 10,000 个；大描述会提前结束当前页并返回有效游标，非法或过大描述明确失败。

真实 Host 测试验证跨页目录一致、单项描述、Host 自身指令在 Controller 目录不可用时继续响应，以及进程内执行与 RPC 使用同一持久回执。路由单元覆盖大小写、隐藏指令、重复来源、权限身份、版本／参数错误、UTF-8 字节容量及非法目录边界。这项基础抽取没有向模型暴露绕过权限的入口；session 工具、动态准入及受管 IPC 注入仍在后续实现范围内。

## Command 只读预校验

`CommandRoutingPort.prepare` 返回当前所属模块的命令描述与规范化调用。Host 自身的命令在稳定进程校验；Controller 命令通过受管进程的专用私有入口使用原始 Zod 契约校验，保留默认值、额外字段拒绝和无法由 JSON Schema 表达的 refinement。`CommandRegistry.prepare` 和 `prepareCommandInvocation` 提供相同的纯校验入口。该阶段不调用业务 handler、不占用执行额度、不创建回执，也没有新增网络 RPC。

请求 ID、命令 ID、版本和幂等键不能被校验模块改写；参数与描述先复制，输入和规范化结果都受 256 KiB 限制。旧模块没有只读校验能力时明确返回不可用，不能用执行命令代替校验。受管 Controller 的契约指纹同步更新，避免把这个私有入口发给不支持的旧模块。

新增测试覆盖默认值与 refinement、版本与身份、UTF-8 容量、默认值扩张、可变入参和缺失能力。真实受管 Host 验证预算预校验没有回执、随后执行产生原有回执；文件预校验没有写入、随后经原执行模块创建文件；目录与稳定 Host 指令也能校验。session 命令工具及其运行身份绑定继续在后续范围内。

## 最终工具参数准入

工具参数先经过 `tool.before` 转换和所属工具的再次校验，再进入只读的 `tool.admitting` 阶段；Workflow 范围、Agent 配置和 Plan 只读约束在这一阶段检查实际将执行的参数。拒绝发生在策略、审批和持久执行意图之前。该 Hook 收到参数副本，返回值不改写执行参数；Host 在 Hook 后恢复会话、Run、workspace 与调用标识。受管插件进程同步支持该阶段及异常传播。

新增集成用例验证后置转换不能把已许可路径改为范围外路径、合法的最终路径修正能够执行，以及观察者不能更改执行参数或 Host 身份。相关权限、取消、审批竞争、隔离执行和插件进程回归通过。两个既有 Workflow 测试文件有 10 项焦点构造用例失败；独立工作树在修改前的 `2e3e2be4` 上复现完全相同的 `WORKFLOW_REVISION_CONFLICT`，这些失败尚未进入工具准入阶段。

Host 组合根还可以注入 `ToolCallPreparationPort`：在最终参数校验后，为单次调用绑定实际副作用、路径范围、进程命令、审批要求、超时和执行器。准备阶段只读并遵守取消；执行器随后经过同一条准入链。调用描述与参数在边界校验、复制，执行描述被冻结，不修改注册工具或其他调用。原工具声明的专门人工审批不能被绑定省略。

`tests/tool-call-binding.test.ts` 验证通用读取入口解析为写入后仍受写入审批、deny、Plan 和 Workflow 约束；后置参数变化不会越过沙箱；准备期间取消不产生执行意图；写入超时保持未知副作用，读取超时则是已知失败。真实插件 owner 传输测试验证本次调用的进程副作用和命令字段能够传给最终准入 Hook。该端口为 session 命令工具提供基础，尚未单独向模型增加工具或赋予命令权限。

## 受管文件命令的空基线

受管执行 owner 的文件读取、目录读取与路径规范化保留 `ENOENT` 分类，同时用固定消息代替原始系统错误中的路径。文件写入用例因此能识别“不存在”的基线并创建新文件；其他未知插件异常继续走原有错误处理。真实 owner 的错误传输用例验证分类与路径隐藏，`tests/managed-file-commands.test.ts` 通过真实 Host、Controller、执行插件与配对设备验证嵌套新文件创建、读取及重复相同内容时的收敛行为。

## Session 的 Command 发现工具

受管 Host 为每个 session 注册 `hbar_commands_list` 和 `hbar_command_describe`。目录包括与 CLI 共用的 Host、client、platform 定义；命令参数与输出的 JSON Schema、默认值、版本和执行域来自当前命令所有者。两个工具沿用普通工具的最终参数、Run、Plan、权限及取消链，只进行读取，不执行命令。

私有 IPC 的 session、Run 与 call ID 由工具网关提供，模型输入不接受 actor 或来源身份。稳定 Host 在读取前后核对 Run claim 与 Kernel owner。监听器尚未提供命令路由时最多保留 32 个等待请求，默认十秒超时，取消和关闭均释放请求；旧监听器的 disposer 不会移除替换后的路由。

各域使用相同字符顺序合并，Host 响应因字节容量提前结束时，本地定义不能跳过尚未读取的 Host ID。模型目录每次最多 50 项、32 KiB，继续读取使用最后一项 ID；完整 IPC 页最多 200 项、512 KiB。单项描述最多 128,000 UTF-8 字节，超过容量或 ID 不匹配明确失败，不返回截断 JSON。CLI 同步使用共用目录，隐藏内部项并修正大小写游标顺序。

真实受管集成通过两个独立 session 验证全目录翻页和读取定义，涵盖三个执行域；Plan 与 deny 下读取成功，无审批、无客户端，也没有给普通 Run 创建 Goal。边界用例验证来源参数伪造、输入容量、UTF-8 描述容量、错误 ID、分页、启动等待、取消、关闭及路由替换。`hbar_command_execute` 和带来源身份的执行上下文仍在后续实现范围内。

## 持久的命令授权来源

session 创建、Run 接受及恢复的规范日志可以保存 `ExecutionPrincipal`，包括来源设备、来源 session 与来源 Run。该记录只标识来源，不保存设备令牌或冻结设备权限。带身份的命令提交绑定自己的 actor；自动恢复复制被恢复 Run 的来源，手动重试绑定本次操作设备。重放同一请求不能换成另一位提交者。Run 的来源一经接受，后续任务提交不会改写它。

运行中的父 session 创建子 session 时，Kernel 显式提供实际父 Run；即使另一设备已在父 session 中排队新任务，子 session 仍继承正在执行的 Run。内部续跑也可以显式指定同 session 或父 session 的来源 Run；存储在同一事务内检查关系并保存结果，外部 session 的来源会被拒绝。新增自动调度必须传递原始任务的来源，既有 Goal 的恢复不能仅凭 session 中最新接受的任务推断授权。

`sessionExecutionPrincipal` 与 `runExecutionPrincipal` 使用既有事件索引读取，session 默认来源最多比较三个候选记录。旧日志中有规范 Run 命令回执时可恢复该来源；没有证明的历史保持未绑定。旧恢复链只允许同 session 的有限前驱，循环或超过 32 个前驱明确拒绝。新增字段与日志在同一事务提交，规范 JSONL 重建后仍可读取来源，不新增另一套权限数据库。

Host 的 `SessionCommandAuthorization` 为执行网关提供重新鉴权：读取规范 Run、来源设备的当前配对记录、角色和 workspace 范围，复用现有命令目标鉴权。设备撤销、降为只读、移出允许 workspace、来源不匹配或缺少来源均明确拒绝；调用参数不能传入 actor。该服务将在 `hbar_command_execute` 的准备与执行阶段接入，目前不代表命令执行工具已经开放。

存储、Kernel 父子任务和权限用例覆盖不同提交者、排队竞争、自动／手动恢复、规范日志重建、旧记录、循环、设备撤销与角色／范围变化。真实受管 Host 用两个配对操作设备分别创建 session 和通过命令模式提交 Run，验证三域目录读取与每个 Run 的来源一致，无审批、无 UI、无新增 Goal。

## 命令所属模块的最终执行校验

`@hbar/commands` 的 `createCommandExpectation` 保存已准入的命令定义与规范化输入；`CommandRegistry.dispatchPrepared` 在当前定义、首次参数解析以及真正进入 handler 前的最终解析处核对。调用者在异步鉴权期间更改原始对象、命令模块被替换，或者所属模块的最终 validator 改写路径，都不能改变已准入的副作用或参数。比较使用有界、键顺序无关的纯 JSON 描述，不依赖浏览器或 Node 专有加密接口。

`PreparedCommandRoutingPort.executePrepared` 与类型化命令 owner 适配器只调用明确支持最终校验的模块；旧适配器或会丢弃校验信息的传输明确返回不可用。来源 actor、校验描述和取消信号独立于模型调用载荷。该入口继续使用原模块的能力鉴权、版本、幂等要求、容量、超时和取消处理。异步鉴权未实际结束时，逻辑取消不会提前释放 Registry 容量。

描述最多 512 KiB，输入最多 256 KiB，结构最多 64 层与 65,536 个节点，循环、非 JSON 值和容量越界明确失败。测试覆盖默认值、身份、键顺序、定义替换、最终参数变化、可变调用对象、旧模块拒绝、取消传递及容量保留。稳定 Host／受管 Controller 的执行接线、物理结算跟踪和模型执行工具仍在后续范围内，不能以这个 SDK 入口替代这些工作。

## 命令的实际完成记录

`CommandRegistry.dispatchPreparedTracked` 提供所属模块内的执行票据，分别记录遵守超时／取消的请求结果，以及底层工作实际结束后的结果。写入请求超时后继续保留原执行容量；原 handler 最终成功时保留真实输出，最终失败时保留错误码及是否已进入 handler。等待异步能力鉴权的取消也必须等该鉴权结束，不能把“尚未进入 handler”误当作“已经完全结束”。

校验、来源、容量或执行前取消被拒绝时，票据记录未进入 handler；最终输出校验失败则保留已经执行的事实。类型化适配器要求所属模块明确支持跟踪，不能从普通请求的逻辑完成推断底层结算。票据中的 Promise 仅限模块本地使用，受管进程需要通过具名数据回执发布结算；持久回执、跨进程接线和超时后的状态核对仍属于后续工作。

定向测试覆盖无视取消的写入、超时后成功／失败、执行前拒绝、取消期间的异步准入、最终参数变化和无效输出，验证底层操作只执行一次，且实际结束前不释放容量。

## Host 与受管命令的最终校验接线

稳定 Host 的 `executePrepared` 现在把已准入定义和规范化参数传到实际所属模块。Controller 内的命令工厂显式提供受保护入口；目录查询继续把校验信息传给 Kernel 所有者，数据库维护则由 Maintenance 所有者再次核对。原生／网络调用保持原有入口，模型调用仍需后续来源网关和准入链接入。受管契约指纹包含新增校验数据，避免旧进程丢弃它们。

远端节点的 `workspace.create` 原有 Host 特殊路径也通过独立 Registry 校验。创建时绑定已准入的 node 和 root，最终定义、输入变化或执行前取消都会在发现节点前拒绝。取消信号经私有应用调用传递；所属模块继续负责原有版本、容量、持久执行要求及输出校验。模块内跟踪票据已可由命令工厂显式调用，跨进程结算回执仍待接入。

真实受管 Host 验证直接调用 Controller 入口也不能修改已准入定义或预算输入，拒绝后没有预算回执。合法调用产生原持久回执，相同调用可读取同一结果；文件创建、Kernel 目录查询、稳定 Host 路径读取和 Maintenance 统计均通过受保护入口完成。远端创建另有定向测试验证拒绝前不调用节点发现，以及合法操作只执行一次。

## 所属模块的有界命令回执

`@hbar/commands/jobs` 提供模块内的 `CommandExecutionJobs`，把原执行票据投影为具名状态及分块结果。请求超时与底层结算分别记录；只有两者都已记录且底层实际结束后，调用方才能确认释放。重复启动同一 job 明确拒绝并要求读取原回执，取消不会伪造操作已停止。回执读取、等待、取消和确认均校验原 actor。

默认最多保留 128 个 job、64 个等待者，每个 job 最多两个等待者；长轮询最多 25 秒。单份结果最多 32 MiB，总结果缓存最多 96 MiB，每次读取最多 65,536 个 UTF-16 code unit，并同时声明 UTF-8 字节容量。块可以在代理对中间分开，拼接后仍得到完整 JSON。确认后释放对应容量；取消、超时和关闭都会清理等待资源。

超大或非 JSON 结果显式标记无法保留，并继续保留底层成功／失败与是否已执行的事实；不会把结果读取失败伪装成操作未发生。丢失结算或损坏的票据工厂保持“未确认”，不能确认释放或据此重放写入。这是跨进程回执端点的模块内基础，尚未接入 Controller／Kernel／Maintenance 的具名端点和 Host 持久记录。

测试覆盖真实写入超时后的晚到回执、保留容量、重复启动拒绝、actor 隔离、Unicode 分块、总缓存与单结果容量、等待取消、关闭及未知结算。调用方仍需在保存结果后发出确认；模块内缓存不替代 StoragePort 的持久回执。

## 受管 Controller 的命令回执传输

Host 的 `executePreparedTracked` 现在可以向受管 Controller 接受一次命令，随后沿同一 owner 查询请求结果、底层结算和结果分块。启动、状态、读取、取消与确认采用具名私有 DTO，Promise 不上网。原 actor、请求 ID、命令版本、幂等键及准入定义保持绑定；不支持跟踪的模块明确返回不可用，不回退到普通逻辑派发。

请求取消通过独立控制入口传递，后台继续核对实际结束。长轮询使用普通 IPC 容量，取消与确认保留控制容量。跟踪最长 1,325 秒；超时、owner 丢失或损坏回执转为未知结果，不重放原操作，也不伪造停止。JSON 块必须保持声明的大小、游标及完整字节容量，结算内容还需与 owner 状态头一致；无法通过校验的回执不能确认释放。

每次受管命令保留 Coordinator resource 和已认证应用作用域。逻辑失败或取消后关闭新的 Host 应用调用，已经开始的工作继续由原 owner 结算。调用方保存结果后显式 `acknowledge` 才释放记录和 resource；底层结束前拒绝确认。版本切换时，旧 Controller 因未确认回执继续保留，新的调用路由到新默认版本。精确 owner 退出仍由现有受管进程树生命周期确认。

真实受管测试注入延迟写入，验证请求超时、并发拒绝、旧请求能力关闭、版本切换、晚到 Unicode 结果、确认前旧进程保留，以及写入只执行一次。传输测试覆盖来源取消、控制容量、跟踪截止、owner 生命周期、损坏游标与字节容量、明确不可读取的结果，以及确认的幂等处理。

本项尚未把回执保存到 Host 的 StoragePort，也没有开放模型执行工具。client/platform 的跟踪端点仍需接入；这些边界不能用 Controller 中的逻辑结果冒充实际结算。

## Kernel 目录查询的回执

稳定 Host 将带跟踪的目录查询直接送到选定的 Kernel owner。私有启动入口只接受目录契约中明确为只读的 query；实际 Registry 再次核对命令定义、规范化输入和 actor，输出通过原契约验证。回执沿接受请求的进程读取，取消、结果分块和确认复用相同有界协议，Host 关闭时终止跟踪。

每次查询保留精确 Kernel generation 的 Coordinator resource；查询实际结束后继续保留回执，直到调用方确认。受管集成验证所属模块拒绝过期定义、合法查询真实结算、旧 Kernel 在换代后保持到确认、新默认版本接续查询，以及整个过程客户端仍连接。该模块内回执仍需由后续来源网关保存到 Host 存储，才能满足重启后的持久核对要求。

## Maintenance 的命令回执

Maintenance 也提供同协议的私有命令启动与回执端点。Relay 按原作业归属选择进程，独立保留命令回执资源；请求确认只释放该回执，清理作业与数据库 writer 继续由原有持久作业、物理租约及交接流程管理。Host 关闭时终止回执跟踪。契约指纹涵盖新的启动和分块回执 DTO。

真实 Maintenance 查询验证定义过期拒绝、实际结算、确认前保留旧版本与新版本继续查询。原有受管回归验证长作业跨版本归属、候选 Worker 故障、进程丢失后的 VACUUM 核对，以及取消与 Storage writer 交接；命令回执没有替代这些作业完成证据。

## Host 命令回执的存储契约

StoragePort 提供命令意图的原子接受、读取与带 revision 的推进。意图绑定来源 session／Run／call、规范来源 actor、命令定义、最终参数、原幂等键及可选客户端 generation。相同操作键读取原记录；定义、参数或目标变化会冲突，重复提交不能改写原请求身份。新意图要求已认证的活动 Run，用户已停止的 Run 不再接受新意图。

所属执行器、请求结果与实际结算分别保存。执行器和已保存结果不可更换；未知结果可以由原执行器的晚到结算消解。两份结果和执行器都保存后才允许记录确认。并发推进使用 revision，重复相同事实保持幂等；存储入口本身不执行命令，也不允许凭未知记录再次启动副作用。

记录复用已同步落盘的规范 Run 日志，使用已有 `(sessionId,type,seq)` 索引直接读取最新记录，无新增数据库表。单记录上限 1.5 MiB，意图预留结果容量；结果 JSON 每份最多 64 KiB 内联，更大的结果使用最多四个内容寻址附件块与总 hash，最多 32 MiB。附件元数据需先提交，事件引用沿用现有回收保护。格式错误、超深结构、非有限数字、未知附件及容量越界均拒绝。

测试验证并发重复、来源伪造、停止后的拒绝、参数变化、过期 revision、不可变结果、晚到结算、未知与完整回执的日志重建、有效查询索引及 SQLite 完整性。Host 执行网关和附件内容校验仍需接入；此存储契约不代表模型执行或重启核对已经完成。

## 跨所属模块的源 Run 资源

Coordinator 的 `retainSourceResource` 允许稳定 Host 把一个已认证的源 Run 与命令执行器关联。它验证源租约与执行器状态，拒绝逻辑上已结束的 Run，并继续禁止执行器借用源 Run 的存储或工具能力。该资源属于实际命令执行器，计入源 Run 的物理引用，因此逻辑完成不会提前释放 session claim；原有保留 session 原生资源的入口不承担这个职责。

命令执行器故障时，动态资源依赖也参与源 Run 撤权。持久撤权使用源租约已经绑定的 authority，另存实际故障所属进程，因而不会绕过 Storage 的 owner 校验。按所属模块分组，每次最多撤权 256 个 Run。Host 的故障处理同时保留原有未完成 claim 及新增动态依赖，物理退出和明确核对仍是恢复条件。

定向测试验证源 Run 保留、未扩大执行器权限、迟到新执行拒绝、伪造租约及候选／撤销进程拒绝、故障后的实际退出与恢复，以及 Storage 对撤权 authority 和故障来源的区分。下述生产命令入口已经使用这个组合入口，当前开放范围为四个目录查询。

## 命令启动前的持久绑定

Host 组合根的 `HostCommandExecutionScopes` 为一次已认证 Run 的调用捕获源租约及持久化启动钩子。Controller、Kernel 目录与 Maintenance 的带跟踪入口使用它保留源 Run 资源，并在发出启动请求前等待所属进程及 job ID 保存。上下文按异步调用隔离，所属执行器描述经过校验、复制并冻结，普通客户端调用继续使用原有资源归属。

持久化阶段收到取消时不再发出命令；该阶段自身的已接受存储工作仍需完成。启动前失败的票据保留已证实的 `executionStarted: false`，可以确认释放本地资源，无需向未接受 job 的进程发送确认。发出启动请求后丢失响应则保持未知并保留原回执，不能使用这个路径推断未执行。

真实受管测试使用源 Run 的实际租约，逐一验证三个所属模块等待持久绑定，再保存请求结果和实际结算，最后确认；在最后一份回执确认前，已结束 Run 的 claim 仍保留。传输与并发上下文用例验证持久化失败、期间取消、启动响应丢失、身份复制及隔离。稳定 Host 本地命令、统一持久执行服务、源 Kernel 能力回调与模型工具仍需继续接入。

## 稳定 Host 本地命令的回执

稳定 Host 的 system、metrics、node、远端 workspace 创建及嵌入运行时的本地命令也通过相同的有界 job 协议跟踪。目录及受管应用命令继续使用实际所属进程，避免把 Controller 的工作错误绑定为 Host 本地工作。Host 本地回执限定实例和 actor，读取原 job 不会再执行命令；源调用的持久绑定钩子完成前不会启动实际 Registry。

本地容量包含正在等待持久绑定的调用，最多 128 个。超时后晚到结果按原 job 保存，只有实际结算与请求结果都已读取后才能确认并释放。关闭只请求取消并清理等待者，不把无法中止的处理器伪装成已结束。测试验证晚到 Unicode 结果、同 job 跟踪、实例及 actor 隔离、准备阶段容量、持久化失败与取消，以及真实 Host 路径查询的确认释放。

稳定 Host 的源工作使用 Coordinator 独立的 Host 实例资源，计入全局资源容量和源 Run 的物理引用，不绑定可重载 Kernel 的版本。Kernel 实际退出也不会释放它；正常交接和故障恢复均等待真实结算及确认。未确认的源工作存在时，普通 Server／Runtime 关闭返回 `HOST_COMMANDS_ACTIVE`，调用方可以完成核对后重试关闭；这不代表无法中止的处理器已停止。Host 专用资源接口不暴露给子进程协调 RPC。

生产组合提供真实 Host 实例及 retainer；自定义适配器缺少它时仍明确拒绝源执行。真实集成在 Controller、Kernel、Maintenance 和稳定 Host 四种路径验证持久绑定及源 claim 保留，并验证未确认时拒绝关闭。下述目录查询工具已接入统一持久执行服务，其余命令仍须按具体权限和能力接入。

回执的公开有界编码器遵循普通 JSON 传输对对象中可选 `undefined` 字段的省略行为。真实未设置的设置项会产生这类字段，修复后可完整保留其正常传输结果。数组中的 `undefined`、稀疏数组、函数、symbol、getter、循环及非有限数仍明确拒绝；不会用 JSON 的静默转换把非法数组值变成 `null`。

## 会话命令的持久执行服务

稳定 Host 现在组合 `SessionCommandExecution`，以实际源租约及规范化命令为输入，从 Run 的原始接纳记录读取 actor，每次执行及结果读取重新核对配对设备、角色和目标范围。网络和模型不能提供 actor。服务先保存接纳记录，再通过实际执行器的启动钩子保存所属实例及 job ID，随后才能开始命令。执行中的相同操作合并等待；已有持久回执不再次启动，失去原跟踪时明确保留待核对状态。

请求结果和实际结算分别保存，两者都持久化后才向原执行器确认，再记录确认完成。暂时的结果发布失败可核对原票据并重试保存；确认失败只重试确认。跟踪到期后可重新读取原实例、原 job，不重新执行命令或重跑启动钩子。保存失败、未知结算及未确认的执行仍占用有界入口；服务最多保留 64 项，未结算时普通关闭会返回 `HOST_COMMANDS_ACTIVE`。revision 竞争只进行有界重新读取，不覆盖不同所属实例或不可变结果。

完整 JSON 在 64 KiB 内保存正文，较大结果通过普通 Kernel upload 及附件引用账本保存为最多四个 10 MiB 块，总量最多 32 MiB。上传占位按源操作和结果通道独立命名，回执事件提交后才释放，由持久事件引用接管保留，不释放用户聊天草稿中相同内容的上传引用。读取检查已保存元数据、块哈希、总大小和整体哈希，并拒绝重定向、损坏、不完整 UTF-8、非法 JSON 及超出结构上限的数据。发布及读取最多两个并发、128 个等待者，等待最长 30 秒。显式无法保存的结果仍保留真实成功／失败及是否已经开始，顶层 `undefined` 也按无法表示的结果处理，不伪造未执行。

workspace 受限的来源在保存目录结果前使用与网页入口相同的范围投影。已保存目录回执再次读取时也检查当前设备的范围；超出当前范围的旧正文只返回不可读取的说明，原始审计记录保持不变。实际源 Run 取消后仍核对已开始工作的结算，拒绝已停止 Run 的新命令。

定向用例覆盖去重、晚到结算、同 job 继续跟踪、确认失败、结果发布失败、服务替换后的拒绝重放、撤销及收窄设备权限、源取消、大块哈希校验和有界发布队列。真实受管 Host 在 Controller、Kernel、Maintenance 及稳定 Host 四条路径完成接纳至持久确认，并使用正常附件上传读回约 11 MB 的 Unicode 结果；账本核对确认事件接管保留，用户草稿的独立上传引用继续存在。一次 Windows／Bun 1.4.0 运行在写入、读回及引用清理期间，以 5 ms 定时器得到 26 个事件循环间隔样本，p95 31.8 ms、max 56.1 ms；这是本机一次代理采样，不是 RPC 延迟或跨环境保证。

该服务由可信 Host 组合入口持有，下述 `hbar_command_execute` 已通过最终工具准入开放目录查询。跨恢复链的未知写入检查见后文；其他具体命令、源文件能力回调、client/platform 路由和完整自动调度仍需实施，不能直接将普通 Controller 权限路径当作模型工具入口。

## 源 Kernel 的命令能力路由

Host 的可信调用上下文可以绑定源 Kernel 的具名应用端口，身份同时核对 Kernel owner 与工具 call ID。文件执行、workspace 搜索和 Git 的 facade 调用使用这个来源端口，继承其取消信号与有界期限；来源调用缺少端口时返回明确错误。未声明方法、不同 owner／call 与非法期限在调用前拒绝。普通客户端入口继续按既有所属模块解析。

隔离 IPC 测试通过真正的临时文件写入和读取，验证捕获的来源上下文跨通信保留、缺少来源端口时文件不变，以及整个来源调用没有解析操作员 Kernel。生产目录查询不调用文件端口；文件命令仍需在完成正常工具准入后创建作用域端口，并等待已经开始的实际调用结束后释放。

命令作用域中的其他 Kernel API 也以完整 owner 身份及有效源租约固定默认 Kernel，包含已经进入 draining 的原代际。指向另一个活动 session 的调用继续按目标的实际租约路由；目标没有活动租约时保留捕获的上下文。源 Kernel 缺失、退出或被撤销时明确失败，不改用操作员默认代际。

这些源调用继承已准入的取消信号和期限，并等待原 IPC 处理器的实际回复。Kernel 应用端口中已经接纳的异步回调也等待原调用结束；逻辑取消仍及时响应，不把尚在执行的回调当作完成。Kernel runtime fingerprint 包含该回调语义。隔离 IPC 与真实受管 Kernel 测试分别覆盖代际路由、明确活动目标、丢失／撤销、处理器取消及嵌套回调取消。生产目录查询使用下述具名准备入口。

本项通过 105 项相关测试、严格变更范围 lint、全仓类型检查及 Web／Host 构建。受管进程回归使用 `bun test --timeout 120000`；初次运行的一个既有双代际用例触发默认 5 秒限制，较长时限重跑通过，实际约 7.7 秒，初次失败没有计作通过。

## 应用调用的实际回复跟踪

`IpcPeer.callTracked` 与 `RuntimeValuePort.callTracked` 为同一次所属进程调用分别提供请求结果和原实际回复。取消及期限仍及时结束请求等待，已经发送的调用继续占用原有物理容量，直到原回复或连接丢失。排队中取消证明没有派发；连接丢失则显式拒绝实际回复等待，不能把它当作成功或已核对结果。普通 `call` 保持原有等待行为。

实际回复只做一次输出校验与应用值解码。逻辑结果结束后关闭新的具名回调入口，已经进入的回调保留自己的操作。测试覆盖迟到成功／失败、排队取消、断连、输入与输出校验、容量、Unicode 文件写入及回调关闭。此项提供后续源能力及插件链路保留真实结算的传输入口；它本身没有把所有应用调用自动改为等待实际结算。

## 受管插件的结算传递

Kernel 的插件适配器及稳定 Host 的插件 Relay 现使用原调用的实际回复作为内部结算。工具网关仍按自己的信号及时返回取消或超时，已经进入插件的工作继续由原进程回复或确认退出。插件与 Kernel 契约指纹包含这个结算语义，普通应用调用没有整体更改等待规则。

具名应用端口可由可信所属模块选择实际回调结算。已经开始的嵌套回调等待原回复，取消立即关闭新回调入口及其嵌套引用；来源异步上下文继续保留。真实 Bun 插件测试验证取消后的源 Run claim 仍保留、原插件晚到写入一次、同调用返回实际结果后才释放 claim。受管 Host 回归覆盖本地／Plan 工具、Goal 插件换代和插件崩溃后唯一安全接续，嵌套文件回调及既有超时、恢复测试同时通过。

## 每次准入调用的源能力端口

`RuntimeCommandSources` 提供 Kernel 组合端的具名源端口。打开时要求匹配的已准入 session、Run 与 call 身份，捕获当时的执行上下文，只注册本次声明的方法。文件、搜索和 Git 的首个工作区参数限定为原执行工作区；省略时使用该工作区。Host 连接端同时核对实际 Kernel peer、来源租约和 call 身份，并等待每个原处理器的实际回复。

每个 Kernel 最多 64 个源端口；每次调用最多 16 个同时进行的能力操作、总计 128 个操作。取消后拒绝新调用，关闭等待已接受的操作，完成后释放注册与引用。进程调用使用已捕获的环境、OS 隔离、准入身份及期限，不能用调用参数覆盖；期限允许收紧。现有原生 Git 后端暂不能执行这套额外隔离要求，遇到要求时明确拒绝启动，仍需后续适配。

测试把端口工厂注入真实 Kernel 工具执行器，验证普通准入后才打开、策略拒绝不创建端口、跨隔离 IPC 保留工作区 authority 与实际文件读写。另验证取消后的原写入及两侧关闭等待、方法和工作区拒绝、身份栅栏、所有容量边界，以及进程约束不可由参数提升。生产文件命令仍需注入这个工厂；当前模型目录查询不使用文件能力。

## 命令未确认结果的写入阻断

StoragePort 的 `commandExecutionPending` 读取同一 session 中每个操作的最新规范回执，仅返回最多 64 项身份、命令、revision 与原因，另以 `hasMore` 表示还有待核对项，不加载命令参数或结果正文到 Host。查询复用已有 session／type／seq 索引，不新增表；只读命令和已经确认的成功结果不计入。已开始的命令若以已知传输／所属进程丢失错误结束，或失败正文不可读取，仍保留待核对状态；明确未启动的失败不会阻断。

持久命令执行服务在接纳新变更前、以及实际执行器启动前都检查该状态。更换操作键、服务实例或后续 Run 不会绕过同一 session 的未确认写入。当前 Run 内仍在正常等待且尚无逻辑结果的本地已知调用可以并发；逻辑等待已经结束、实际结果仍未确认时则暂停新变更。原回执和只读检查继续可用，原晚到结算确认后允许继续。此处采用同 session 的保守范围，覆盖其后续恢复链。

测试验证规范日志重建、最新回执筛选、容量与大参数隔离、嵌套传输失败、进程启动前再次检查、确认未执行的回执、正常并发及只读核对。一次 Windows／Bun 1.4.0 运行在 65 条未确认记录及 200 条无关事件下采样 16 次 StoragePort 读取，p95／max 均为 5.75 ms；这是小样本本机测量，不是跨环境保证。

## 所有变更工具的命令结果检查

受管 Kernel 在最终参数绑定、`tool.admitting` 和 Run 权限检查之后，为所有写入、进程与网络工具调用 Host 的结果核对入口；检查发生在策略、审批和 `tool.started` 之前。入口按实际 Kernel owner 与 Run claim 鉴别来源，不接受模型传入 actor，也不会授予权限。只读检查仍可使用；Host 尚未启动网页监听器时也执行同一检查。

Host 的命令执行服务与普通工具共享 `CommandMutationAdmission`。当前 Run 内健康的原调用仍能并发，但只有本地跟踪 revision 至少覆盖最新规范记录时才允许豁免；较新的规范不确定状态不能被旧内存状态覆盖。监听器卸载时释放只读状态关联，默认保守检查继续存在。该检查不会替代 Plan、Workflow、沙箱或人工审批。

真实受管 Host 测试验证：旧命令尚未派发但回执待核对时，内置 `write_file` 不写文件也不记录执行意图，`read_file` 仍正常工作；明确保存原命令未启动的事实后，后续写入完成且资源释放。Kernel 测试覆盖后置转换把读取变成写入、取消检查、正常审批和 deny；命令服务测试覆盖较新规范记录与原调用迟到结算。

## 派生任务的共同核对范围

变更检查读取当前 Run 的规范授权来源，同时检查本 session 和最初授权 session；后续排队任务不会替换该来源。子 session 的非只读命令先在最初授权 session 写入 `run.commandMutation.*` 摘要，再保存自己的完整回执。摘要只有来源身份、命令、revision 与核对状态，不复制参数和结果。父任务、兄弟任务和更深的派生任务因此共享待核对限制；独立授权的任务保持自己的范围。

摘要先写入规范日志，再写源回执。若跨日志写入中途失败，恢复可以保留额外的暂停条件，不会丢失已经写入的限制。原始实际结果保存后同步更新摘要，明确未执行也可解除限制；嵌套 Storage、节点、IPC 或 Git 未确认错误仍保持待核对。已确认记录与只读命令不阻断。

读取继续复用 session／type／seq 索引，最多返回 64 条摘要与溢出标志，不扫描 session 树，也不新增表或提高数据库版本。测试覆盖父／兄弟／孙任务、独立任务、规范日志重建、元数据容量和真实子日志文件故障；受管 Host 验证父任务的未知命令也阻止派生 session 的内置文件写入。人工核对、孤立限制的解除协议和完整模型执行入口仍须后续接入。

## 自动回答的人工边界与记录

用户输入问题增加可选 `purpose`：`decision` 表示任务偏好与选择，`fact` 表示无法从上下文确定的用户事实，`authorization` 表示授权。旧问题未声明用途时按需人工处理；`isSecret` 始终要求人工。Plan 的模型工具说明与参数契约提供这些字段，经过受管插件 IPC 后仍保留原值。

现有 `unattended` 推荐逻辑只自动处理整组明确的非秘密 `decision` 问题，且每题必须有唯一推荐项。一组中任何题需要人工时，整组继续沿用用户输入流程，不填充或编造缺失的事实。自动选择在返回前持久保存 `user_input.autoDecided`，包含原请求、选择来源和回答；保存失败不返回自动答案。来源取消或停止边界同样会阻止返回。

真实 Kernel 与受管 Host 验证普通推荐选择、人工选择覆盖推荐、秘密／事实／授权／旧问题、审计写入失败、来源取消及资源释放。初始实现使用原有 `unattended` 开关，随后接入下述分层策略及同模型补全；目标 session 委派仍待实施。

## 源模型的无工具决策补全端口

Driver SDK 增加可选 `completeDecision`，受管 Host 以源 Run 的实际 Kernel owner、session 和
已绑定 Driver 版本路由。Driver 仅在原模型 Run 仍活动时接收请求，并核对原模型配置；
候选进程、错误来源、模型替换及来源取消均拒绝新补全。原 Run 所属的 draining Driver 可以完成已有任务的补全。
旧或自定义 Driver 未提供此能力时，调用方仍须保留人工请求。

请求必须显式声明空工具集，只含最多四条文本消息，系统文本最多 16,384 字符，
规范化请求最多 131,072 UTF-16 单元。每次输出额度单独传递，范围为 64–4,096 tokens，
不修改或依赖模型配置标准化后的默认输出额度。

Host 和实际 Driver 各限制最多 16 个补全。每次有 90 秒期限，IPC／来源取消后仍无法结束的实际所属进程

两侧 IPC 等待原实际回复，逻辑取消、期限或主 Driver 终态均不会提前释放来源 Run 的关联；

## 会话命令的生产工具入口

## 持久问答与人工接管

问答在任何自动补全之前登记到规范日志，每个 request ID 使用原 session／Run／call 身份和策略快照，记录容量上限 128 KiB。
StoragePort 新增 userInputAccept／userInputRead／userInputCommit，使用已有 session/type/seq 索引读取最新状态，不增加第二份可变数据库或表。
单写者事务通过 expectedRevision 判定答复与取消；兼容 requested、resolved 和 autoDecided 审计与规范状态在同一事务内提交。
规范类型使用 user_input.state 前缀，沿用 fsync 的持久日志规则；Storage RPC 握手覆盖新增端口。

Kernel 在自动判断期间也保留可人工接管的 pending 投影。人工与自动答复竞争时仅采用持久赢家，失去竞争的模型答案不返回给来源任务。
已发生的模型补全等待实际结算并保留原 Run 用量；不会因为人工提前回答而丢失费用。
答复写入失败后保持等待并向调用方返回错误；接纳或答复确认丢失时只读取同一原记录一次，不提交第二个答案或新问题。

## 统一决策目录与命令接口

`decision.list/get/resolve` 在 CLI、API 和命令面板使用同一组类型契约，覆盖问答、普通审批和 Plan Exit。
目录按 session 和 kind 分页，默认只读 pending，每页最多 50 条，仅返回身份、状态、版本和来源 Run 状态；正文通过 get 单独读取。
问答复用规范事件的 session/type/seq 索引，审批按 session/kind/id 建立表达式索引；已有数据不增加新的可变日志表。
审批版本以 pending 为 1、终态为 2；问答使用持久状态 revision。

resolve 要求认证操作人、幂等键和已读取版本，调用原 Kernel 问答、审批或 Plan Exit 用例。
Plan Exit 保留原 Run/call 与模式切换、当前许可和反馈限制；普通审批不能冒充 Plan Exit。
命令边界保持设备、角色与 workspace/session 授权，observer 只可读取。
同 session、actor 和幂等键的意图及结果写入 `decision.operation` 规范持久记录，每条最多 512 KiB，并在确认前 fsync。
已确认结果可跨重启原样读取；不同输入复用原键返回冲突。只有意图而缺少确认回执时返回 RESULT_UNKNOWN，要求 get 核对原决定，不重放。
这不是决定状态与外层命令回执的跨事务原子保证：两者之间若中断，保留未知结果并停止自动重试。

所有 session 可以通过 hbar_command_execute 执行 decision.list/get，沿用来源 actor 和完整命令准入；decision.resolve 的模型调用仍等待显式委派授权链，尚未开放。
命令面板的名称、说明和选项由宿主中英文文案提供。真实网络测试覆盖原请求答复、拒绝审批、同 Run 退出 Plan、跨会话与权限拒绝和重复请求；真实 Worker 验证索引分页、重启回执、确认丢失和未知意图不重放。
决策目录在重启后可读取持久请求，但中断 Run 的交互执行器恢复仍需后续调度接入。

## 普通任务的无人值守恢复

全局分层字段 `backend.unattended` 默认关闭，可在通用设置中保存并即时应用。
`hbar serve --unattended` 创建服务时以本机认证设备保存开关；复用已有 Host 时通过正常 settings 命令保存，不重启已有服务、不改端口和决策模式。
开关改变后合并调度刷新，唤醒当前可安全恢复的会话；只运行当前 default Kernel，关闭时等待刷新结束。

未设置显式 Goal 的普通任务遇到来源明确的 provider 临时错误时，最多接受两个自动后继 Run，分别等待 1 秒和 2 秒。
退避时刻、原任务、前序 Run、稳定 request ID 和累计次数写入 `run.autonomyRetry` 规范持久记录；接纳新 Run 与其谱系复用 enqueue 的同一事务和单条规范接纳记录。
确认丢失只核对原 request ID。Host 重启后使用原时刻及次数，不重新计算退避或清零。
续跑提示保留原任务，要求检查已完成工具结果后继续；模型、Plan／approval 设置、规范操作人及 session 预算保留，所有工具继续经过原权限和沙箱链。
预算耗尽时不再发起付费请求；正常完成后不再续跑，也不创建 Goal。

规划与接纳均复核全局开关 revision、最新任务、归档状态、来源设备角色及原/current workspace 权限、取消和未结算工具／命令结果。
已有显式 Goal 的会话继续只由 Goal 调度；预算、配额、未知结果、超时、中断和普通执行错误不当作临时 provider 错误重放。
在失败任务的退避阶段取消，会持久停止该任务，保留原失败状态；重新启用开关不会复活它。
退避期间 runtime idle 为 false，并保留 session 的 queued 保护，等待及停止均有清理路径。

真实 Storage Worker 覆盖重开、稳定重复接纳、次数上限、策略改变、新用户任务、未知工具、撤销设备、scope 和文案。

## 执行额度组件

Runtime 提供有界的 `ExecutionSlots`：默认四个执行额度，FIFO 排队；同一 Run 的模型与并行工具分别持有活动引用，共享一个额度。
确认等待时可暂停该活动，只有 Run 的全部活动都暂停或实际结束才释放额度；恢复等待重新排队，不改变 Session claim。
降低额度保留已执行的工作，直到它们实际结束后才接纳后续任务；调用者负责验证身份和实际结束，不能用逻辑超时清理物理引用。
组件限制 4096 个执行、8192 个活动及每次执行 64 个活动，提供独立回执及有界状态快照。
七项测试覆盖四个来源与决策目标、并行工具仍在执行、等待后 FIFO、动态收缩、容量与身份隔离、实际退出清理以及一千个任务公平排空。
等待输入时的活动级释放及长时间等待的完整链路仍在下列后续范围。

## Host 无人值守额度接纳

开启全局 `backend.unattended` 后，稳定 Host 在持久 claim 之前预留四个共享执行额度，其余 Run 保持 durable queued 状态。
写入 claim 尚未结束及确认丢失时继续保留额度；确认丢失需先核对原持久回执，不能通过取消队列预留绕过核对。
逻辑结束后仍有真实工具或资源时继续保留原额度及 Session claim，实际结束并释放原 claim 后才唤醒下一项。
退出或替换 Kernel 只清理尚未 claim 的旧预留；已执行的 Run 继续沿用原版本的资源保护。

`--unattended` 在入口保存认证设置前先采用四个额度，避免启动恢复先接纳过多旧任务。
确认持久开关开启后，后续设置变更统一按持久值应用；关闭开关恢复普通客户端原有的并发接纳行为，保留已运行任务。
降低额度不会取消或提前释放实际工作。

获准队列每次最多核对和唤醒十六个 Session，核对最新 queued Run，并绑定预留的原 Run ID 清理失效项。
临时运行门禁保留队列；丢失唤醒提示后，已有的一秒核对循环会再次发现已获名额但尚未 claim 的任务。
唤醒只检查持久队列，不重放请求或修改原历史终态。

新增七项调度器场景覆盖四个 claim、持久写入期间的额度、丢失确认、实际工具结束、队列取消、Kernel 换代、动态额度及可恢复的唤醒提示。

## 模型实际活动与物理响应结算
