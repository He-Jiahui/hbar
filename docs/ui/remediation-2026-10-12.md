# 2026-10-12 UI 架构整改

本轮落实附件第 0～4 步，生产链路为 Web → app-react → Lumen。
代码在 `codex/ui-remediation` 隔离工作树中逐项验证和提交；原工作区已有修改保留。
用户选择先完成 Lumen 独立包和本地 Git 仓库，本轮没有远端创建或发布。
早期 [组件整治计划](component-remediation.md) 中的 hbar-app-ui 名称描述历史实现；
当前生产 UI 使用 `@lumen/app-ui`，兼容目录与预览不在生产 workspace 中。

## 第 0 步：清理生产链路与独立 Lumen

生产入口移除 ReactBits 参考主题，参考路由仅在开发模式动态加载；
删除无引用的 `recharts`、`@xyflow/react` 依赖，移出兼容 UI 与预览 workspace。
移除 MUI fork 子模块依赖，Lumen 源码归入 `packages/lumen-app-ui`，保留 MIT
许可证和上游来源记录，Material UI 使用公开版本依赖。

同级独立 checkout `../lumen-app-ui` 有自己的 Git 仓库、锁文件与构建入口。
它不依赖 hbar 的 runtime、tsconfig、预览应用或私有源码路径；可安装公开注册表依赖，
运行包内类型检查、测试和构建。构建输出 ESM、类型声明、独立工作台/目录 CSS，
本地 archive 用构建导出清单打包。所有 41 个公开导出均检查目标文件；新安装消费者
通过根入口、基础控件和 CSS 导入验证包可用。

独立仓库提交为 `263cbfa26ede2713edb6e5cfaf2d510a3ed16f36`，分支
`codex/standalone-lumen`；提交后干净且没有远端。最终本地归档为
`artifacts/packages/lumen-app-ui-0.12.0.tgz`，大小 990,024 字节。

Lumen 只维护 `--lumen-*` 主题变量；宿主阅读、语法和文字角色在
`packages/app-react/src/theme-bridge.css` 映射一次，旧 theme-store CSS 写入函数移除。
宿主使用公开 `data-lumen-part`，不访问 Lumen 内部类名。

## 第 1 步：入口与提示归属

侧栏常驻新建、搜索、项目/会话树、通知和设置；排期、模板、首次配置、命令等
次要入口归入更多菜单，扩展与技能在设置中访问。
状态中心按系统、运行、用量、诊断组织，旧运行看板入口映射到运行分区。
运行数据失效通知只刷新当前可见的运行分区，隐藏页和其他分区不响应。

同一个停靠会话面板切换活动、监控、代理与目标/计划，保留 pane 实例与会话归属。
输入区上方按优先级显示一条主要提示，其余恢复项在会话面板登记和操作。
关闭详情、重开面板和切换会话不改变条目所属目标。

真实 Host 的丢失上传响应场景验证了两会话三个上传回执：B 与 A1 核对后回到各自
草稿，A2 仍保留待核对状态；恢复没有新增上传，累计上传次数始终为 3。
该验收使用临时目录和 fixture 凭据，没有使用用户会话或商业模型。

## 第 2 步：组件与 Composer 状态

会话页拆成头部、历史、恢复提示和输入区，各区域独立订阅所需数据。
外壳拆成侧栏模型、项目树、底部动作和工具区；布局继续由已有描述文件管理，
不复制第二套布局事实。`app-runtime` 的 Composer 选择器统一给出可提交、
可取消、锁定和阻止原因，视图据此展示反馈与控制状态。
Goal 与 Plan 保持独立意图，草稿和幂等操作回执继续归 runtime 管理。

回归补齐了拆分后暴露的阅读和恢复问题：选中空闲会话即有标准空草稿；
1px 向上滚轮也能暂停自动跟随；位置校正不会用旧闭包覆盖新阅读锚点；
流式 Find 在同一查询/目标下保留并重建有效 Range，失效文本不会保留假高亮。
虚拟行卸载时保存嵌套表格/代码的横向位置，只恢复内容签名仍匹配的块。
缓存按会话和消息隔离，最多 128 行，组件卸载清理，并拒绝旧行的迟到事件。

## 第 3 步：设计刻度与响应式边界

间距使用 2、4、8、12、16、24、32 七档，圆角使用 control、surface、panel
三种角色，层级使用命名 token。几何零、百分比、边框和图表尺寸有各自契约；
圆形控件的 pill 与已有方形偏好不产生另一套普通面板圆角刻度。
视口断点统一为 40rem、48rem、64rem，TypeScript 与 CSS 使用相同边界；
可调整工作台面板的内部布局由命名容器查询决定。

`bun run check:styles` 检查宿主选择器及间距/圆角/层级，沿公开工作台样式图
检查 Lumen。`bun run check:responsive` 跟踪生产 CSS 导入，拒绝缺失、越界
导入、额外视口宽度和未声明的命名容器。细则见 [样式契约](../ui-style-contracts.md)。
固定 1440 × 960 视口下实际拖动工具分隔条，session 容器从 770px 缩为 590px；
页头跨越 48rem 容器边界，发送动作与监控标签保持可见，页面错误为空。

Lumen 根入口收敛为基础控件和工作台组合，当前安装后的根入口有 135 个运行时导出。
账单、认证、付费墙、看板等保留在显式 catalog/组件族入口，目录 CSS 独立导出；
生产宿主不加载完整目录或预览登记。

## 第 4 步：类型化文案与术语

`createMessageScope<TMessages>()` 提供宿主注入的 Provider 和 `t(key)`，
key 与返回值保留字符串、对象和格式化函数的准确类型，t 回调在相同消息对象下稳定。
未注入必需 Provider 时明确失败，允许缺席的表面使用显式 optional reader；
组件没有隐含英文 fallback，也不导入 Web 的 locale 或 store。

会话头部/历史/输入区、侧栏/项目树/工具栏、设置、通知、文件、扩展、状态、
诊断和会话监控等消费者在所属窄 scope 内直接读取文案，减少内部逐层 labels 转发。
公开组件的宿主 `labels` 适配入口保留；Lumen 的公共宿主内容契约和纯格式化 helper
也保留类型化参数。本轮不宣称删除所有历史 `Labels` 接口或重写每个参考目录。

`bun run check:typed-messages` 接入串行 `check`，检查 app-react/Web 源码，
阻止已迁移区域重新创建旧 Labels Context、把完整 copy 对象改名为 labels，或
包装完整旧 scope 后向下转发。它是明确规则的静态门禁，不推断全部可能的数据流。
规则的正反夹具有 6 项测试，当前扫描 747 个源码文件通过；文件系统 CSS 测试
移至仓库 Bun 测试层，避免浏览器组件包依赖 Node I/O。

中文术语见 [术语表](../ui-terminology.md)：Host 为宿主，Run 为运行，Agent 为代理，
child Agent 为子代理；模型 Token 为词元，凭据 Token 为令牌，设计 Token 为设计令牌。
英文文案、协议字段、动作 ID 与斜杠命令保持技术标识，术语测试验证中英文边界。
