# UI 子目标、依赖与完成状态

上级：[UI 总计划](index.md)。更新：2026-09-20。状态仅以实际提交和验收证据推进；计划写完不代表页面实现完成。

## 1. 实施顺序

```text
R0 证据与入口盘点
 └─ R1 组件基础与视觉修复
     └─ R2 展示状态、外壳、导航
         ├─ R3 会话与输入
         ├─ R4 会话工具
         └─ R5 设置、状态、命令
             └─ R6 清理与完整验收
```

R1 中能独立复现、修复的组件可以先完成，之后进入页面组合。每个可独立交付的子功能通过验证立即提交；失败或未执行的检查不标记完成。R0–R6 已按表内证据全部关闭；历史行保留各切片当时的状态和验证边界。

## 9. 提交与交付记录规则

每个任务记录 commit、验证命令、结果和截图路径；纯文档修改只进行格式/链接/一致性校验。视觉产物留在 artifacts，不提交原始测试数据或凭证。用户已有的组件库修改逐项核对，不能 git add 整个包或通过清理工作树移除。

一次提交若含同族多个小修复，必须能独立验证一个完整行为。不能把未完成的下一页面提前提交成 placeholder；也不能为了提交数量把类型、实现、测试拆成不能运行的中间态。
