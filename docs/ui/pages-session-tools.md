# 页面设计：文件、监控、子 Agent、目标与计划

上级：[UI 总计划](index.md)。任务范围 R4；公共状态规则见[总体架构](architecture.md)。

## 1. 四种工具共用的容器

复用并完善 `HbarAppUiToolPane`。容器拥有标题、明确目标、关闭/返回、可选工具栏、状态条、内容与底部动作。禁止在 ToolPane 内再渲染一个完整带 h1/关闭按钮的页面。

工具通过会话页头图标或命令打开。宽屏并排、平板 drawer、手机单面板；业务实例、目标和草稿不因断点改变。当前工具按钮具有 aria-pressed/选中态，再点击同一入口切换关闭，使用明确 close command。

当前实现已通过 `hbar-app-ui/tool-pane` 窄入口固化该容器。文件工具显示工作区名称并把路径放在描述行；Monitoring、子 Agent 和 Goal/Plan 显示会话名称。子视图的返回动作进入同一标题栏，正文不再重复 h1、返回和关闭。外壳 header 固定，普通长内容由 body 持有外层滚动；文件虚拟列表和编辑器继续在 body 内使用各自有界内容区。三档真实 Host 对照见[视觉审计第 36 节](visual-audit-2026-09-19.md#36-toolpane-正式契约与四类工具统一外壳)。

初次打开显示区域 loading；刷新保留已有内容并标记刷新中。错误放在所属列表/字段/动作附近；没有数据、无权限、尚不支持分别表达，不能都显示空列表。

## 2. 文件工具

### 结构与导航

```text
文件                         当前工程          关闭
路径面包屑 / 返回父目录                        刷新
文件与目录列表（独立滚动）
    点击文件 → 同一工具内的文件详情
返回文件列表 / 文件名称 / 修改状态
文件内容或编辑器（滚动）
保存状态                                      保存
```

默认使用列表→详情的逐级呈现；24rem 工具区不再同时塞文件树、文件编辑器和重复标题。桌面与窄屏使用同一子路由和打开文件 ID。

复用 WorkspaceFiles、FileDocument、VirtualList 和已有编辑器。新增 embedded/header 控制与 selectedId，以 typed props 表达；文件行使用统一按钮样式，文件/目录/选中/禁用有明确层次。

### 行为

- 文件名显示 basename，路径放面包屑/tooltip；长路径不挤掉关闭、保存等动作。
- 目录按已有 cursor 有界加载；打开文件加载期间保留列表返回入口。
- 只读、二进制、不支持预览、过大文件和无权限显示真实原因及已有可用操作，不能装成文本编辑器。
- 编辑草稿以 workspaceId+path+版本隔离。保存执行现有文件命令；冲突显示源文件已更新，提供重新加载/保留草稿，禁止静默覆盖。
- 切换工具/会话不把草稿写到新文件。返回列表保留位置。关闭详情保留普通草稿；明确丢弃必须针对具体文件。

验收：空目录、100/101 文件、长名称、目录切换、已删除文件、只读、保存失败、冲突、会话快速切换和窄屏长代码。

## 3. 当前会话监控

标题显示“当前会话”或固定目标名；范围提供当前会话/含后代（仅当现有查询支持）。从上至下为运行摘要、紧凑关键指标、token 趋势、模型/工具明细。默认不同时展开放满所有图表。

核心指标为总 token、输入/输出、费用估算、输出速率、运行耗时；详细区展示 TTFT、响应耗时、缓存与工具统计。null、gap、未采样与估算沿用真实数据质量标记。不能从全局 CPU 推算“该会话 CPU”。

复用全局 Usage 的指标/图表组件及 UsageSurfaces 的受控能力。共享 query/formatter，不维护另一份累计器。过滤条件经已有 status/session 命令持有；图表 hover 在组件内。

验收：未运行、运行中、结束、无样本、断线 gap、长模型名、价格未知；切换范围不改会话选择，导出/刷新绑定原目标。

## 4. 子 Agent 管理

默认呈现子 Agent 列表，标题旁只有一个“创建”操作。每行展示名称、状态、简短任务、预算/耗时摘要；行内更多菜单放取消等低频动作。“打开会话”是明确导航，不能点击行内取消时顺带切换。

选中条目进入该工具内详情，显示任务、来源会话、模型、运行状态与必要操作。“创建子 Agent”按需打开表单：任务必填；标题、模型、预算、思考和审批策略按现有 Schema/命令能力提供，默认值来自当前配置。

复用 ObjectiveForm、统一 Field、Dialog、Status、列表 primitives。列表和创建表单不再永久左右并排。创建期间防重复；成功插入返回实体；失败保留字段。父会话与新 Agent 的预算归属明确呈现。

验收：无 Agent、单个、分页、大量并发状态变化、同名、失败/取消中/结果未知、列表变更后针对原 agentId 操作。

## 5. 目标与计划管理

主视图上方是当前 Goal 摘要与状态，下方是 Plan 步骤。没有目标时呈现简短空态和一个设置目标入口；有目标时显示编辑、清除等具体操作。不要同时出现大创建表单、重复目标卡和计划卡。

编辑 Goal 使用已有 ObjectiveForm；编辑 Plan 使用 PlanEditor。步骤显示顺序、状态和简短说明，编辑控件只在编辑模式显示。长步骤允许换行；完整计划属于工具 body 的滚动内容。

提交与清除使用现有目标/计划命令，显示应用于哪个 session。普通草稿可离开后恢复；清除目标需要绑定当前目标确认，不能因 UI 选中变化清除其他会话的目标。运行约束、生效状态来自后端，不由前端推断。

验收：无目标、已有目标、运行中修改限制、长计划、步骤重排、版本冲突、保存失败和回执未知；返回会话后时间线摘要同步，但不抢焦点。

## 6. 工具与 Schema 设置的衔接

会话设置是第五个工具入口，但进入统一 Settings 页面，而不是塞入 24rem 工具容器。打开时捕获 sessionId，顶部清楚显示作用域；返回时恢复之前打开的工具与聊天位置。

终端、浏览器/计算机和诊断能力仍通过已有注册入口及命令访问。本轮不为了“补齐参考”创建空工具页面。若旧能力只有 command，功能清单如实注明该入口，而非宣称已有完整 UI。
