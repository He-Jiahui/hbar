## 1. 设计基准与保留边界

**整体视觉贴近 cc-haha，保留单页面导航。** 重做 hbar 的外壳、页面层级、工具区、设置和交互反馈；现有命令框架、Schema 设置框架、业务状态与服务器交互继续复用。

总计划编写时已目视对照 **8 张 cc-haha 产品截图和 8 张 hbar 视觉产物**，涵盖会话、文件、设置、供应商编辑、命令面板、子 Agent、深色和窄屏。主要参考包括 [cc-haha 会话界面](/D:/Git/cc-haha/docs/images/app/zh-CN/session-main.webp)与[设置界面](/D:/Git/cc-haha/docs/images/app/zh-CN/settings-general.webp)。当时实时浏览器工具遇到认证兼容错误，这批证据属于已有截图。2026-09-19 的计划展开已通过项目 Playwright 流程补充 Prompt 修复前后各 21 张真实渲染图及生产会话截图，详见本轮审计；cc-haha 当前运行版本和整页重设计的实时验收仍待完成。

新设计明确替换以下布局：

- 底部堆叠大量等宽导航按钮，缺少主次关系。
- 工具、设置和命令面板全部争用同一个主内容出口。
- 页面外层大留白、内层大卡片、重复标题共同挤占有效空间。
- 输入区、活动卡和大块用量面板挤压聊天正文。
- 窄屏直接把整个侧栏堆到页面上方。
- 业务表单混用浏览器原生外观与组件库控件，缺乏统一尺寸和层级。

不引入顶部多页面标签。cc-haha 的定时任务、市场、宠物等业务不随参考布局迁入。hbar 已有功能通过新的导航归位，保持可达。

## 2. 确定后的页面与导航设计

### 外壳与会话页

```text
┌──────────────────┬────────────────────────────────────────────┐
│ hbar       收起  │ 工程 / 当前会话            会话工具图标组 │
│                  ├──────────────────────────┬─────────────────┤
│ ＋ 新建会话      │                          │ 工具标题    关闭│
│ 命令      Ctrl K │                          ├─────────────────┤
│                  │       聊天时间线         │                 │
│ 工程          ＋ │                          │  当前会话工具   │
│ ▾ 工程 A         │                          │                 │
│   当前会话       │                          │   按需打开      │
│   其他会话       │                          │                 │
│ ▸ 工程 B         ├──────────────────────────┤                 │
│                  │ 提示词输入框             │                 │
│  工程树独立滚动  │ 附件 / 模型 / 思考 / 发送│                 │
│                  │ 紧凑 AI Usage            │                 │
├──────────────────┤                          │                 │
│ ● 服务端状态     │                          │                 │
│ 状态       设置  │                          │                 │
└──────────────────┴──────────────────────────┴─────────────────┘
```

右侧工具默认关闭。关闭工具后，聊天与输入区共同使用剩余宽度，并保持一致的内容对齐。

| 区域       | 最终设计与行为                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------- |
| 左侧导航   | 品牌与收起按钮；新建会话；紧凑命令入口；工程→会话树；底部服务端状态及“状态、设置”。树独立滚动，底部不随列表滚走。 |
| 工程操作   | 工程标题行提供“打开工程”；具体工程的新增会话、重命名等操作放在所属行或更多菜单中，明确绑定目标。                  |
| 会话选择   | 点击会话即进入该会话主页面；从设置或状态页点击会话，也必须立即回到聊天。选中样式与可见页面一致。                  |
| 主区顶部   | 一条紧凑标题栏，展示工程、会话标题及必要运行状态。工具入口在标题栏右侧横向排列，使用图标、提示和选中状态。        |
| 聊天正文   | Markdown 为主；活动、工具调用、计划按所属消息组织，详细内容按需展开。待审批内容保留明确的操作入口。               |
| 提示词输入 | 独立的底部正常布局区域；附件、模型、思考等级和发送/停止集中在输入框工具行。多行内容增高到上限后内部滚动。         |
| AI Usage   | 输入框下方使用紧凑摘要，显示用量/预算、速率和预计费用；详细统计进入当前会话监控。                                 |
| 会话工具   | 文件、监控、子 Agent、目标与计划使用同一个右侧工具区，一次展示一种工具；每个工具只有一层标题和一套关闭操作。      |
| 会话设置   | 打开统一设置页面，预选当前会话作用域，明确显示目标名称；不另做一套会话设置实现。                                  |

**单页面的返回规则固定如下：**

- 设置和状态中心在主区展示，桌面端保留工程侧栏；页面标题栏提供“返回会话”。
- 从会话进入管理页时保存会话、滚动位置和工具上下文；返回时恢复。
- 管理页之间切换不叠加无限返回历史，始终保留原会话返回目标。
- 会话切换保留各自输入草稿；工具的 `followActive` 与 `pinned` 语义继续保留，固定目标必须在工具标题中标明。
- 关闭工具只关闭工具。关闭弹窗恢复触发位置焦点。关闭供应商编辑返回原设置分类和作用域。
- 导航失败保持原页面，并在入口附近反馈；禁止出现侧栏已选中、主区仍停留在无关页面的状态。

### 设置、状态与命令面板

**设置页**采用 cc-haha 的分类栏＋表单结构：顶部放返回、标题与作用域选择；左侧放 Schema 分类；右侧按分组展示字段。作用域同时显示具体工程或会话名称。继承来源、覆盖状态与校验就近展示，保存区留在表单底部独立区域。

供应商列表使用统一行布局与操作菜单。“添加/编辑供应商”打开真正的对话框，背后保留设置页面；表单内容滚动，标题和保存/取消操作保持可见。插件与技能等已有扩展管理归入设置的“扩展”分类，移除外壳中重复的常驻入口。

**状态中心**保留 Performance、Usage、Git 三个页面内分区。标题、分区切换、筛选、图表与明细形成稳定层次；筛选使用紧凑工具行，低频条件放到筛选面板。会话 Monitoring 复用相同的数据与展示组件，并明确限制目标范围。

**命令面板**改为覆盖当前页面的搜索对话框：

- 初始展示搜索和分类结果。
- 选择带参数命令后，在同一对话框进入参数表单，支持返回结果列表。
- 当前目标以可读名称呈现；技术参数放入高级选项。
- 执行结果优先呈现可读摘要，原始 JSON 收入可展开详情。
- `Ctrl/Cmd+K` 打开；关闭后恢复原页面与焦点。
- 命令目录、参数校验、执行回执及 CLI 对应关系继续使用现有实现。

## 3. 视觉规范、模块边界与接口调整

### 视觉与响应式

采用参考中的浅色纸面、柔和侧栏、细分隔线、明确选中态和克制阴影，同时提供对应深色主题。保留用户已有主题偏好；无偏好时跟随系统。字体层级、控件高度、圆角、间距和图标统一通过组件库 token 管理。

以下数值是新设计的起始约束，实施时通过实际截图校准，不作为已测得的参考尺寸：

- 桌面侧栏默认 `17.5rem`，工具区默认 `24rem`；聊天正文与输入区共享最大内容宽度。
- 页面标题使用紧凑字号，普通页面不再套大圆角背景卡。
- 普通内容使用 flex 流；只有真实对话框、菜单和抽屉使用覆盖关系。
- ≥`80rem`：支持侧栏、聊天和右侧工具并排。
- `64rem`–`80rem`：保留侧栏，工具使用右侧抽屉。
- <`64rem`：侧栏使用抽屉，选择会话后收起。
- <`48rem`：工具进入带返回入口的单面板页面；设置分类改为分类选择入口。主页面不被压缩成几条狭窄列。
- 页面内容、工程树、聊天、工具和表单分别拥有明确滚动区域；正文和普通表单不得造成整个页面横向溢出。

### 包与状态职责

| 模块                           | 本轮职责                                                                                           |
| ------------------------------ | -------------------------------------------------------------------------------------------------- |
| `hbar-app-ui`                  | 外壳、侧栏、页面标题栏、工具容器、对话框、表单控件与视觉 token；使用受控 props，不接触业务 store。 |
| `@hbar/app-react`              | 组合页面、映射只读投影、绑定命令、适配 Schema 控件；按会话、设置、状态、工具拆分。                 |
| `@hbar/app-runtime`            | 页面、工具、弹窗及返回上下文的状态转换；处理目标绑定、导航竞争和草稿恢复。                         |
| Web/Tauri 组合根               | 注册页面与组件、提供 i18n、默认布局和平台能力；统一视觉结构，仅平台交互不同。                      |
| command/schema/settings 框架包 | 保持现有职责与业务契约，继续作为 UI 与 CLI 共用基础。                                              |

应用展示状态从单个 `focusedPanelId` 扩展为明确的 **主页面、活动工具、活动弹窗、返回上下文**。新增只读展示投影，UI 不能直接写入。

继续兼容 `app.setSession`、`app.openPanel`、`app.closePanel`、`app.openSettings`、`app.openStatus`、`app.openSettingsEditor`。通过页面注册描述确定落点；补充返回及侧栏显隐所需的应用命令。会话选择成功后，由 runtime 统一完成选择与页面切换。

布局继续使用独立版本化描述和白名单注册，复用现有 FlexLayout 适配能力，限定为单主区与单工具区，不启用顶部标签与自由停靠。恢复旧布局时迁移有效尺寸与偏好，失效内容回退默认布局；不删除其他业务状态。

## 5. 视觉验证与验收标准

**截图检查是每个子计划的交付条件。测试通过不等于视觉通过。**

实施时采用真实页面或明确标识的确定性 fixture，固定数据、主题、语言、缩放和字体加载条件。每次形成“参考截图／本次截图／问题与修正记录”，人工检查后再更新基线。

- **核心页面矩阵**：会话、右侧文件、设置、供应商对话框、命令面板、状态中心分别检查 `1440×960`、`1024×768`、`390×844`。
- **布局边界**：主会话补充大屏、`1280`、`768`、`320` 宽度；检查浅色、深色、中英文长文案及放大显示。
- **内容边界**：空列表、单条、多条、分页边界、长名称、长代码、长表单、加载、失败和断线；数据不足时展示真实缺失状态。
- **空间分配**：空或短输入且无审批时，输入区与 Usage 合计不超过会话区域约四分之一；聊天保有清楚的阅读主区。长输入在上限后内部滚动。
- **导航一致性**：设置或状态页点击会话必达聊天；工具不意外替换主会话；关闭、返回与 Escape 作用于当前层级；焦点可恢复。
- **状态可靠性**：切换会话不丢草稿，异步结果不写入新目标，打开工具不改变消息滚动位置；布局刷新恢复及损坏数据回退通过。
- **工具验证**：使用项目 Playwright 视觉检查流程采集截图、检查几何关系、溢出、焦点和控制台；执行相关 flow/content/icon guards、类型检查、lint、构建及行为测试。
- **桌面验证**：对 Tauri 真实窗口检查系统缩放、标题栏、窗口缩小、弹窗、输入焦点和资源选择；浏览器截图不能代替桌面验收。

最终交付应同时具备：**完整功能映射、可靠命令交互、人工检查过的视觉证据**。原先的“B1–B7 功能已完成”保留为历史记录，新的 UI 完成状态以本轮 R0–R6 的实际验收为准。
