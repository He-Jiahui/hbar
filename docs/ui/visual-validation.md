# 视觉验证、回归矩阵与交付门禁

上级：[UI 总计划](index.md)。本规则适用于每个子任务，不等到所有页面写完后再检查外观。

## 1. 三层证据

| 层次              | 要回答的问题                                         | 验证入口                                                        |
| ----------------- | ---------------------------------------------------- | --------------------------------------------------------------- |
| 组件独立渲染      | 没有旧工作台 CSS 时，生产组件能否正确显示/操作？     | preview 中只 import production 组件、theme 和宿主布局的独立入口 |
| 完整页面 fixture  | 外壳、聊天、工具、设置组合之后，比例和滚动是否成立？ | 同一生产页面组件＋明确标识的确定性数据                          |
| 真实 Host / Tauri | 真实命令、状态、异步和平台差异是否影响界面？         | E2E Host fixture、实际 Web build、Tauri 实窗                    |

目录变体截图只证明该变体。不能用 preview.css 对原生控件的全局补丁，掩盖生产组件缺少样式；不能用离线 mock 宣称服务器功能已经完成。

## 2. 采集规则

每组记录 code commit/dirty 范围、reference 来源、页面 URL/入口、fixture、viewport、DPR、缩放、浏览器、主题、locale、字体加载和捕获时间。参考截图缺少其中信息时明确标为未知；不把图片像素直接当 CSS px。

固定随机数据与时间显示；普通静态基线禁用非必要动画；等待字体、布局和有界数据加载。流式/运行场景用可控 fixture 在指定状态捕获，不依赖真实付费模型。动画连续性审核是例外：必须启用被测 transition/animation，以受控输入采样起始、中间、结束和快速反向；不能使用 Playwright 的“禁用动画后直达终态”作为连续性证据。

产物放 `artifacts/ui-redesign/<task>/<before|after>/`；每组包含 screenshot、结构/几何报告和错误日志。报告注明是组件图还是页面图。人工审阅记录进入 docs，截图默认不入 Git。

## 3. Lumen 视觉与连续动画验收矩阵

Lumen 的规范终态见[统一设计系统、Lumen 视觉语言与全局外观设置](design-system.md#3-lumen-无界视觉语言)。本节规定后续实施必须如何证明这些关系，不能用“存在 transition 声明”“最终截图看起来正常”或单一 viewport 替代全过程证据。

### 3.1 基础控件状态矩阵

| 对象                    | 必测状态/转换                                                                                                      | 主要可观察量                                                     | 额外行为证据                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Button / IconButton     | idle、hover、focus-visible、pressed、selected、running、disabled；hover → focus、selected → idle、running → failed | 灯带 edge、语义 length、线芯尺寸、opacity、halo、文字/图标对比度 | Enter/Space、快速移入移出、连续提交不会重复动作或重建灯带；disabled 无发光且名称可读 |
| Progress                | 接近 0、中间值、接近满、complete、failed、paused；中间 → complete、running → failed/paused                         | 填充长度、opacity、halo、tone、状态文本/ARIA                     | 数值连续增减和快速反向时不跳帧；failed/paused 不只依靠颜色                           |
| Range / `LumenSlider`   | 静止、键盘调整、鼠标拖动、触摸拖动、快速反向拖动、released、disabled                                               | thumb 位置、track 完成区、轨道/把手 glow、dragging 边界          | 拖动时输入跟手且边界增强；释放后不闪回；Arrow/Home/End 和触摸目标一致                |
| Switch / toggle         | off、on、focus-visible、disabled、快速重复切换                                                                     | 灯点/短灯带位置与 opacity、halo、轨道对比、checked ARIA          | off/on 节点稳定；重复切换从当前呈现值反向，不闪烁或暂时显示相反状态                  |
| `LumenSurface`          | 普通、interactive idle/hover/focus-within/selected、静态大结构、真实可拖拽边界                                     | 背景透明度、局部灯带、结构边界与 glow                            | 静态 surface 不冒充可交互；focus-within 可见；只有真实 splitter/scroll boundary 增强 |
| `LumenDialog` / overlay | opening、open、背景模糊、内容滚动、固定 header/footer、Escape、closing、焦点圈定和关闭后恢复                       | overlay opacity、blur、外边界、外发光、内容/操作可达性           | 初始焦点正确；Tab 不越界；Escape 只关当前层；关闭后回到原触发点；长内容不遮挡 footer |

每个状态同时人工与自动核对：

1. 灯带方位是否符合组件语义，且同一角色不会因文案或实例变化而换边。
2. 灯带终态长度是否来自 `standard`、`action`、`area` 或组件拥有的受控 progress 语义；不得从文本宽度或截图坐标计算。
3. 同组相邻灯带是否共用对齐基线、控件尺寸和长度节奏；长中英文文案换行后仍不参差。
4. 线芯是否保持水平/垂直直线，未沿圆角弯折或组成完整发光描边。
5. 边界是否有明确功能；普通大结构低对比，小结构不过度套框，表格、代码、滚动、焦点和拖拽边界仍可辨。
6. dark/light 是否保持相同的层级与状态强弱关系；亮色墨条也有受控外扩散，不退化为无反馈黑线。
7. disabled、不可交互和低进度是否降低发光而不丢失文字、状态、焦点或必要的起点。

### 3.2 动画帧与可打断性矩阵

| 转换                                 | 起始记录                    | 中间记录                                       | 结束记录                          | 必测打断                                                  |
| ------------------------------------ | --------------------------- | ---------------------------------------------- | --------------------------------- | --------------------------------------------------------- |
| idle ↔ hover / focus-visible         | 低亮度线芯、稳定语义长度    | opacity、长度、halo 位于两终态之间；无空帧     | 对应 hover/focus 或 idle 稳定终态 | 连续移入移出；hover 中途转键盘 focus；blur 后立即 hover   |
| selected → idle → selected           | 选中条可见                  | 退场仍保留连续尺寸/亮度                        | idle 低亮度终态                   | 退场中立刻重新选中，不先跳到 idle 或 0                    |
| running → failed / paused / complete | 运行线芯和循环效果          | 循环层与状态层平滑交接，不争抢同一属性         | 目标 tone、长度、文本和 ARIA 稳定 | 运行中取消、失败后立即重试、完成前数值反向                |
| dragging → released                  | 当前 thumb/track 与拖拽边界 | 位置、完成区、亮度连续跟手                     | 释放位置与受控值一致              | 快速往返、越过中点、释放后立即键盘调整                    |
| dialog closed ↔ open                 | 下层焦点与未显示 overlay    | 遮罩、blur、边界和 glow 连续变化；无无内容空框 | open 焦点圈定或 closed 焦点恢复   | opening 中 Escape；closing 中重新打开；嵌套层只改变当前层 |

每次采样保存同一 DOM 节点在转换前、transition 已开始且尚未结束的至少一个中间帧、稳定终态以及快速反向后的首个中间帧。记录浏览器时间戳、动画/transition 名称与持续信息，以及下列 computed/bounding 数据：

- 灯带/填充的 width、height 或逻辑尺寸与 `opacity`；
- halo 的 `opacity`、`box-shadow`/filter 强度，或可等价量化的主题 token 解析值；
- thumb 的位置、track 完成区和受控业务值；
- overlay 的 opacity、backdrop-filter、外边界和焦点目标；
- 元素 identity、`display`、`visibility`、连接状态与最终 ARIA 状态。

自动断言验证变化方向、中间值位于当前呈现值与目标值之间、反向从当前值继续、最终值稳定且没有空帧。不要把单一截图的像素差异当作审美结论，也不要通过固定 sleep 猜测中间帧；优先使用浏览器 animation/transition 状态、两终态之间的 computed 值和有界轮询。实现采用离散生命周期时，报告必须证明视觉退出完成后才移除节点。

### 3.3 减少动态效果

在 `prefers-reduced-motion: reduce` 和宿主 motion-off 下分别验证：

- 持续呼吸、循环脉冲与非必要空间运动停止；页面没有闪烁或反复重绘。
- 状态文字、ARIA、线芯方向、稳定长度与可读对比仍可辨，不能把所有反馈一并隐藏。
- 对必须立即响应的控件，稳定终态不会先经过错误状态或空帧；如保留短暂非空间淡变，记录其属性和终态。减少动效允许取消普通空间插值，但不接受明显的亮灭闪变。
- 快速重复 toggle、tab 和提交仍保持业务状态与视觉状态一致；不因 motion-off 路径使用另一套 DOM 或未清理 animation class。

### 3.4 主题与环境矩阵

| 维度          | 最小覆盖                                                  | Lumen 专项检查                                                                               |
| ------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 主题          | dark、light；后续自定义主题需单独登记                     | 灯光/墨晕扩散、宿主背景、反差文字和 semantic tone 关系一致；透明/半透明 surface 透出正确画布 |
| viewport      | desktop、narrow，并覆盖响应式断点两侧                     | 同组灯带基线与长度节奏不因换行失配；无横向溢出或坐标式重排                                   |
| 指针          | mouse hover、`hover: none`、触摸拖动                      | hover 不是唯一反馈；触摸无残留 hover；slider/splitter 的触摸边界可发现                       |
| 键盘          | Tab/Shift+Tab、Enter/Space、方向键、Home/End、Escape      | focus-visible 清晰；操作后焦点不丢失；dialog 关闭恢复触发点                                  |
| 动效偏好      | normal、`prefers-reduced-motion: reduce`、宿主 motion-off | 连续转换或稳定终态符合 3.2/3.3；没有循环与闪烁                                               |
| 像素密度/缩放 | DPR 1 与项目支持的常见系统/浏览器缩放                     | 直线线芯清晰、不折弯；halo 不裁切；焦点环与功能边界不中断                                    |
| 内容          | zh-CN、en-US、刻意长标签/说明/路径                        | 文案由宿主 fixture 提供；换行不改变语义长度档位、图标档位或操作顺序                          |
| 功能边界例外  | 表格、代码区、滚动条、拖拽分栏、dialog                    | 无界规则没有删除数据关系、滚动/拖拽反馈、焦点或 overlay 层次                                 |

### 3.5 证据与判定格式

每个组件/转换记录：被测生产组件和公开 props、commit/dirty 范围、主题/locale/viewport/DPR/缩放/输入设备、触发步骤、起始/中间/结束/反向样本、computed JSON、截图或视频/trace 路径、自动断言结果、人工观察与遗留差异。状态名称必须映射到真实 ARIA/受控业务状态，不能只靠测试 class 模拟。

单项只有在静态终态、连续转换、快速反向、减少动效和至少一个窄屏/长文案场景均有对应证据时才可标记通过。未测触摸、dialog 焦点恢复、功能边界例外或亮色墨晕时，报告按未覆盖记录，不用邻近组件或 dark 截图外推。

当前阶段只交付本验收契约，不执行或伪造整套运行时矩阵，也不据此声称现有组件已经完成视觉改造。后续实现切片必须把实际命令、退出结果、截图/trace 与人工结论写入对应任务证据，再更新完成状态。

## 5. 人工看图标准

逐张确认以下项目，并记录问题位置、所属组件、原因与修复：

1. 第一眼能否识别当前工程、会话/页面，以及主要操作。
2. 外壳、页头、内容、工具、弹窗层级是否明确；是否重复标题或多层装饰套壳。
3. 聊天是否占据主阅读空间；输入框和用量是否过大；消息与输入是否对齐。
4. 正常/hover/focus/selected/disabled/危险状态是否可辨；默认控件外观是否混入。
5. 长名称、字段说明、代码和本地化文案是否把操作挤走；图标和文字是否对齐。
6. 真正需要滚动的区域是否可滚；是否出现多个无意义滚动条或整个页面横向移动。
7. 窄屏能否完成同一任务；侧栏是否侵占主区；对话框保存/关闭是否可达。
8. 错误、加载和缺失数据是否靠近触发位置；是否用零值、空白或灰按钮掩盖失败。

像素 diff 用于发现偏移，不是审美分数。与 cc-haha 的比较允许已经确认的单页面、hbar 功能差异；差异必须能解释到产品决定，不能随意归为“风格不同”。

## 6. 可自动检测的门禁

- 页面及普通表单没有横向溢出；代码/数据表局部横向滚动允许且标明区域。
- 所有操作按钮都在所属容器内且可点击；图标 hit area 与图标本身尺寸独立。
- 隐藏区域 inert/不可聚焦；modal 焦点圈定、Escape、关闭后恢复。
- 主页面、工具和模态数量及 active target 与 runtime 投影一致。
- 输入行数增长有上限；长内容不会挤出发送/保存；短输入场景满足约 25% 空间目标。
- 列表 0/1/正常/上限/上限+1、重复/失效 ID 和异步回调原目标。
- 页面无未处理异常；预期断线记录和真正 pageerror 分开。

这些检查不能代替人工查看截图。纯组件样式修复无需增加重复业务单元测试，但应有针对真实故障的视觉/行为回归。

## 7. 已可运行的 Prompt 审核

```powershell
# 默认启动独立 Vite 测试入口，生成 after 截图并执行断言。
bun scripts/verify-hbar-app-ui-prompt.ts

# 仅记录模式用于修复前证据；不会执行“已修复”断言。
$env:HBAR_APP_UI_PROMPT_RECORD_ONLY='1'
bun scripts/verify-hbar-app-ui-prompt.ts
Remove-Item Env:HBAR_APP_UI_PROMPT_RECORD_ONLY
```

入口为 preview 项目的 `prompt-audit.html`，输出为 `artifacts/ui-redesign/prompt/`。可用 `HBAR_APP_UI_PREVIEW_URL` 指定服务地址，`HBAR_APP_UI_CHROME_PATH` 指定本机浏览器。脚本只关闭自己启动的服务，使用 fixture，不修改用户真实会话。

注意：在已修复版本执行 record-only 只会记录当前版本，不能恢复历史 before 图。历史对比需要使用对应 commit 的隔离 checkout 或保留的原始证据；不要在用户脏工作区切换历史版本。

## 8. 每个实施切片的命令与门禁

按变更范围运行组件脚本及对应 E2E；新/实质修改样式运行 flow guard，TSX 跑 content/icon guard。代码提交前运行 lint、typecheck、基础测试；Web 变化运行 build。受影响检查失败后修复重跑，已通过且未受影响的不反复运行。

当前仓库完整 check 可使用 `NODE_OPTIONS=--max-old-space-size=8192`；这属于运行资源设置，不是跳过 lint。格式只处理本次明确路径。最后检查 staged diff 和用户原有修改。

Tauri 阶段还需真实窗口：100%/125%/150% 系统缩放、普通/窄窗、标题栏拖动、键盘、对话框、文件选择。Web E2E 或打包成功都不能代替这一轮。

## 9. 完成状态与证据格式

每个 task 写：状态、commit、验证命令及退出结果、截图路径、人工观察、遗留问题。无截图、未人工看图、关键行为未测、存在核心页面裁切时保持未完成。截图更新基线必须说明修复原因，不把回归图直接“接受”为新正确效果。
