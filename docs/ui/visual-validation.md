# 视觉验证、回归矩阵与交付门禁

上级：[UI 总计划](index.md)。本规则适用于每个子任务，不等到所有页面写完后再检查外观。

## 1. 三层证据

| 层次              | 要回答的问题                                         | 验证入口                                                        |
| ----------------- | ---------------------------------------------------- | --------------------------------------------------------------- |
| 组件独立渲染      | 没有旧工作台 CSS 时，生产组件能否正确显示/操作？     | preview 中只 import production 组件、theme 和宿主布局的独立入口 |
| 完整页面 fixture  | 外壳、聊天、工具、设置组合之后，比例和滚动是否成立？ | 同一生产页面组件＋明确标识的确定性数据                          |
| 真实 Host / Tauri | 真实命令、状态、异步和平台差异是否影响界面？         | E2E Host fixture、实际 Web build、Tauri 实窗                    |

目录变体截图只证明该变体。不能用 preview.css 对原生控件的全局补丁，掩盖生产组件缺少样式；不能用离线 mock 宣称服务器功能已经完成。

## 2. 采集规则

每组记录 code commit/dirty 范围、reference 来源、页面 URL/入口、fixture、viewport、DPR、缩放、浏览器、主题、locale、字体加载和捕获时间。参考截图缺少其中信息时明确标为未知；不把图片像素直接当 CSS px。

固定随机数据与时间显示；禁用非必要动画；等待字体、布局和有界数据加载。流式/运行场景用可控 fixture 在指定状态捕获，不依赖真实付费模型。

产物放 `artifacts/ui-redesign/<task>/<before|after>/`；每组包含 screenshot、结构/几何报告和错误日志。报告注明是组件图还是页面图。人工审阅记录进入 docs，截图默认不入 Git。

## 4. 人工看图标准

逐张确认以下项目，并记录问题位置、所属组件、原因与修复：

1. 第一眼能否识别当前工程、会话/页面，以及主要操作。
2. 外壳、页头、内容、工具、弹窗层级是否明确；是否重复标题或多层装饰套壳。
3. 聊天是否占据主阅读空间；输入框和用量是否过大；消息与输入是否对齐。
4. 正常/hover/focus/selected/disabled/危险状态是否可辨；默认控件外观是否混入。
5. 长名称、字段说明、代码和本地化文案是否把操作挤走；图标和文字是否对齐。
6. 真正需要滚动的区域是否可滚；是否出现多个无意义滚动条或整个页面横向移动。
7. 窄屏能否完成同一任务；侧栏是否侵占主区；对话框保存/关闭是否可达。
8. 错误、加载和缺失数据是否靠近触发位置；是否用零值、空白或灰按钮掩盖失败。

像素 diff 用于发现偏移，不是审美分数。与 cc-haha 的比较允许已经确认的单页面、hbar 功能差异；差异必须能解释到产品决定，不能随意归为“风格不同”。

## 5. 可自动检测的门禁

- 页面及普通表单没有横向溢出；代码/数据表局部横向滚动允许且标明区域。
- 所有操作按钮都在所属容器内且可点击；图标 hit area 与图标本身尺寸独立。
- 隐藏区域 inert/不可聚焦；modal 焦点圈定、Escape、关闭后恢复。
- 主页面、工具和模态数量及 active target 与 runtime 投影一致。
- 输入行数增长有上限；长内容不会挤出发送/保存；短输入场景满足约 25% 空间目标。
- 列表 0/1/正常/上限/上限+1、重复/失效 ID 和异步回调原目标。
- 页面无未处理异常；预期断线记录和真正 pageerror 分开。

这些检查不能代替人工查看截图。纯组件样式修复无需增加重复业务单元测试，但应有针对真实故障的视觉/行为回归。

## 6. 已可运行的 Prompt 审核

```powershell
# 默认启动独立 Vite 测试入口，生成 after 截图并执行断言。
bun scripts/verify-hbar-app-ui-prompt.ts

# 仅记录模式用于修复前证据；不会执行“已修复”断言。
$env:HBAR_APP_UI_PROMPT_RECORD_ONLY='1'
bun scripts/verify-hbar-app-ui-prompt.ts
Remove-Item Env:HBAR_APP_UI_PROMPT_RECORD_ONLY
```

入口为 preview 项目的 `prompt-audit.html`，输出为 `artifacts/ui-redesign/prompt/`。可用 `HBAR_APP_UI_PREVIEW_URL` 指定服务地址，`HBAR_APP_UI_CHROME_PATH` 指定本机浏览器。脚本只关闭自己启动的服务，使用 fixture，不修改用户真实会话。

注意：在已修复版本执行 record-only 只会记录当前版本，不能恢复历史 before 图。历史对比需要使用对应 commit 的隔离 checkout 或保留的原始证据；不要在用户脏工作区切换历史版本。

## 7. 每个实施切片的命令与门禁

按变更范围运行组件脚本及对应 E2E；新/实质修改样式运行 flow guard，TSX 跑 content/icon guard。代码提交前运行 lint、typecheck、基础测试；Web 变化运行 build。受影响检查失败后修复重跑，已通过且未受影响的不反复运行。

当前仓库完整 check 可使用 `NODE_OPTIONS=--max-old-space-size=8192`；这属于运行资源设置，不是跳过 lint。格式只处理本次明确路径。最后检查 staged diff 和用户原有修改。

Tauri 阶段还需真实窗口：100%/125%/150% 系统缩放、普通/窄窗、标题栏拖动、键盘、对话框、文件选择。Web E2E 或打包成功都不能代替这一轮。

## 8. 完成状态与证据格式

每个 task 写：状态、commit、验证命令及退出结果、截图路径、人工观察、遗留问题。无截图、未人工看图、关键行为未测、存在核心页面裁切时保持未完成。截图更新基线必须说明修复原因，不把回归图直接“接受”为新正确效果。
