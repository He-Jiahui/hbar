# 页面设计：状态中心与命令对话框

上级：[UI 总计划](index.md)。任务范围 R5.5–R5.8。

## 1. 状态中心共同结构

入口是侧栏底部“状态”，执行 `app.openStatus`。页面保留应用侧栏，顶部为返回会话、标题和当前分区操作；下方使用 Performance / Usage / Git 页面内切换，不产生顶部页面标签。

```text
返回会话  状态                                  刷新 / 导出菜单
Performance | Usage | Git
范围 / 时间窗 / 常用筛选                  更多筛选
关键指标行
主趋势图
明细列表 / 表格（有界数据）
数据来源、估算/缺失/采样说明（按实际情况）
```

去掉固定的大外层 Surface 和每个分区重复页面标题。指标卡只用于需要并排比较的关键数字，其他内容用分组和分隔线。过滤变化保留结构；loading 不让整个页面抖动。

## 2. Performance

默认展示 Host 进程范围；范围选择可以切换已有整机能力，明确标注来源。第一行 CPU、内存、线程/进程摘要；第二层 CPU/内存时间趋势；磁盘 I/O、网络与进程详情按分组展示。

“线程占用”只有数据源提供归因时才能显示；只有数量时标注线程数，不能把 CPU 利用率当线程利用率。采样间断保留 gap，单位与时间窗始终明确。

复用 Monitoring/Dashboard 中已具备受控内容契约的指标、图表和列表；带 spec/demo 的变体先抽出受控图表，再接 app-react。不为追求完整图表矩阵填造零值。

验收：整机/Host、短长时间窗、单样本、gap、进程退出、采样 unavailable、读写/上下行单位，以及图表在 390 宽度的图例和坐标轴。

## 3. Usage

默认全局，可选择工程/会话；常用筛选为时间和范围，供应商/模型/聚合粒度置于展开筛选区。筛选值由现有 status-workspace 命令持有，刷新和导出使用同一 query snapshot。

| 分组 | 展示内容                                   | 展示约束                                    |
| ---- | ------------------------------------------ | ------------------------------------------- |
| 总览 | token 总量、输入/输出、预计金额、总耗时    | 费用估算与缺少价格分别标记                  |
| 速率 | token 消耗、输入/输出速率                  | 说明窗口；无有效分母不生成虚假速率          |
| 模型 | 模型与供应商用量/费用分布                  | 长名称换行/详情，颜色之外有文本             |
| 响应 | TTFT、总响应耗时、缓存命中率变化           | 明确统计口径与样本数；不能推算缺失历史事实  |
| 执行 | 工具调用成功/失败/未知、并发、Run/工具耗时 | 复用当前执行账本口径，和 token 请求统计区分 |
| 明细 | 请求/Run/工具记录、详情                    | cursor/有界数量，导出截断显式提示           |

复用 UsageSurfaces 中的 Overview、ModelSpend、RequestLog 等受控能力；让相同图表同时服务全局 Usage 和会话 Monitoring。图表 hover 仅本地状态，不能每次 hover 发命令。

导出以当前筛选结果为准，JSON/CSV 置于一个菜单。导出中有原位状态，失败不生成空文件冒充成功。空数据页仍保留筛选入口。

## 4. Git

默认当前工程，支持已有仓库/来源/时间窗筛选。上方显示分支和工作区摘要，中间是提交数量柱状图、提交文件数及增删行趋势，下方是提交列表与单条详情。

自动提交与手动提交使用来源标签/筛选区分。柱状图选中时间桶只过滤本页明细；点击提交进入页内详情，返回保留筛选和列表位置。无仓库、无提交、读取失败分别呈现；本轮不新增自动执行 Git 写操作。

验收：无 Git 仓库、空历史、大量提交、跨时间窗、文件/行数缺失、来源过滤、长提交说明，且不会改变 active session。

## 5. 分类命令面板

生产以 `HbarAppUiDialog` 承载 `HbarAppUiCommandList` 和参数/结果子视图，从整页双列 catalog 转为单个临时模态。底层 catalog、descriptor、参数草稿、执行回执继续复用；三步状态由 runtime 持有，NativeDialog 只负责顶层、焦点和 Escape 出口。

```text
搜索模式： 搜索框 → 分类结果 → 键盘帮助
参数模式： 返回结果 / 命令名称 → 目标摘要 → 参数字段 → 执行
结果模式： 结果摘要 → 可执行下一步 → 可展开技术详情
```

分类沿用 catalog：导航/工程会话/模型预算/运行审批/文件/Agent/目标计划/设置/状态/扩展等以真实目录为准，不在组件里维护第二张命令表。内部 form 字段编辑命令不显示为普通用户操作。

输入 `session.setBudget` 等 ID 或本地化名称都应可发现；带参数的字符串调用继续由命令框架解析。参数模式预填已解析的目标，展示会话名称和工程；确需指定不同目标时通过 picker/高级字段修改。

缺失必填字段定位到控件；敏感字段按现有 secret 策略管理。已提供参数的无表单命令可以直接执行；破坏性命令沿用目录中已有确认语义，不另外生成 UI 专有实现。

成功显示具体结果摘要，原始 JSON 放“详情”；失败保留草稿；unknown 保留 request/idempotency 信息供核对。导航命令成功后关闭模态并落到目标页面，读取/设置命令保持结果视图供查看。

### 键盘、焦点与宽度

- 搜索打开后聚焦输入，上下键选结果，Enter 进入参数或执行；输入法 Enter 不执行。
- 参数模式 Escape 先返回搜索；搜索模式 Escape 关闭。业务执行结果未知时不因 Escape 宣称取消成功。
- 初始宽度使用 min(42rem, 可用视口)，长参数表单 body 滚动，header/footer 保持可达。
- 不在打开命令面板时改变选中会话；执行会话导航命令才改变目标。
- 关闭后焦点返回触发按钮/输入；父目标已删除则回到有效页面标题，不落到隐藏元素。

验收：分类、重名、空结果、大目录虚拟化、目录更新导致选中项消失、长参数、动态选项、敏感值、键盘、失败/unknown、导航落点、320 宽度和中英文。
