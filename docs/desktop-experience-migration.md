## 核心判断

cc-haha 易懂的根源是作用域和阅读顺序：左侧负责找任务，顶部负责切上下文，右侧负责查看当前任务成果，输入区负责决定下一次执行方式，设置页负责长期配置。次要动作在对象旁渐进展示，主动作则有清楚文字。

hbar 已具备工程/会话树、工具侧栏、设置分类、返回会话、Host 命令和可靠保存语义。迁移不是重造这些能力，而是让入口更容易发现、少绕路、明确作用对象。不能把“命令优先架构”误解成“普通用户必须经过通用命令表单”。

### 导航准则

- 全局、工作区、会话、文档、选区操作分开归位。
- 入口捕获原始实体 ID；不能点 B 项目却读全局当前 A 项目。
- 目的地选中态与“后台保留的会话上下文”不是同一件事。
- 长列表独立滚动，主操作与设置留在滚动区外；活动项不得被截断规则藏掉。
- 工具关掉只是收起视图；不能隐含取消、删除或清空草稿。

## hbar 迁移单元与验收

以下是实施边界，不代表已经完成。实际完成与检查结果记入独立提交。

1. **输入旁的模型入口**：把静态模型说明变为可操作控件，直达当前会话的模型/思考设置；未配置同位恢复；返回保留草稿。不引入第二套模型状态或保存协议。
2. **项目对象的就近入口**：项目菜单提供文件和工作区设置，明确原始workspace ID；跨项目会话点击显式携带归属；页面选中态只标当前目的地。保留后台上下文但不制造双重选中。
3. **会话工具的可发现性**：为高频文件/计划提供可扫描文字，其余工具保持就近；窄窗不靠图标缩小或横向裁切。不能删功能来换简洁。
4. **设置导航与作用域**：分类可扫描、页面/分组操作分层；全局供应商和客户端外观不能被会话scope误导；模型和默认参数仍保留三层继承和未知结果核对。
5. **后续更大迁移候选**：专用新建/重命名流程替代通用参数表单、会话搜索、多工作上下文标签、文件/Git/预览联动。涉及新状态模型和产品能力，逐个独立闭环，不添加空入口。

容量：新菜单是短有界列表，内容长高；项目/会话目录沿用每页100的分页契约和侧栏独立滚动；设置分类是短有界导航，未知组以Host元数据回退，不内置演示项。新增入口不改变持久化格式。

验收必须覆盖中文/英文与长标签，desktop/900/390/320，键盘和accessible name，零/一个/正常/边界列表，失效ID及列表变化后的原对象回调。跨项目操作、设置返回、草稿保留、失败恢复均用可观察状态验证。涉及实际桌面集成时另跑构建和WebView2 smoke，不把浏览器通过写成原生窗口通过。

本轮保留开始时已有的未提交文件及脏 `hbar-ui` 子模块，不以夹带提交或还原清理制造干净工作区。
