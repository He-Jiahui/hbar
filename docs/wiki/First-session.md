# 跑通第一条会话

这篇把“选工作区 → 发消息 → 审批工具 → 取消或恢复 → 检查结果”串成一条完整路径。第一次尝试建议使用 `--demo` 和一个可以随时还原的 Git 项目。

## 1. 选择工作区

工作区是 Agent 可以读取和操作的项目目录；hbar 自己的数据库、配对凭据和设置保存在另一个 `--home` 数据目录中。不要把密钥、个人配置或 hbar 数据目录当作工作区交给工具。

启动 Host 时可以显式指定项目：

```powershell
bun run host --home .dev/first-session --workspace <你的项目目录> --demo
```

桌面工作台也可以通过工作区选择器添加目录并为它命名。多个工作区可以共用一个 Host，但每个数据目录仍只允许一个 Host 实例。

## 2. 新建 Session 并选择运行方式

在工作台中创建一个 Session，确认当前工作区和模型。`--demo` 使用本地 fixture，不访问模型网络；真实模型需要先在“设置 → 模型”中完成配置，详见 [模型与设置](Models-and-settings.md)。

默认模式适合执行任务；Plan 模式只规划不执行相应的计划修改。Goal、Plan 和 Budget 是独立的内置能力：可以记录目标、查看步骤，并为一段任务设置 token 上限。它们的状态会随 Session 持久化，不要把 UI 上的草稿当作后端已提交事实。

## 3. 先发送一个小目标

从可观察、可回滚的任务开始，例如：

```text
请阅读 README.md，概括这个项目的目录结构，不要修改文件。
```

需要附件时，可以附加图片或一般文件；Host 会校验类型、大小和数量，并只把受限的文本内容交给模型。不要在消息或附件里放 API Key、Cookie、配对码或其他不应离开本机的内容。

## 4. 观察运行和工具审批

模型的流式回复、工具调用、审批请求和最终结果会按顺序显示在 Session 中。Demo 模式下可以用下面的请求验证不同分支：

```text
/tool read_file {"path":"README.md"}
/tool write_file {"path":"scratch.txt","text":"hello"}
/tool shell {"command":"Get-Location"}
```

工作区内读取默认允许；写入和 Shell 会请求批准。批准卡展示的是最终参数。拒绝后应以失败结果继续审阅，而不是假定工具已经执行。

运行时间较长时，可以取消当前 Run；排队中的输入可以单独取消。关闭浏览器或桌面窗口不会取消 Host 中已经接纳的 Run。

## 5. 审阅、分支和继续

完成后先检查消息和工具结果，再在工作区使用 Git 查看实际文件变化。需要保留另一条思路时，从已结算边界 Fork Session；不再需要的会话可以归档或导出。重复使用同一个 `requestId` 会返回原 Run，不能用同一标识偷偷提交不同输入。

## 6. 出现中断时怎么做

Host 重启会把活动 Run 标记为 `interrupted`，未结算的工具意图标记为 `unknown`，不会自动重放可能产生副作用的写入或命令。先核对文件和命令的实际结果，再明确重新提交；不要把“没有看到最终消息”当作“没有执行”。

下一步可以阅读 [工作区与会话](Workspaces-and-sessions.md)、[模型与设置](Models-and-settings.md) 或 [排查问题](Troubleshooting.md)。
