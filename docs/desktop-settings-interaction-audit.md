## 应迁移的表达规则

1. **稳定的两级导航，而非把管理任务交给命令搜索。** 主栏负责会话、市场等长期目的地；设置栏负责配置类别。页面标题、选中类别、返回位置同时明确。搜索/命令是快捷路径，不替代可见的配置入口。
2. **列表负责发现，详情负责理解，编辑器负责修改。** 供应商列表不显示所有字段；技能列表不直接塞完整 Markdown；插件详情能说明它提供的技能/MCP/Agent 并链接到真实对象。hbar 当前扩展卡片罗列技术数据，却缺少相应详情路径。
3. **动作跟随对象。** 添加在列表标题旁；测试、编辑、删除跟随供应商；安装跟随市场卡片；缺依赖的恢复跟随失败项。全局 toast 或泛化的“打开命令”不足以承担结果和恢复。
4. **默认简单、必要时展开。** 名称、地址、认证是供应商基本路径；协议映射、上下文、价格、思考级别是可继续查看的高级路径。简洁来自有秩序地展开，不是删掉 hbar 已有能力。
5. **保存策略按风险显式表达。** cc 的主题/语言一选即改；连接、网络、凭据有保存/测试；删除、重建、卸载有目标确认。不能给所有页面套一种“保存”模板，也不能把草稿误标为已生效。
6. **类型化作用域与权限必须真实。** hbar 的客户端外观、Host 供应商、工程/会话可继承设置不是同一类。外观不得出现会话作用域；技能或插件没有 workspace 安装能力时不得仿造可选项。
7. **视觉轻重服务操作。** 参考以纸面、墨色文字、细边线、低对比选中底色组织信息，品牌色只强调状态/局部选择；不把每个字段、统计和段落都做成等重量嵌套卡片。hbar 用既有 token、语义图标等级与正常 flex 流映射，不逐像素复制参考坐标。
8. **美感需要一致性而非装饰数量。** A2 的标题、描述、表单左边线和节间距形成节奏；A1 的表单可滚动但动作区域稳定；A4 的错误颜色只用于真实失败。参考截图中的个人资料与累计统计不必机械复制到 hbar 的管理页。
