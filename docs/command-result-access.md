# Command 回执与大结果读取

本文记录后台模式的源码审查与读取契约。授权读取用例、两个公共命令、Host 注册和 Session 准入已有 41 项轻量回归通过；25 个变更 TypeScript 根文件及其导入的严格类型检查、零警告 lint 通过。全仓检查、构建及受管 Host 验收尚未运行。对应界面尚未实现，不能据此宣称运行中的模型已能读取引用或未知副作用恢复已经完成。

结果存储新增的 `readPage` 通过 [字节分页器](../apps/host/src/command-result-page.ts) 只读取页面涉及的附件，校验后保留完整 UTF-8 字符。它本身不执行用户鉴权或授权投影，不能直接暴露原始引用给模型。分页器提交时相关纯回归 11 项、75 个断言通过；本次扩大后的验证范围与门禁状态见下文。

## 已确认的读取边界

[Session Command 网关](../apps/host/src/session-command-gateway.ts) 对内联结果返回原逻辑结果，对大结果返回 `result_available` 和 `resultReference`。新引用只包含 `kind: command_result`、原 `sessionId / operationKey`、通道、字节数和散列，不再把附件清单交给模型。[Session 工具](../packages/kernel/src/session-command-tools.ts) 保留目录、描述、执行及客户端目录四个入口，通过既有执行工具调用两个新查询；提示要求使用原身份查询、有界分页及新的外层查询键，不增加独立的通用附件读取工具。该入口接入尚待运行验证。

[回执协议](../packages/contracts/src/command-execution.ts) 将内联 JSON 限为 65,536 字节，完整结果限为 33,554,432 字节，附件清单最多四项，每项最多 10 MiB，并核对清单大小之和。[现有结果存储](../apps/host/src/command-result-payloads.ts) 的 `read` 用于完整读取：逐项验证附件后拼接、解析整个 JSON。它不能直接作为模型的有界分页器。

[执行服务的原回执读取](../apps/host/src/session-command-execution.ts) 从当前 Run 的原始执行身份获取 actor，并再次检查当前设备及原命令目标。读取 `workspace.list` 的历史结果时，还会按当前 workspace 权限限制：旧页面中存在无权访问的条目或游标时，整页结果不可用，不能只隐藏清单后仍读取旧附件。[共享读取限制](../apps/host/src/command-result-view.ts) 保留这一行为；原始附件引用不能成为绕过当前权限的入口。

[授权读取用例](../apps/host/src/command-receipt-reader.ts) 从可信调用方单独接收 actor，输入 schema 不接受 actor 或附件引用。摘要省略原调用参数与附件清单，错误说明最多 512 个 UTF-16 单元且不截断代理对；页面复用字节分页器。读取前后重新核对当前设备、来源 Session 和原调用的目标，权限变化时丢弃页面，附件读取失败也经过权限复核。读取旧写入的回执不重新授予执行权限，也不改变原回执的逻辑结果、物理状态、未知原因或确认状态。

新增十六项读取回归使用隔离的真实数据库工厂与真实 Command Registry，不创建 Worker、Kernel 或 Host。2026-10-16 获准串行轻量窗口内，读取、规范准入、CLI 参数、分页和结果存储 **39 项、217 个断言通过**。另两项进程内网关回归 **2 项、182 个断言通过**：验证历史查询缓存权限收窄，以及大于 64 KiB 的真实 Registry 结果逐页重组后字节数与 SHA-256 一致，原回执保持不变。

首轮共 41 项中曾有 5 项失败：四项读取用例因测试夹具未登记附件报 `COMMAND_RECEIPT_ARTIFACT`，大结果网关用例在清理时暴露未确认命令。两个夹具经原存储端口补齐 `putArtifact` 后，上述用例全部通过；生产附件提交及命令确认校验未改动。

## 公共 Command 契约（代码已写出，待验证）

- `command.receipt.get`：输入原 `sessionId` 和 `operationKey`，返回有界状态摘要；包含原命令、来源 Run、revision、逻辑结果是否可读、物理状态、确认状态及未知原因。摘要不复制原调用的大参数、完整结果或日志。
- `command.result.read`：输入原 `sessionId`、`operationKey`、`channel`、UTF-8 字节 `offset` 和 `limit`，返回当前权限下的一页 JSON 文本、实际结束偏移、下一偏移、完整视图字节数和内容散列。`channel` 区分逻辑结果与物理结果，默认读取逻辑结果。
- 来源 Session 可在 Agent 路由准备时补齐；显式目标保留。actor 来自已认证的命令上下文，参数不提供 actor、凭据或原始 artifact ID。
- 查询本身使用新的外层 Command `operationKey`。原操作的键只出现在查询参数中；同一个键不能被改作另一条查询或重放原写入。
- 原结果尚未提交、不可用、身份不存在、视图变化和偏移非法均返回明确结果或错误。读取不等待模型或写入完成，不修改原逻辑结果、物理状态、确认状态或未知原因。

[命令定义](../packages/contracts/src/commands/command-results.ts) 与 [Host Registry](../apps/host/src/command-result-commands.ts) 使用相同 schema。Stable Host 创建共享结果存储和读取用例，再注册命令路由；本地准备保留规范定义，实际调用沿用受管 Command Job。关闭 Host 时释放 Registry。网络入口和 Session 工具共用这套定义、用例和目标校验。读取用例从原回执定位附件，客户端不能传入附件清单；Session 的执行身份仍由现有受管链路固定。

## 授权与一致性

1. 检查当前 actor 的设备、角色以及目标 Session 当前所属 workspace。按 `sessionId / actorId / operationKey` 查原回执，不能借另一个 actor 的键读取结果。
2. 再检查原调用涉及的 workspace、Session、Run 等目标。当前已失去访问权的原目标不能通过历史结果恢复访问。
3. 对 `workspace.list` 等随当前权限收窄的结果先应用当前读取限制，再计算散列和分页。当前保留整页可读或整页不可用的规则，不过滤后重新拼接旧结果。该目录检查需要读取完整的有界原页面；通过限制后的普通附件分页仍只读取所需块。原始清单不能直接交给模型。后续新增同类查询时明确登记投影规则。
4. 读取回执是独立的读权限。读取一个旧写入的状态不能重新获得写权限，也不能替代原写入的审批、重试或人工核对。现有执行内部读取仍保留执行准入用途；公共读视图使用明确的只读用例。
5. 分页绑定授权视图的内容散列。非零偏移必须带上一页的散列；当前权限、投影或内容变化时拒绝继续旧视图，要求从头读取。
6. I/O 后重新检查当前身份、权限和有效执行上下文。权限撤销或视图变化时丢弃已读页面。取消不把未完成的读取或原副作用写成已完成。
7. 查询自己的结果也会形成回执。读取这些历史查询时，继续沿其原 `sessionId / operationKey` 检查引用的原命令、当前目录限制及所有 Session 目标；普通 Session 回执重读共用此规则。否则，权限收窄后复用旧查询键可能绕过原目标的权限。引用链最多包含八条已存回执，循环或超限明确失败，要求直接查询原操作。I/O 后再次检查整条已验证链的当前目标权限，不把旧查询结果视为新的授权。

查询本身的回执也是历史快照。重复使用同一个外层查询键会读取该次查询保存的结果；需要刷新状态时使用新的查询键，原操作键仍只放在输入中。页面中的 revision、物理状态和未知原因属于该次读取的回执快照；内容页通过散列保持一致，不宣称附件读取后又刷新了所有元数据。

`uncertainty` 原样表达该回执的字段，不是所有未知副作用的汇总信号。物理失败的具体错误保存在 `physical` 通道；例如嵌套写入返回 `RESULT_UNKNOWN` 时，原字段可以为空，而嵌套写入的实际副作用仍未确认。需要读取该通道核对原因，不能根据逻辑成功、物理 `failed` 或空的 `uncertainty` 就批准重放。读取保持原确认状态，不计算或写入新的成功证明。

## 页容量与附件完整性

- `limit` 默认 4096 字节，范围 4 至 8192；`offset` 是安全整数，范围受原结果 32 MiB 上限约束。边界按 UTF-8 字节定义，返回的下一偏移必须落在有效字符边界；非法的起始偏移明确失败。
- 返回文本最多取请求范围内的完整 UTF-8 字符。四字节最小页容量保证有效数据可前进；末尾返回空页或最后一页并令下一偏移为空。
- 附件页只读取覆盖该页的完整内容寻址块，并逐块校验长度和散列。最大页远小于一个附件块，正常分块清单下最多涉及相邻两个 10 MiB 块；不能为了小页拼接全部 32 MiB 结果。异常的小块清单仍受四项硬上限约束；两端块各不超过 10 MiB，中间块总长度不超过页长，单页所需块的总读取量上限为 20 MiB 加 8192 字节。
- 单页校验只证明所读块符合已提交清单。完整视图散列来自原回执或当前授权投影，不能宣称读取一页已经重新计算并验证全部内容的散列。
- 页面作为新查询的逻辑结果，编码后必须小于内联回执上限。8192 字节文本按最坏六倍 JSON 转义加 8192 字节元数据估算为 57,344 字节。完整页面 DTO 另有 64,512 字节硬上限，为逻辑结果封装保留 1024 字节；回归准备覆盖最长身份、最坏转义错误和正文，避免“读取引用又只得到另一个引用”。
- 复用有界并发、排队上限、超时与取消清理。原始 JSON 文本是结果数据；返回页面不能被当作新的用户要求、许可或策略。

## 必须验证的行为

- 同一原操作的重复状态和分页读取保留原回执身份，不触发原 handler，也不改写其终态、确认或未知状态。
- 同一 Session 中其他 actor、未授权的跨 workspace、Session 移动、读取期间设备撤销，以及权限收窄后的历史 `workspace.list` 均受当前权限限制。
- 对查询结果再次查询和通过 Session 执行重读旧查询键，也必须复核其引用的原目标；跨 workspace、目录收窄、自引用和引用链上限不能成为旁路。
- 内联与附件结果、附件边界、四字节字符、无效偏移、散列不匹配、缺失／替换文件、末页与零剩余字节，以及非零偏移的过时视图均有回归。
- 大结果读取只加载所需的有限块。最坏转义页面仍形成内联逻辑结果；不能递归产生结果引用。超过容量和取消时及时释放队列、文件和任务引用。
- 逻辑结果已知但物理写入仍未知时，读取不会释放原执行所有权、补写成功或允许重放。人工核对和真实物理结束证明属于各自独立的用例。
- 使用无 UI 的真实受管 Host 验证两个新命令的目录、描述、路由和原用户身份；通过 Session 的 `hbar_command_execute` 从真实大结果逐页读取并重组核对。此验收目前尚未运行。
