# 工作台侧栏拖动尺寸验收

被测主仓库提交：`85e2e42b`（尺寸与取消）和 `69827bc5`（侧栏通知外层）；canonical 子模块仍为 `8446abca8d`。
分支为 `codex/hbar-app-ui`，验收日期为 2026-10-03。

## 症状与原因

用户截图中的主区／右工具栏分隔条拖动后尺寸错误；同一路径也影响左侧工程栏。
桌面投影在 `0229b6fc` 中使用整个视口换算 FlexLayout 权重，包含了外框与分隔条占用的宽度；
拖动组件没有收到描述文件的宽度上下限，保存时才将结果截断到允许范围。
本轮通过当前代码、相关提交差异和真实 Tauri/WebView2 的重现定位，未对所有历史版本执行 bisect。

在 1600 CSS px 的内窗中，布局容器实际宽度为 1598，两条分隔条共占 16。
旧代码把 20 rem 的工具栏最小宽度渲染为 316.41 px；超范围向左拖动时，预览位置 x=415，
松手后分隔条回到 x=1021.48，出现约 606 px 的回跳。

## 修复行为

- 用布局容器的 CSS 像素宽度、当前根字号与实测分隔条宽度做双向换算；无需设备像素比修正。
- 把工程栏 12–24 rem、主区至少 20 rem、工具栏 20–36 rem 的约束投影到拖动组件。
- 只在完整拖动或键盘调整后保存；单纯激活面板不改布局偏好。
- 保留未调整一侧的偏好，包括窗口较小时暂时压缩的显示宽度；放大窗口后恢复原尺寸。
- Esc 通过组件支持的 pointercancel 取消拖动；不保存预览尺寸，不影响草稿。
- 通知铃铛在侧栏中的外层改为内容高度，避免继承整块面板高度而挡住设置按钮。
