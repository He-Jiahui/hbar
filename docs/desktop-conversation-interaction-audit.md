## 核心设计表达

1. **会话是阅读主线，设置是辅助行为。** 常用选择保留输入上下文，弹出菜单/小浮层使用后就地消失；只有提供商尚未配置时才引导到设置。
2. **稳定的 composer 语义分组。** 左侧是“加入材料、运行权限、项目上下文”，右侧是“上下文状态、模型、思考等级、发送/停止”。草稿、等待、运行不改变用户找入口的逻辑。
3. **正文、过程、决策三种不同视觉重量。** 助手正文无重复卡片；过程完成后归纳成弱对比计数；等待审批/回答才使用有边框的显著区块。不是所有内容都套等重量卡片。
4. **入口携带目标。** 工具行说明文件/命令，审批标题说明将操作哪个文件，问卷带具体问题；用户不必先打开原始 JSON 才知道自己在决定什么。
5. **持续使用渐进披露。** 活动摘要 → 单步行 → diff/命令/原始参数；简洁来自压缩次级信息，不来自删除能力。
6. **图标提供辨认，文字承担解释。** 菜单行有标题与短说明，列表有路径/来源/结果。低频 icon-only 动作有可访问名称；主任务入口不依赖猜图标。
7. **尺寸是角色，不是坐标。** cc 的具体像素只用作证据；hbar 应映射语义字号、sm/md 图标与内容流。浮层可锚定触发器，正文/工具/问卷必须 flex 正常流，不能用截图坐标布局。

## 建议实施顺序与完成门槛

1. **局部选择闭环**：模型、思考等级（主线进行中）。必须有真实可选数据/确认/失败/切换保护与桌面窄屏截图，不能以打开settings算完成。
2. **阅读主线闭环**：复制缺失、助手正文层级、连续工具/思考摘要。先修已确认无回调的复制，独立测试后提交；再实现有界局部会话组件，避免修改共享Lumen其它surface。
3. **材料与上下文闭环**：附件预览/移除/失败、文件提及、斜杠命令、context用量渐进披露。仅接入真实可用契约。
4. **运行与决策闭环**：Send↔Stop、queue/引导、审批与问卷关联回原步骤、当前任务活动。先区分哪些已有Host能力、哪些必须独立扩约。
5. **跨端验收**：每个子功能测中文/英文长标签、空/一/边界/超限、键盘、快速切会话、失败恢复，再看桌面+窄屏截图。区分已有契约未接线的 session fork、已有 per-run Plan mode，以及尚需扩约的 sessionallow 等能力；明确保留未完成项，不能用外观相似替代事实闭环。

总体验收应覆盖本文每行，不因模型、Goal、Plan或五个工具按钮已调整而把整会话迁移标完成。
