# Bun 后端与可靠同步

## 后端职责

- 业务后端与工程脚本使用 Bun 驱动 TypeScript。Tauri 保持桌面适配职责，不为新增业务引入第二个 Node/Python/Rust 后端。
- Controller 负责认证、参数校验、调用应用用例以及错误/结果映射。领域规则、队列和事务不放入 HTTP/WS handler。
- kernel 通过公开端口使用 storage、执行器和插件服务；SQLite 访问留在独立 Storage Worker。事务边界必须覆盖需要原子一致的事件、序号和投影更新。
- 外部输入、配置、插件参数及协议响应均在边界进行运行时校验。类型断言不能替代校验，鉴权不能只在按钮或连接建立时做一次。
- 遵循既有执行链：参数校验、前置处理、最终参数再校验、策略/审批、意图日志、执行、结果提交及结算。任何新接口都不能绕过此链执行相同副作用。

## 并发、延迟与生命周期

- 不同 Session 可并发；同一 Session 的活动 Run claim、队列更新和取消必须原子化。使用领域级锁、事务或队列，不能用全局锁把无关会话串行化。
- 网络请求、外部进程、Worker RPC、排队、重连及写缓冲均有明确上限、超时和清理策略；不能无限等待、无限重试、无限积压或无界 `Promise.all`。
- 长任务尽早返回受理标识，再通过关联状态报告进度和终态，不能让交互命令一直等待业务执行完成。明确区分“已受理”“运行中”“取消已受理”和“实际结束”。
- `AbortSignal` 向有能力取消的 I/O 和执行器传播；超时或取消时释放监听器、定时器及任务引用。`Promise.race` 超时不等于底层工作已经停止。
- 对无法强制中止的进程内插件明确能力边界，必要时使用受管 Worker/子进程隔离；不得声称断开 UI 或拒绝等待已经停止外部副作用。
- 大计算、同步文件操作和重型序列化不得长期阻塞 Host 事件循环；使用已有 Worker、分页、分块或有界批处理。慢客户端不能拖慢其他客户端和运行。
- 请求重试只用于安全读取或经过明确幂等设计的操作，采用上限和退避；有副作用请求超时后先按 `requestId` 核对结果，不能自动用新 ID 重放。
- 最少记录操作关联 ID、耗时、队列长度、失败码、重连/重同步次数与推送字节数，避免记录凭据和完整敏感载荷。指标用于验证瓶颈，不能把模型推理时间和命令受理时间混为一谈。
- 延迟验收参照 `docs/testing.md` 的可重复基准，报告环境、样本与 p95/max；新操作定义可测预算。不得以一次本机测量保证所有环境无延迟。

## 简单、有界的推送契约

- 复用 `packages/contracts` 和现有 JSON-RPC over WebSocket；定义具名方法、判别联合、字段含义和错误码，不增加功能重复的自定义传输层。
- 命令有请求关联 ID；持久事件有协议版本、稳定事件 ID、实体 ID 和该实体范围内的单调序号。请求 ID、幂等键、事件序号和文本偏移职责不同，不混用。
- 默认只订阅当前需要的实体和字段；隐藏视图释放无用订阅，重新打开使用游标恢复。后台摘要确有需求时单独订阅摘要，不借机广播全部历史。
- 首次加载使用分页快照和一致性游标；快照后的事件从该游标连续衔接。建立订阅和读取快照之间不得存在丢事件窗口。
- 常规变化只传新增、修改字段或删除标识，不在每次变化时刷新全部 bootstrap、历史或实体集合。大文件、图片、日志和导出内容使用受鉴权引用、分页或流式下载。
- 流式文本使用流 ID、所属实体、基准偏移/版本和新增片段；分别明确正文与 thinking 的偏移，以及偏移单位。不能仅凭一个总长度去推断多字段变化。
- 如需覆盖已有文本，定义具名 replace/reset 操作及版本前提，不把任意 JSON Patch 或全对象替换作为所有变化的默认形式。
- 合并高频增量时保留连续范围和顺序，并设置最大批次字节数、条目数与时间窗；合并发送不能变成反复发送自起点累计全文。
- 单帧、分页、连接在途请求、队列和缓冲字节数均有可配置硬限制。服务端在序列化/入队之前限制数据量，不能仅依赖发送后断开连接。
- 持久事件不能静默丢弃。缓冲超限或游标过期时发送可识别的恢复信号，或通过已约定关闭码断开并触发恢复；慢客户端独立处理。
- 全量恢复仅用于首次获取必要状态、明确刷新、协议/游标失效、无法修补的缺口等情况，仍保持分页和载荷上限。不能因任意变化都走全量恢复。

## 一致性与恢复

- 后端是业务事实源；客户端 store 是投影，按实体序号/版本归并。过时、重复和已撤销连接的事件不能覆盖新状态。
- 游标只推进到已经连续校验并成功应用的位置，不能简单取“见过的最大 seq”。乱序缓冲有界，缺口必须触发补取或受控重同步。
- 文本增量验证基准偏移，防止重复拼接和跨流混入；缺片、重放、乱序、替换和终态都要有明确处理。流式最终结果与持久消息交接不能重复显示或丢字。
- 断线重连从连续游标恢复；回放窗口外获取新分页快照及游标，再接续订阅。恢复次数有界或带退避，避免无限快照循环。
- 多客户端更新经后端确认广播到合法订阅者。需要避免覆盖的修改带预期版本，冲突返回明确错误并刷新相关实体，不能默默最后写入覆盖。
- 提交事务后才能发布代表已提交事实的事件。发布失败仍能从持久日志恢复；暂态流与持久记录明确区分其崩溃恢复保证。
- 凭据撤销和权限变更立即影响相关连接与订阅。按 workspace/session 校验访问权限；不在 URL 或推送中泄露令牌、密钥、内部堆栈和不必要字段。
- 保持 Origin/Host 校验、输入限制和限流；配对不是传输加密。协议变更同步 producer、Client SDK、Zod 校验、版本兼容/迁移和文档，不能只改一端。

## 后端与协议验收

- 按改动风险覆盖多 Session 并发、同 Session 竞争、重复请求、超时、取消、断线恢复和崩溃后未知副作用，验证没有重复执行或永久 pending。
- 对增量链路注入重复、乱序、缺口、游标过期和慢消费者；验证恢复后的前端投影与后端快照一致，且无关客户端继续工作。
- 检查载荷与队列上限、订阅释放和长任务期间命令响应。固定新增片段大小，增加累计历史长度，确认普通增量帧不会随历史同比增长。
- 验证鉴权失败、跨实体越权、设备撤销和畸形消息；恢复路径也必须遵守同样权限。
