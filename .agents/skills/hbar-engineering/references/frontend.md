# 前端、状态与工作台

## React 与 Zustand

- 按功能组织 View、ViewModel、模型转换及测试；现有目录内逐步拆分，不创建无用途的空层级。一个可独立交互或维护的功能单元必须有独立组件边界。
- View 负责展示、可访问性和交互绑定，不直接发起 HTTP/WS 请求、操纵数据库或调用跨功能 store 的 `setState`。
- ViewModel 使用 Zustand store/slice、selector 和 action，承接加载、命令、状态转换与失败恢复；复杂用例提取为可独立测试的服务。向 View 暴露操作，不泄漏传输和存储实现。
- 共享业务数据、会话投影、跨组件草稿、连接和布局状态由 Zustand 管理。纯局部视觉状态可用 React state，例如悬停和局部展开；不得在组件 state 再复制一份服务端实体。
- Zustand 按领域分 store 或 slice，细粒度订阅，保持引用稳定；禁止订阅全局 store 导致无关模块随每个流式帧重绘。
- 持久化仅包含允许恢复的草稿、偏好与布局描述；显式选择字段和版本迁移，排除连接、函数、运行中状态及凭证。
- 派生值使用 selector 或纯函数计算，不保留需要人工同步的多份数据。实体按稳定 ID 定位，分页和事件按 ID/序号合并。
- 请求捕获 `host/connection generation`、`workspaceId`、`sessionId` 和具体实体 ID；只向仍匹配的目标应用结果。切换栏目后到达的旧响应不得覆盖新栏目。
- 异步命令明确区分待处理、已确认、失败、未知结果。乐观更新必须有回滚或重新核对路径，网络中断后不能继续显示已成功。

## 布局描述文件

- 复用 FlexLayout；默认布局必须来自仓库中独立的 JSON 等可序列化描述文件，不能只存在于 JSX、函数或内联常量。推荐随工作台功能存放，如 `apps/web/src/workbench/layouts/default.json`，路径可随现有结构调整。
- 描述格式至少表达 `schemaVersion`、稳定模块 ID、模块类型、区域、顺序、分栏尺寸、可见性与模块配置。允许封装或映射 FlexLayout 原生格式，禁止同时维护两套互相竞争的布局模型。
- 组件注册表通过白名单模块类型映射 React 组件；描述中不得包含可执行脚本、任意 import 路径、事件函数或密钥。
- 使用 schema 校验默认文件与恢复数据。对未知模块、重复 ID、越界尺寸、损坏数据和旧版本提供可预测的迁移或回退；加载配置不能把工作台变成空白页。
- 用户布局修改经过 action 保存序列化描述；设备本地持久化可以作为当前布局的存储后端，但不能替代仓库默认描述文件。支持恢复默认布局，按需要提供导入导出，导入必须验证。
- 桌面和移动布局使用相同模块标识及数据归属。桌面支持符合功能需要的分栏、标签和工具区；移动端提供可访问所有已交付功能的单面板导航。

## 视觉与信息组织

- 采用 JetBrains 风格的多模块工作台：稳定导航、清楚的工具区、主内容区、辅助面板和状态区域。优先保证反复操作、快速扫描和功能定位。
- 以适度圆角矩形为主要形态，常规面板和控件优先 4-8px 圆角；用对齐、间距、分隔线和层级组织模块，避免嵌套卡片与装饰占用操作空间。
- 工具操作复用 `lucide-react` 图标；不熟悉的图标提供 tooltip 和可访问名称。选项集用菜单，模式用分段或标签，布尔设置用开关或复选框，数值用适当输入控件。
- 面板标题与内容密度匹配，字体尺寸稳定；文本、长路径、长代码、按钮和动态状态不能造成遮挡或布局跳动。检查桌面、窄屏、长文本和高密度数据。
- 信息展示覆盖用户决策所需的目标、状态、结果与错误原因；细节按需展开。删除重复标签、无决策价值的统计、宣传语、自我介绍、功能说明废话和技术实现说明。
- 简洁不能通过隐藏必要状态或移除功能实现。错误文本应简短说明原因和可执行的恢复方式；必要的 tooltip、字段校验和风险确认不属于废话。

## 按钮唯一性与就近响应

- 每个栏目维护明确的操作集合，以“动作 + 目标 + 作用域”判断重复；同栏不得同时出现功能相同的“新增”和“创建”等独立按钮。
- 一个按钮只触发一个用户意图。不要把保存和跳转、删除和切换目标等不相关动作绑成一个操作。
- 事件处理函数显式绑定所属面板和实体 ID，不能在等待后读取全局 active ID 来决定写入目标。工具栏只能操作其所属栏目，行按钮只能操作该行目标。
- 加载标记、进度、成功状态、错误与重试入口放在触发按钮附近或其所属内容区域；局部失败不能只在远处全局 toast 显示。全局通知只承载跨模块的全局事件。
- 不相关面板不能因点击而跳转、抢焦点、展开或改变选择。其他视图对同一实体的必要数据同步允许发生，但不得成为动作落点或改变其导航。
- 事件冒泡不得导致行内按钮同时触发行选择或另一个命令；快捷键在所属上下文生效。隐藏或非活动模块不得接收不属于它的操作。
- 与功能相关的禁用、忙碌、重复提交防护、取消、重试、空态和错误态必须落实。删除或覆盖等必要确认绑定明确目标，不能依赖模糊的全局选中项。

## 前端验收

- 验证操作入口、状态变化、后端确认和最终展示形成完整闭环；禁止假数据冒充已实现功能、无行为按钮和完成路径上的 TODO。
- 覆盖两个面板或会话同时打开、快速切换、异步返回、点击行按钮和重复点击；确认动作仅作用于原目标且反馈就近出现。
- 用 Playwright 检查桌面和移动视口，查看截图、控制台错误、焦点、溢出与实际交互；布局修改验证刷新恢复、损坏描述回退和恢复默认。
- 对长历史检查虚拟化或分页，对流式状态检查无关模块不会持续重绘。对受影响的失败、取消、重连流程做行为测试。
