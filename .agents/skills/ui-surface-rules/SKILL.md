# UI Surface Rules

适用于 `apps/web` 中所有可交互选项、菜单、上下文菜单、下拉层和弹出面板。

这些元素是同一类最高层级的临时交互表面，不是可各自定义样式和关闭语义的局部组件。实现或修改其中任一项时，必须接入共享的浮层模板；不得新增独立的 `z-index`、portal、毛玻璃或外部点击实现。共享模板能力不足时，先扩展其公开契约。

## 复用工作流

1. 修改前先检索 `apps/web/src/FloatingLayer.tsx` 及其调用方，确认当前表面应使用 anchored、point 或 modal 模式；不要从业务组件现有的局部实现复制模板。
2. 业务组件只提供内容、语义、目标实体和动作。需要新能力时先扩展 `FloatingSurface` 的类型契约与生命周期，再迁移调用方；不要用局部 prop、样式或监听器绕过公共能力。
3. 迁移后删除旧的 `createPortal`、独立外部点击/`Escape` 监听、局部 z-index、背景和定位代码，并检查同一文件没有保留第二条实现路径。
4. 每个独立表面迁移完成后运行针对性 lint、类型检查/构建和实际交互验收，再提交一个只包含该表面迁移的 commit。

详细的模式选择、触发器竞态和验收矩阵见 [浮层组件契约](references/floating-surface-contract.md)。

## 强制契约

- 选项内容统一左对齐：图标、主标题、辅助说明和快捷键从同一内容起点排列。禁止因为选中态、图标缺失或不同菜单类型而居中或右对齐。
- 所有浮层必须通过统一的 portal/floating-layer 机制渲染到 `document.body`，脱离工作台局部 `overflow`、`transform` 和 stacking context。
- 浮层层级必须高于工作台面板、输入框和普通弹窗；复用统一的最高层级 token，不在单个组件中随意降低 `z-index`。
- 浮层必须有独立的不透明或足够不透明的背景，并使用 `backdrop-filter: blur(...)`（含 `-webkit-` 前缀）提供背景模糊。底层文字和控件不得透出形成重影、噪声或视觉重叠。
- 玻璃装饰层只负责背景，不得截获点击；内容层必须位于装饰层之上并保持可访问的焦点顺序。
- 菜单项及其图标、标题、辅助说明和快捷键必须左对齐；项目容器使用左起的内容流（例如 `text-align: left` 和 `justify-content: flex-start`），并为可选图标保留稳定槽位。不能因某项没有图标、处于选中态或来自另一种菜单而改为居中、右对齐或改变文字起点。
- 打开时注册共享的全局 `pointerdown` 捕获处理；事件的 `composedPath()` 不包含该浮层内容时，立即关闭它。浮层外部包括工作台任何区域、工具栏或触发器、遮罩和其它浮层；不要仅依赖 `blur`、`mouseleave` 或会被 `stopPropagation()` 绕过的冒泡监听。该规则没有“保持已打开”的例外。
- 同时存在多个浮层入口时，交互后至多保留当前操作明确打开的一个浮层；旧浮层必须先按外部点击规则关闭，不能残留、叠加或遮挡新入口。
- 菜单内容过长时设置最大高度和滚动，不能让浮层撑出视口；定位后同时校验顶部、底部、左右边界。
- 新增或修改浮层后，至少验证左对齐、最高层级、背景模糊与隔离、键盘 Escape 关闭、点击工作台空白处关闭、点击另一个浮层或其入口后旧浮层关闭，以及窄视口不溢出。以实际截图和交互结果验收，而非只匹配 CSS 或监听器文本。

## 实现边界

- 业务组件只声明菜单内容和动作；左对齐结构、定位、portal、最高层级、背景模糊、关闭和视口约束均由共享浮层组件负责。
- 不要为单个菜单复制一套对齐、z-index、定位、玻璃背景或事件监听实现。若共享组件缺少能力，先扩展公开契约，再迁移调用方。
- 视觉回归以实际截图和可观察几何结果为依据；不要只用匹配 CSS 文本的测试代替交互验证。
